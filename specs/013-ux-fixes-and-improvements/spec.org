* Agreed increment: annotation input guards
** AC013.3 - Prevent input beyond the annotation limit :ac:
:PROPERTIES:
:CUSTOM_ID: ac-013-3
:END:
- Status :: *Important pre-existing UX defect*, reported 2026-09-20; paired
  implementation authorized. Separate from the native Markdown migration.
- Observation :: The editor accepts further typing beyond its save limit. An amber
  warning appears, but the blocking alert occurs only when leaving the editor.
- Required outcome :: *Prevent input beyond the supported limit while editing*,
  with immediate, accessible feedback. Preserve accepted text and allow deletion
  or replacement at the limit; handle typing, paste and input-method composition
  without silently discarding existing text.
- Current limit :: *4,000 Unicode code points and 16,384 UTF-8 bytes*, hardcoded in
  =assets/web/annotation-composer.js= and =internal/annotation/{event,replace}.go=.
  These are not YAML configuration keys. Retain server-side enforcement.
- Verification :: Boundary input, paste, selection replacement, accented
  and supplementary characters, composition, editing existing notes and recovery.
  Input rejection must occur before the leave-editor workflow.

** AC013.4 - Preserve Org footnote paragraph boundaries :ac:
:PROPERTIES:
:CUSTOM_ID: ac-013-4
:END:
- Status :: *Confirmed syntax constraint; paired editor guard authorized*.
- Authority :: [[https://orgmode.org/manual/Creating-Footnotes.html][Org manual: Creating Footnotes]]
  ends a definition at the next definition, heading or *two consecutive empty lines*.
- Distinction :: =first\n\nsecond= contains *one blank line* and permits another
  paragraph. =first\n\n\nsecond= contains *two blank lines* and ends the footnote.
- Intended guard :: Preserve normal multi-paragraph notes; prevent an extra blank
  line from terminating an Org definition while composing ordinary prose. Include
  pasted text and whitespace-only lines; do not apply the Org rule indiscriminately
  to Markdown or literal blocks. Org sidecars follow their destination's Org rule,
  including sidecars belonging to Markdown source documents.
- Existing protection :: =ordinaryNoteEnd= recognizes this boundary; native creation
  and editing reparse the generated definition and reject a boundary-breaking save.
  This protects persistence but does not establish adequate editor feedback.
- Verification :: Single blank-line paragraph separation, two blank lines,
  whitespace-only lines, LF/CRLF, creation and editing; preserve unrelated source.

** Input-guard solution and evidence boundary
- Rejection :: Reject the whole invalid insertion or paste, retaining prior text
  and selection. Do not truncate clipboard contents. Deletion and valid replacement
  remain available; a pre-existing oversized note may be shortened progressively.
- Composition :: Let the input method finish its composition before validating;
  reject an invalid committed composition as a whole. Do not autosave interim text.
- Browser events :: Cancel invalid =beforeinput= operations when their replacement
  text is available; validate =input= as a fallback for non-cancelable events,
  undo/redo and composition commits. Rejected text never enters the autosave queue.
- Feedback :: Use the editor's existing reserved status space for an accessible
  explanation and amber outline. No modal or extra layout row for input rejection.
- Org scope :: Match the writer's case-insensitive =#+BEGIN_...=/=#+END_...=
  block recognition; count whitespace-only lines outside those blocks. Normalize
  CRLF for boundary detection. This is an editor guard, not an Org parser or a
  replacement for the server's source-preserving reparse checks.
- Evidence :: Browser typing, selection, clipboard and composition require the
  operator's real browser. Browser automation and CLI JavaScript are excluded;
  there is no approved JavaScript test runner. Do not substitute source-string
  assertions or a mock DOM. Reuse the existing HTTP/writer preservation tests,
  plus focused lint/build checks, and record browser evidence as user tests.

* Current correction: implementation notes
- Inline probes :: A temporary line-end marker inside multiline verbatim/code
  is rendered literally. Remove only generated unparsed markers from the probe
  DOM before comparing it with the original. Such markers never authorize a
  write; only parsed reference hits at verified block ends can do so.
- Indented blocks :: Preserve closing-line indentation in the temporary probe
  and saved reference paragraph. Preserve the original following line endings
  so a new blank line does not split the enclosing list. The native converter's
  invisible probe prefix follows that indentation too.
- Labels :: A description term gets a distinct interactive ID referring to its
  first verified content boundary. Paragraph and label selection remain distinct;
  neither inserts a footnote into the description delimiter.
- Security :: Existing revision checks, shape/text correspondence, request
  authentication and source-preserving write checks remain active. Literal or
  otherwise unverified probe markers do not become client-writeable offsets.

  work and retrospective design review remain pending; the ticket stays open.
