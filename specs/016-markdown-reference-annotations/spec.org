* Synopsis
:PROPERTIES:
:CUSTOM_ID: summary
:END:
** Outcome
- *Markdown text remains annotatable* when the source contains hidden reference definitions.
** Before
- A temporary annotation probe can make a *hidden definition visible*, disabling
  annotation targets throughout the page.
** After
- *Definitions remain untouched* during probing; ordinary blocks retain their targets.
** Changes
- Annotation mapping recognizes *reference-definition source spans* before probing.
** Unchanged
- *No browser, configuration or storage-format change*. Existing write checks remain.
** Edge cases
- *Multiline definitions and titles* remain hidden; ordinary bracket text and code remain visible.
** Decisions
- Reuse *Goldmark's reference transformer*, rather than implement Markdown syntax again.
** Next step
- Validate the corrected preview in the browser and record closure separately.

* Edge Cases
- *Literal code and ordinary bracket prose* must not be mistaken for hidden definitions.
- *Multiline titles and adjacent definitions* must be excluded in their entirety.
- Unsupported insertion locations still require the existing DOM-shape proof.

* Solution Design
- Ownership :: =internal/annotation/blocks.go= owns candidate source boundaries.
  It asks the existing Goldmark reference paragraph transformer for definition
  spans before adding temporary footnotes to Markdown lines.
- Mechanism :: At a bracket-led line outside existing literal exclusions, form
  a paragraph from source segments through its next blank line. Transform reference
  definitions only, then skip candidate offsets through the final definition's
  source end. Ordinary text after that span continues through the existing mapper.
- Reuse :: Goldmark 1.8.6 is already pinned. Its reference transformer handles
  indentation, destinations and multiline titles. No full second document
  conversion or new parser implementation is introduced.
- Compatibility :: Org bypasses this check. Existing native rendering, DOM pairing,
  browser selectors and storage writer remain unchanged. Definition bytes are
  read only; the existing annotation patch writer owns actual footnote insertion.
- Security :: No access, privilege, networking or persistence expansion. The
  existing source limits bound the input; no authored source executes. Only
  verified DOM targets reach the unchanged authenticated write endpoint.
- Verification :: The HTTP lifecycle regression observes delivered targets and
  actual writes; implementation review checks parser reuse and unchanged safety checks.
