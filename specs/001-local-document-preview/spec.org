* Installable Markdown and Org previews with linked browsing
:PROPERTIES:
:CUSTOM_ID: summary
:END:

- Outcome :: A *global command previews Markdown and Org* in the browser while
  leaving *source files unchanged*.
- Before :: The *repository contains prototypes and licensed fonts*, with no
  packaged application or maintained application regression suite.
- After :: A *Go binary for macOS, Linux, and WSL* uses Pandoc 3.9.0.2 through
  3.9.x and opens source-labelled pages in the *system default browser* from an
  *owner-private temporary directory*. WSL opens the Windows default browser
  using translated file URLs. Install by prefix or the macOS Homebrew recipe.
- Changes :: The candidate defines four connected capabilities:
  - *Rendering preserves Org metadata, literal blocks, and identifiers*, embeds
    both Asap faces and four Iosevka Custom faces with their notices, and retains
    accessible outline controls and printing. *The original filename header
    copies its full source path* with mouse or keyboard activation.
    *Fonts need no system installation*,
    including when invoked through a symlink from another directory.
  - *Local references resolve from their source directories*. Opt-in traversal
    defaults to 50 contexts, depth 3, 10 MiB per source, 50 MiB total source,
    100 MiB output, and 60 seconds of conversion.
  - *Quick previews expire after three seconds*; reading sessions retain pages
    until SIGINT/SIGTERM. Slow browsers can miss quick previews.
  - *Passive rendering blocks active source content and network URLs*. Includes
    stay literal; unsupported raw CSS, srcset, and SVG are diagnosed.
- Unchanged :: *Pandoc performs conversion*; Lua runs inside Pandoc; JavaScript
  runs only in the browser. *Sources remain read-only* and code blocks are not
  executed. There is no server, publication, or remote crawling.
- Edge cases :: *Concurrent runs remain isolated*; empty inputs retain source
  labels; encoded paths and fragments retain their destinations. *Failed inputs
  and handoffs are diagnosed*; aliases and ambiguous IDs have explicit rules.
  Partial publication aborts opening. *Cleanup affects only the owned session*;
  forced termination may leave its directory behind. *WSL translation failures
  are diagnosed*; unrepresentable original links become inactive. *Denied clipboard
  access offers manual copying*; without JavaScript the path remains selectable.
- Decisions :: *Go and temporary-directory output are selected*. *Asap is the
  proportional default*; *Iosevka Custom is the fixed-width and code default*.
  *Project code uses Apache 2.0* and both font families retain OFL 1.1.
  macOS/Linux/WSL and default-browser opening are *operator requirements*.
  Qualification baselines, browsing, retention, and passive-source
  defaults are *candidate choices for approval*. CSS/JS use source and browser
  review; no CLI JavaScript lint runtime is introduced.
- Next step :: *Audit this candidate, then obtain operator sign-off*. Linked
  browsing, lifetimes, platform packaging, and passive-source policy are explicit
  proposals for approval; no implementation is authorized.

* Context
:PROPERTIES:
:CUSTOM_ID: context
:END:

** Problem

- Readers need a *globally available preview command* for local Markdown and Org,
  with consistent presentation and useful document structure.
- The *Org prototype needs revision*: preservation, identifiers, keyboard
  handling, and printing have identified defects.
- *Source-adjacent HTML writes into document directories*. Moving output to a
  private temporary directory requires explicit source-relative references.

** Outcome

- The *command opens one finished preview per distinct explicit input*, with
  source identity, readable typography, and preserved document content.
- The *application owns conversion and output lifetime*: packaging, references,
  diagnostics, retention, and cleanup.
- *Automated tests verify command and output behaviour*; human tests assess
  typography, browser navigation, and keyboard interaction.

** Scope

*** In scope

- *Go application orchestration* with Pandoc as a runtime dependency.
- *Markdown and Org rendering* with packaged HTML, CSS, browser controls, and
  both variable Asap faces plus four static Iosevka Custom faces.
- *Source-preserving temporary output* and local link/image resolution.
- *Revision of project-owned Org code*, including pre-processing, Lua, CSS, and
  browser JavaScript.
- *Build, lint, test, installation, and dependency-check entry points*.
- *macOS, Linux, and WSL installation and system default-browser handoff*.
- *Opt-in linked browsing, quick/read lifetimes, and passive source handling*,
  with the contracts below.

*** Out of scope

- *Source editing, live reload, and persistent services*.
- *HTTP serving, publication, remote crawling, PDF conversion, and plugins*.
- *JavaScript on the CLI or a separate Lua runtime*. Prebuilt-binary users do
  not need a Go toolchain or source checkout.
- *Implementation during definition*.

*** Unchanged

- *Source files, linked assets, and unrelated directories remain untouched*.
- *Pandoc owns ordinary parsing and conversion*; Org blocks are displayed
  without execution.
- *External hyperlinks retain their destinations* without remote conversion.

** Constraints and dependencies

- *Go owns application behaviour*; Lua is limited to Pandoc integration.
- *Packaged assets replace personal configuration*: shell helpers, Pandoc data,
  private fonts, and checkout paths must not be runtime requirements.
- *Fonts and application styling are local*; neither conversion nor initial
  page loading fetches remote resources.
- *JavaScript runs only in the browser*. This operator constraint overrides the
  selected standards' CLI JavaScript tooling defaults.
- *Sources and asset locations are read-only*. Output contains local document
  content and paths, with no telemetry or publication.

** Decisions

- Application language :: *Go is selected* after the operator considered Lua.
- Output placement :: *Private OS-temporary output replaces source-adjacent HTML*.
- Presentation :: *Asap is the default proportional face*; *Iosevka Custom is the
  default for all fixed-width text*, including code blocks and inline code.
  The two variable Asap faces and four static Iosevka Custom faces, with their
  notices, are included as WOFF2 assets.
- Font amendment :: On 8 September 2026, the operator selected *Iosevka Custom
  from the local font archive*. This specifies the earlier generic monospace
  requirement; the prior audit remains historical evidence for its revision.
- Platform amendment :: On 8 September 2026, the operator required *macOS,
  Linux, and WSL* and confirmed *system default-browser opening*, including the
  Windows default browser from WSL. This supersedes the earlier macOS-arm64-only
  candidate. The font-installation suggestion is addressed through embedded
  assets, with no system font installation or runtime font discovery.
- Source-header amendment :: On 8 September 2026, the operator required *the
  original filename header and click-to-copy interaction*. Inspection of the
  personal Pandoc template found directory text followed by a bold filename;
  its inline JavaScript copies the header text and briefly marks success. This
  supersedes the earlier optional-copy architecture. The contract below adds
  keyboard access, explicit failure feedback, and an unambiguous full-path value.
- Ownership :: *Reused Org fidelity code is maintained project code*, subject to
  normal design, build, and verification.
- Licensing :: *Project code and documentation use Apache 2.0*; both Asap and
  Iosevka Custom retain SIL OFL 1.1 and their respective copyright notices.

- Definition choices :: The following *candidate defaults require sign-off*:
  linked browsing is opt-in; quick retention is three seconds; linked sessions
  remain foreground until signalled; the qualification matrix and four release
  targets below use prefix installation plus a macOS Homebrew recipe; source
  rendering is passive.
- Authority boundary :: These *authoring proposals are not recorded as operator
  approval*. Signing off this specification adopts their exact contracts.
  Earlier unanswered clarification questions are preserved in audit history.

** Unresolved blockers

- *No implementation choice is left for the delivery agent to guess*. Operator
  approval of the candidate remains PENDING. Release publication is a separate
  human action and is not needed for local package validation.

* Solution Design
:PROPERTIES:
:CUSTOM_ID: solution-design
:END:

** Architecture context

- Relevant components :: *Go coordinates inputs, sessions, rendering, references,
  and desktop handoff*. Pandoc converts Markdown and Org.
- Ownership boundary :: *This project owns pre-processing, Lua integration,
  presentation, and policy*. Reused prototype code is part of the normal build
  and tests; no personal wrapper or separate prototype runtime is invoked.
- Existing pattern :: *Replace the shell/AWK pipeline with context-aware Go
  preservation*. Keep source recovery before Pandoc, semantic transforms in
  small Lua modules, and reference policy in Go.
- Alternatives :: *File URLs avoid an HTTP server*. Explicit rewriting avoids
  the fragment side effects of a source-directory base element. A foreground
  session retains linked files without a background cleanup service.
- Evidence :: [[file:audits.org][Definition evidence]] retains the earlier
  inspection environment and ID/planning/drawer probes. These establish reader
  losses, not full application fidelity.
- Technical sources :: [[https://pandoc.org/MANUAL.html#option--sandbox][Pandoc reader/writer isolation]],
  [[https://pkg.go.dev/os#Root][Go confined filesystem access]],
  [[https://pkg.go.dev/os/exec#CommandContext][Go process cancellation]],
  [[https://pkg.go.dev/golang.org/x/net/html][HTML5 parsing]],
  [[https://github.com/microcosm-cc/bluemonday][bluemonday sanitization policy]], and
  [[https://docs.brew.sh/Formula-Cookbook#specifying-other-formulae-as-dependencies][Homebrew dependency declarations]].
- Platform sources :: [[https://pkg.go.dev/embed][Go compile-time asset embedding]],
  [[https://portland.freedesktop.org/doc/xdg-open.html][Linux desktop opening]],
  [[https://learn.microsoft.com/en-us/windows/dev-environment/wsl-interop][WSL path translation and Windows interoperation]], and
  [[https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/start-process?view=powershell-5.1][Built-in Windows PowerShell process handoff]].
  These support the proposed mechanisms; they are not application validation.

** High-level design

*** Flow

1. *Validate arguments and environment settings*, then check the Pandoc version.
2. *Allocate a private session* and register cleanup before extracting assets.
3. *Process explicit sources first*, in argument order, reserving their places
   within the document limit. Read one bounded snapshot per source context.
4. If enabled, *discover linked contexts breadth-first* from rendered anchors,
   within their permitted root, device, depth, and budgets.
5. *Finalize successful pages and target identifiers*, rewrite supported URLs,
   sanitize document HTML, and insert the packaged presentation.
6. *Publish finished entry pages before opening any*, then invoke the platform
   opener once per distinct successful explicit context.
7. *Retain the whole session* for the selected lifetime and clean up its owned
   directory when that lifetime ends.

*** Interfaces and configuration

- Invocation :: =htmlpreview FILE [FILE ...]= accepts *local files only*; =--=
  ends option parsing. =-h= and =--help= are equivalent; =--version= identifies
  the build. Informational requests bypass settings, dependency checks, and
  all preview effects. Accept one informational option with no inputs; combining
  informational options or adding inputs is invalid. Before the explicit =--=,
  recognize options anywhere in the argument list; unknown options return 2.
- Inputs :: Accept *regular UTF-8 files* ending in =.md=, =.markdown=, or =.org=
  without case sensitivity. Empty files are valid. Stdin documents, directories,
  URLs, devices, and FIFOs are unsupported source inputs.
- Input failure :: *Unreadable, unsupported, or malformed source files fail
  individually* with status 1 while other inputs may succeed. Missing arguments,
  unknown options, and invalid settings fail before output with status 2.
- Compatibility :: *Release macOS and Linux binaries for amd64 and arm64*;
  WSL1/WSL2 use the matching Linux binary. Native Windows executables are outside
  scope. The build baseline is Go 1.26.3; a later reviewed compatible patch may
  be pinned during delivery. Go is not a binary runtime dependency. The matrix
  below defines initial qualification; other OS releases and browser engines
  remain unverified until recorded, rather than being assumed compatible.
- Pandoc :: Require *Pandoc 3.9.0.2 or a later 3.9 patch release*, with its bundled
  Lua 5.4. Reject other release series with status 1 before session allocation.
  Real conversion tests run against the declared minimum and the packaging
  candidate's Pandoc version when they differ.
- Dialects :: Org uses =org=. Markdown uses *Pandoc's 3.9.0.2 default markdown
  extension set* with =raw_tex= and =latex_macros= disabled. Record the explicit
  enabled/disabled set below in packaged defaults, rather than inheriting
  another release's changed defaults. Raw HTML follows the policy below.

- Enabled Markdown extensions :: *Freeze this exact enabled set*; all other
  3.9 reader extensions are disabled. Source raw HTML remains subject to the
  passive policy.

- Configuration :: *Environment values override documented defaults*. No user

  =HTMLPREVIEW_= variables are invalid to expose misspelled controls.
- Platform selection :: *Select macOS by GOOS; distinguish WSL before ordinary
  Linux*. On Linux, a non-empty WSL_DISTRO_NAME or a case-insensitive Microsoft
  marker in /proc/sys/kernel/osrelease selects WSL, including WSLg sessions.
  Read only that bounded kernel identifier, not arbitrary proc entries. A WSL
  candidate with unavailable interoperation fails visibly; never silently choose
  a Linux browser. Unsupported GOOS fails before allocation.
- Desktop handoff :: Use */usr/bin/open on macOS* and *xdg-open on Linux*, with
  an absolute generated file URL as one argument. Resolve external tools from
  PATH once, except the fixed macOS opener. Use the *configured default HTML/URL
  association*; the environment must associate local HTML with its default
  browser. Do not choose a named browser or modify associations. Linux requires
  an active desktop session and xdg-utils; headless/SSH-only environments receive
  the ordinary diagnosed opener failure, not a terminal browser or server.
- WSL handoff :: Invoke the built-in *powershell.exe* with =-NoLogo=,
  =-NoProfile=, =-NonInteractive=, and =-Command= followed by *fixed owned command
  text*. Read one ASCII percent-encoded generated file URL from child stdin
  using =[Console]::In.ReadToEnd()=, then pass it as the sole =-FilePath= value
  to =Start-Process= with =-ErrorAction Stop=, without =-Wait=. Catch errors and
  return 1; return 0 after a successful handoff. Close child stdin after writing;
  the application never reads the user's stdin. Document paths never enter
  PowerShell source, an argument-list command string, or cmd.exe. This small
  reviewed OS bridge requires no additional PowerShell installation or profile.
- Tool bounds :: *Each version query, path translation, and opener call has a
  five-second deadline and 64 KiB combined output cap*. Translation also stays
  within the current conversion/publication phase deadline. Cancel and reap
  helper processes on failure or signal, without terminating the launched
  browser. Missing WSL tools are dependency failures before session allocation;
  runtime bridge failures follow handoff/publication failure policy. Never
  enable interoperation, change PATH globally, or change the desktop settings.
- Output :: *Diagnostics go to stderr*; stdout lists each successfully published
  explicit preview's absolute browser-facing file URL, translated on WSL.
  Reading mode also reports its Linux/native session
  path and termination instruction on stderr. No document content is logged.

- Quick lifetime :: *Start one retention timer after the final handoff attempt*.
  Wait for the configured grace, then clean up. There is no browser readiness
  signal and no promise of reload or successful slow-browser loading after expiry.
  The timer is an expiry policy, not synchronization evidence.

*** Data and state

- Session ownership :: Use *os.MkdirTemp with the OS-selected location* and
  mode 0700; generated files are mode 0600. Paths are session-local, independent
  of source basenames. No cache, database, source write, or shared session exists.
  Verify owner-only modes. In WSL, require a private Linux-filesystem temporary
  location; reject Windows-mounted temporary output rather than changing ACLs
  or relocating to a Windows shared directory. Existing WSL access uses the
  user's existing permissions and the distribution must remain available.
- Budget accounting :: *Count admitted source bytes per context*, even if bytes
  are reused from a snapshot. Count all generated session bytes, including
  extracted assets, staging files, font expansion, and final HTML, before writes.
  Bound stdout/stderr buffers and retained diagnostics within that budget.
- Source snapshots :: *Read each admitted context once*. Source edits during
  a run do not update its preview; no cross-document atomic snapshot is promised.
  Regular-file and size checks apply to the opened handle, not only path metadata.
  The macOS and Linux adapters open candidates non-blockingly before the type check so a
  path swapped to a FIFO cannot stall admission; non-regular handles are closed
  without reading document content.
- Identity :: A *source context is canonical file path plus logical source
  parent directory*. Identical arguments share a page. Symlink aliases with
  different relative contexts may produce separate pages and consume separate
  budget slots. Hard links with different canonical paths remain distinct.
- Relative origin :: *Resolve links from the logical source parent*, then
  canonicalize the target for admission. Keep that origin distinct from output
  placement and physical identity.
- Traversal roots :: Without a root override, *each explicit source owns its
  canonical physical parent directory tree*. With an override, every explicit
  canonical source must be inside it.
  Each root retains its starting device identifier; linked targets must remain
  inside that canonical root and on that device. Already explicit successful
  targets may be linked across roots because they were explicitly requested.
- Traversal access :: *Open admitted files through a Go os.Root boundary* after
  canonical containment checks; inspect the opened file's device and type before
  reading. Do not rely only on string prefixes or a pre-open symlink check.
  Roots on separate filesystems are independent; do not enumerate directories.
- Discovery :: *Visit local document anchors in rendered document order*.
  Images, directories, non-document files, remote URLs, and unresolved =id:=
  links do not add graph nodes. Explicit contexts precede every discovered node.
  Depth limits apply to outgoing discovery, not links to an already rendered page.
- Mapping :: *Only successfully rendered targets enter the final catalogue*.
  Render into bounded staging, derive identifiers, then rewrite and publish every
  selected page within a separate five-second publication deadline. *Any final
  publication failure aborts the invocation before browser opening*, with cleanup
  and status 1; partial success applies to source/conversion failures, not a
  failed publication transaction.
- URL handling :: *Split URL path, query, and fragment before filesystem
  resolution*. Decode path escapes once and encode emitted file URLs once;
  preserve queries and fragments. Malformed URLs become inactive labelled
  references with diagnostics. Missing local targets retain absolute file URLs
  and a warning; the preview does not create or search for them.
- Reference subset :: *Rewrite anchor href and image src*, including Pandoc's
  output and permitted literal HTML. Same-page fragments stay on generated pages.
  Unconverted local documents/assets use absolute original-file URLs. Remote
  HTTP/HTTPS/mailto anchors remain unchanged.
- WSL file URLs :: *Resolve and admit paths in Linux first*. Convert each
  required absolute local path using =wslpath -w= as a direct argument array;
  cache translations per session. Construct Windows drive file URLs or UNC file
  URLs structurally, encoding each path component once and preserving the
  separate query/fragment. Never hard-code a drive mount. Accept absolute drive
  paths or the current distribution's share on =wsl.localhost= or =wsl$= only;
  derive that distribution/share from the translation of the owned session and
  require any supplied WSL_DISTRO_NAME to agree. Reject other UNC authorities,
  other distributions, device/extended path namespaces, malformed translations,
  and drive-relative paths. Reject Windows-reserved path components, control
  characters, and trailing dot/space components; allow a colon only in the
  drive prefix. Require a =wslpath -u= round trip to the original cleaned Linux
  absolute path, preserving case, to catch ambiguous separator conversion.
  Generated pages use these URLs too; a translation
  failure aborts publication before any page is opened. A failed original-file
  translation produces an inactive labelled reference and warning, never a
  guessed Windows URL. Missing originals retain URLs only if translation
  succeeds. A mapped URL is not proof of Windows/browser read permission;
  actual availability is covered by the platform user test.
- Org file searches :: *Resolve Org file searches* =::#custom-id= and =::*Heading=
  against the actual
  target catalogue. Heading matching is case-sensitive after trimming/collapsing
  whitespace and excluding task keywords, priority, and trailing tags; statistics
  remain part of the title. Match only a unique target.
- Ambiguity :: *Duplicate, unknown, and unsupported Org searches are diagnosed*.
  File links fall back to the absolute original source without a search suffix;
  an adjacent explanation retains the original search text. =id:= resolves only
  within the already admitted set and only when unique; otherwise its label is
  inactive with an explanation. No global Org-ID database is read.
- Identifiers :: *Capture ID and CUSTOM_ID before parsing*. Prefer CUSTOM_ID as
  primary and retain a distinct ID alias. Repeated generated slugs receive stable
  suffixes. Duplicate or invalid source IDs retain their property text but are
  marked ambiguous for source-link resolution; output identifiers remain unique.
- Literal preservation :: *Track Org blocks, drawers, and comments*. Preserve
  source/example contents, including tabs, without interpreting directive
  lookalikes. Use collision-checked internal names, never an unchecked LOGBOOK_
  substitution. Incomplete literal blocks remain literal through end of input.
- Org values :: *Retain task declarations, tags, priorities, statistics,
  planning, and drawers*. Support TODO/SEQ_TODO/TYP_TODO declarations and preserve
  active/inactive dates, times, repeaters, warning offsets, ranges, and punctuation.
  Unknown timestamp forms remain text; no statistics or calendar values are
  recomputed. Plain-source line endings may normalize in rendered text.
- Outline :: *No-JavaScript output starts fully readable*. With enhancement,
  STARTUP overview hides section bodies, content shows all headings without
  bodies, and showall shows everything. Default is showall. Per-heading VISIBILITY
  folded/children/all overrides its subtree at startup only; unknown values open
  that subtree and warn. Runtime toolbar or local controls override initial
  metadata, with fragment revelation taking precedence.
- Local fold states :: *Folded hides the body and all descendant sections*;
  children shows immediate child headings without their bodies or descendants;
  all opens the whole subtree, including drawers. Global overview shows root
  headings only; content shows every heading without bodies; showall opens all.
- Presentation :: *Use one source-identity h1*; source headings begin at h2.
  Generated levels follow actual ancestor nesting without gaps; retain original
  source levels as metadata. Beyond h6, use role=heading with aria-level rather
  than invalid h7 elements. Fold controls are native buttons; no document-wide
  Tab interception. Drawers/details are emitted open for no-JavaScript reading;
  enhancement applies their initial folding. Before print, expand all sections
  and drawers; restore prior state afterwards. Print styling shows all content.
  Dark/light palettes meet WCAG AA body/large-text contrast requirements.
- Source header :: *Display the full absolute logical source path in the leading
  h1*, with its basename in strong emphasis and as the document title. Match the
  original compact right-aligned header and separator; use Iosevka Custom 400
  for the directory and 700 for the filename, with wrapping and accessible
  contrast rather than the original blanket opacity. Preserve visible path
  whitespace and do not abbreviate or truncate the copy value.
- Copy value :: *Derive the path from the source context*, equivalent to the
  cleaned absolute input path before symlink canonicalization. Linked pages use
  their own context. In WSL it remains a Linux path, even for mounted Windows
  sources. Store the exact escaped value on the owned header, separate from
  formatted text; do not trim it, URL-encode it, shell-quote it, or derive it
  from the temporary page. The original private path-formatting helper is not
  a dependency and its displayed-text normalization is not retained.
- Copy interaction :: *Enhance the plain selectable header with a native button*
  named to indicate copying the source path. Bind only the owned header element;
  source content cannot opt into clipboard handling through classes or IDs.
  Use the native click event for pointer, Enter, and Space activation. Call
  navigator.clipboard.writeText directly in that activation, without an earlier
  asynchronous step that loses user activation. Never read the clipboard.
- Copy feedback :: *Announce success only after writeText resolves*, using visible
  text and a polite live region outside the copy value. Retain success text
  for two seconds. Permit only one pending attempt; clear prior feedback timers
  before a new attempt and on teardown. A rejected or missing API restores the
  button and announces a manual-copy instruction with a readonly selectable
  full-path field. Do not steal focus or claim success from selection alone.
  Without JavaScript, leave the original header as plain selectable text;
  printing hides the button/status/field and retains the full source identity.
- Browser script :: *Use a small inline ES2020 module without imports* or global
  mutable state. Scope listeners and DOM queries to application-owned controls;
  use safe DOM APIs and register teardown for listeners/print-state changes.
  Build the outline index in linear time and yield during large initialization
  batches so static reading remains available before enhancement is ready.
- Assets :: *Embed separate reviewable HTML/CSS/JS/Lua sources and both font
  families*. For Asap, use regular/italic @font-face rules, weight 100 to 900,
  width 75% to 125%. Include both families' full copyright/OFL text in HTML
  comments and all applicable notices in release archives.
- Asset lookup :: *Resolve embed patterns relative to a Go package at build
  time*. Keep the asset package and its files inside the module; no embed path
  crosses the module or follows an external symlink. Runtime reads embed.FS,
  extracts only conversion assets to its session, and emits all six fonts as
  inline WOFF2 data URLs. Do not derive asset paths from cwd, argv[0], executable
  symlink targets, an installation prefix, or system font directories.
- Fixed-width font :: *Use Iosevka Custom for every fixed-width style*, including
  =pre=, =code=, =kbd=, =samp=, and fixed-width Org metadata. Embed the four WOFF2
  files named by the asset authority in the executable and each preview's CSS
  data URLs. Declare normal/italic at weights 400 and 700, normal stretch;
  these are static fonts, with no variation axes. Select the packaged face
  without =local()=, followed by a generic monospace fallback.
- Font budget :: *Count all six embedded faces and their base64 expansion* in
  the existing output budget. Iosevka adds 1,923,456 bytes per page before CSS
  and notices; the byte limit can stop rendering before the document limit.

*** Failure behaviour

- Explicit failures :: *Report each failed source and return 1* while opening
  other successful explicit previews. Linked skips alone return 0; report a
  concise count and affected original targets without source content.
- Limit exhaustion :: *Stop new linked admission at count/depth/source limits*.
  If an explicit input cannot be rendered within a resource limit, it fails.
  On output/time exhaustion, cancel current conversion, reject unfinished pages,
  publish only already rendered pages under the separate publication deadline
  if output capacity remains, and report every skipped explicit input as a failure.
- Process lifetime :: *Cancel and reap every converter on deadline or signal*.
  Use context-controlled execution and close bounded pipes; do not leave child
  processes after return. Go's process-control boundary and reader/writer budget
  adapters remain small and testable.
- Cleanup :: *Remove only the exact owned directory*, never a prefix/glob search.
  No-output failure cleans immediately; usable outputs retain the chosen lifetime,
  even if a handoff failed so their printed paths remain usable. Attempt cleanup
  once, report its error and remaining path, and return 1 on failure.
- Abrupt termination :: *SIGKILL or system failure may leave output behind*.
  No cross-session scavenger is included; document the exact manual removal path.
  Normal cleanup is best effort on a functioning filesystem, not a guarantee
  against a stalled or unavailable storage device.

** Architecture impact

*** Security impact

- Threat boundary :: *Source content is passive input*. The application never
  loads user filters/templates or executes Org source blocks.
- Reader isolation :: Feed bounded source snapshots through *Pandoc --sandbox*
  with explicit packaged defaults/data and owned Lua only. Disable raw TeX and
  latex macros for Markdown, preserve tabs, and do not use embed-resources.
  Pandoc's sandbox covers readers/writers, not the trusted filter code.
- Includes :: *Neutralize Org INCLUDE and SETUPFILE before parsing*, retaining
  the directive as literal visible text and warning. Ignore source metadata
  requesting styles, filters, includes, bibliographies, or scripts. Preserve
  title/author/date/language as escaped display data only.
- Sanitization :: *Sanitize after all source-derived HTML transformations* with
  a purpose-built bluemonday allowlist; use x/net/html for structural processing.
  Keep document content separate from packaged chrome. Insert only static owned
  CSS/JS afterwards, with contextual escaping for source names and diagnostics.
- Allowed elements :: *Retain passive document structure*: a, abbr, b, blockquote,
  br, caption, code, col, colgroup, dd, del, details, div, dl, dt, em, figcaption,
  figure, h1-h6, hr, i, img, ins, kbd, li, mark, ol, p, pre, q, s, samp, section,
  small, span, strong, sub, summary, sup, table, tbody, td, tfoot, th, thead, time,
  tr, u, ul, var, and wbr. Unknown structural containers unwrap to passive text;
  script/style/frame/embed/form/SVG content becomes an explanatory placeholder.
- Allowed attributes :: *Retain bounded presentation data*: id/class, title,
  lang/dir, image alt/width/height, table spans/scope, list start/value/type, and
  generated accessibility/Org metadata. Source event attributes, style, srcset,
  base, name, form actions, srcdoc, and executable embeds are removed and warned.
  Source content cannot claim reserved application control attributes.
- URLs :: *Allow local file images and raster data images* (PNG/JPEG/GIF/WebP/
  AVIF), and file/fragment/HTTP/HTTPS/mailto anchors. Remove all other schemes.
  Remote images and stylesheet URLs become explanatory linked placeholders;
  inline SVG/CSS URLs/srcset are unsupported. This is an explicit subset, not
  a claim that every raw reference can be rewritten.
- File authorities :: *Accept source file URLs only with an empty or localhost
  host*. Reject other source file authorities. After source resolution, the
  final allowlist may retain *application-generated current-distribution WSL
  file URLs* according to the translation contract above. Keep provenance in
  Go state, not a forgeable source attribute. This exception does not admit
  source-authored UNC links or expand traversal roots/devices.
  Ordinary OS access to mounted/cloud-backed
  filesystems is outside the no-network-URL promise; graph device limits still
  apply to document admission.
- Browser policy :: *Emit an application-owned Content Security Policy* before
  content: default-src 'none'; base-uri 'none'; form-action 'none'; object-src
  'none'; script-src and style-src restricted to hashes of packaged inline
  payloads; font-src data:; img-src file: data:. Do not permit unsafe-inline,
  eval, connections, frames, or remote automatic resources.
- Data and secrets :: *Keep source content and paths in owner-private output*;
  minimize diagnostics, and add no telemetry or publication. Local images remain
  dependent on the original files and OS/browser permissions.
- Clipboard boundary :: *Only explicit activation copies the original source
  path*. No load-time writes, clipboard reads, permission bypass, or source-body
  clipboard handlers are allowed. Treat the browser's clipboard API as a
  permission-controlled boundary; no CLI clipboard helper, network service,
  or browser security-setting change is introduced. The
  [[https://www.w3.org/TR/clipboard-apis/#dom-clipboard-writetext][Clipboard API working draft]]
  describes writeText and rejection; actual file-page behaviour requires the
  selected browser tests.
- Access :: *Traversal cannot widen its root or device boundary implicitly*.
  Resource links outside that boundary remain original browser references, not
  graph inputs. Following an external hyperlink is an explicit browser action.
- Conclusion :: *Layer reader isolation, passive HTML policy, and CSP*, with
  negative regression and real-browser tests. No whole-process OS sandbox or
  guarantee against converter/browser vulnerabilities is claimed.

*** Other relevant qualities

- Reliability :: *Separate snapshots, conversion, publication, handoff, and
  retention*. A rendered page is usable only after publication; opener success
  does not mean page readiness.
- Performance :: *Bound session data and conversion work* with the public
  settings. The limits do not bound browser memory, original image sizes, or
  total process RSS. Pandoc receives its documented 512 MiB RTS heap limit.
- Operability :: *Provide make build, lint, test, install, sync, vulncheck, and
  release*. Build produces the binary; install uses PREFIX (default /usr/local)
  and DESTDIR for staged installs; repeat installation replaces only managed
  binary/licence files. Build/install default to the host OS/CPU. Release uses
  =CGO_ENABLED=0= to produce versioned *darwin-amd64, darwin-arm64, linux-amd64,
  and linux-arm64* archives with SHA-256 checksums. WSL uses the Linux archive.
  Install embeds the fonts in the binary and copies notices under the prefix;
  it does not register fonts, update font caches, or download dependencies.
- Packaging :: *Maintain packaging/htmlpreview.rb.tmpl and the release generator*.
  For example, ~make release VERSION=0.1.0~ produces the binary
  archives named =htmlpreview-VERSION-OS-ARCH.tar.gz=, their SHA-256 manifest,
  and =dist/Formula/htmlpreview.rb=. VERSION is required for
  release and consists of three non-negative decimal components separated by
  dots, with no prefix or suffix; invalid or absent values fail before packaging.
  With no release URL,
  the generated macOS formula selects each architecture's actual local archive
  file URL and checksum, using separate arm64/amd64 branches. It declares Pandoc
  and is macOS-only; Linux/WSL use prefix installation and the documented Pandoc
  prerequisite. Unsupported formula platforms fail clearly. A supplied
  RELEASE_BASE_URL selects an existing operator-provided asset location; verify
  it and its checksum before generating a public formula. Local validation keeps
  the same formula class/name, dependency, checksum, and install recipe; only the
  archive transport differs. Publication is outside this change's authority.
- Installation boundary :: *Do not alter shell profiles or an existing personal
  preview script*. Document PREFIX/bin on PATH and detect/report command
  shadowing during package validation. The default install prefix may require
  operator permissions; no automatic sudo or permission widening is permitted.
  Document installing a compatible Pandoc separately for prefix installs and
  xdg-utils for Linux desktops. WSL requires its existing wslpath, built-in
  Windows PowerShell, enabled executable interoperation, and Windows access to
  the active distribution. Do not imply a distribution package automatically
  meets the pinned Pandoc series; the runtime compatibility check is authoritative.
- Versioning :: *Embed version and source revision at build time*; this is build
  identity, not runtime configuration. Documentation marks unsupported platforms
  and the supported Pandoc series explicitly.
- Accessibility :: *Human review checks every qualification browser environment*,
  including both themes, narrow/wide layouts, focus, fragments, print, Irish
  glyphs, no-JS reading, and passive-source browser behaviour.
- Portability :: *Desktop, browser-facing URL, and filesystem operations have
  small macOS/Linux/WSL adapters*. WSL retains Linux filesystem identity and
  signal semantics while opening Windows-readable URLs. The earlier macOS-only
  scope is superseded by the operator's platform amendment. No native Windows
  executable, Linux-browser selector in WSL, registry editor, or local server
  is added.
- Maintainability :: *Use Go's testing package and small interfaces*. x/net/html
  supplies HTML5 parsing; bluemonday supplies a reviewed sanitizer policy engine.
  The standard library has no equivalent HTML parser/sanitizer. Review and pin
  both modules and transitive licences/advisories in go.mod/go.sum during delivery.
- Static checks :: *Go uses gofmt, go vet, and the selected golangci-lint rules*;
  maintained Lua uses StyLua and a syntax check in Pandoc's Lua host. Review Lua
  globals/errors explicitly. Use generated-HTML validation and human browser
  evidence for presentation.
- Tooling exception :: *No Node/npm, ESLint, stylelint, or separate Lua runtime is
  introduced*. CSS/JS receive source review under WEB/JAVASCRIPT standards and
  the declared browser tests; automated CSS/JS lint coverage is not claimed.
  This candidate deviation follows the operator's CLI-language constraint and
  remains visible for sign-off.
- Vulnerabilities :: *make vulncheck runs govulncheck against pinned Go inputs*
  without installing tools or changing dependencies. The scanner is provisioned
  separately and fails closed. Owned Lua/CSS/JS are source-reviewed; Pandoc is
  separately package-managed and its exact version is recorded in validation.
- Test boundaries :: *Go tests exercise the installed CLI and generated HTML*.
  Use real Pandoc for normal conversion; doubles only force process/device/
  cleanup failures. Human browser tests avoid adding a new browser harness.
  Homebrew packaging is a bounded one-off test, not a repeated regression.
