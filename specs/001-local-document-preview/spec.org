* Specification Summary
:PROPERTIES:
:CUSTOM_ID: summary
:END:

- Outcome :: A globally installed =htmlpreview= command *opens readable local
  Markdown and Org previews* without modifying source documents.
- Before :: The repository contains *prototype rendering code and font assets*;
  it has no packaged application or maintained application test suite.
- After :: A *Go application invokes Pandoc*, packages its presentation and Asap
  fonts, and owns output in a *private temporary directory*.
- Changes :: Source-relative references are *rewritten for temporary output*;
  Org preservation and outline controls become *maintained application code*.
- Unchanged :: Documents remain *read-only inputs*. JavaScript runs *only in the
  browser*. Project code uses Apache 2.0; Asap retains OFL 1.1.
- Edge cases :: The definition covers *invalid inputs, source preservation,
  reference encoding, rendering failure, missing assets, and concurrent runs*.
- Decisions :: Go, Pandoc, embedded regular and italic Asap, temporary-directory
  output, and assessment of all reused prototype code are *operator-selected*.
- Open scope :: Linked browsing, retention, release platforms/installation, and
  source trust *await operator direction*. Their acceptance criteria and test
  definitions cannot be finalized until that direction is recorded.
- Next step :: Resolve the named choices, finish the dependent definitions,
  perform the definition gate, then request operator sign-off.

* Context
:PROPERTIES:
:CUSTOM_ID: context
:END:

** Problem

- Readers need a *single globally available command* to inspect local Markdown
  and Org in a browser with consistent presentation.
- The prototype's Org rendering contains *useful behaviour and identified
  defects*. It is project-owned source, not an external compatibility boundary.
- Source-adjacent temporary HTML preserves ordinary relative links but *writes
  into document directories*. The selected design moves output to a private
  temporary directory and *resolves references explicitly*.

** Outcome

- A packaged command *renders separate previews* for explicit local inputs,
  *opens their finished HTML*, and preserves source data.
- The application *owns conversion, asset packaging, reference handling,
  diagnostics, retention, and cleanup*.
- Visual and keyboard quality require *recorded human validation* alongside
  automated verification of the command and generated output.

** Scope

*** In scope

- A *Go command-line application* with Pandoc as a runtime dependency.
- Markdown and Org conversion with *packaged presentation assets*.
- *Embedded Asap regular and italic variable fonts* and their licence notices.
- *Private temporary output* and source-relative link/image resolution.
- *Project-owned revision* of relevant Org pre-processing, Lua, CSS, and browser
  JavaScript, informed by the prototype assessment.
- *Local build, lint, test, installation, and dependency-check entry points*.
- Explicit *file-lifetime, release-platform, and source-trust contracts* once
  the outstanding decisions below are resolved.

*** Out of scope

- Editing source documents, live reload, a persistent service, an HTTP server,
  publication, remote document crawling, PDF conversion, and a plugin system.
- A JavaScript CLI runtime, a separate Lua runtime, or a Go toolchain required
  on machines using a prebuilt executable.
- Implementation during this definition workflow.

*** Unchanged

- Original source files, linked assets, and unrelated temporary directories
  *remain untouched*.
- Pandoc remains responsible for *ordinary document parsing and conversion*.
- Org code blocks are *displayed without execution*.
- External hyperlinks remain *external destinations*; the application does not
  recursively convert remote pages.

** Constraints and dependencies

- *Go owns application behaviour*; Lua is limited to useful Pandoc integration.
- *Packaged assets* replace reliance on personal shell helpers, private font
  installations, user Pandoc defaults, or a source checkout at runtime.
- *Generated HTML and bundled fonts* are local output; no font service is needed.
- The repository has a *user-owned uncommitted profile amendment* selecting the
  Lua standard. Definition work must not stage, revert, or overwrite it.
- Initial inspection environment :: Go 1.26.3, Pandoc 3.9.0.2 with Lua 5.4,
  macOS 26.6 on arm64. This is *inspection evidence*, not an approved support
  matrix.

** Decisions

- Application language :: The operator reconfirmed *Go* after considering Lua.
- Output placement :: A *private operating-system temporary directory* replaces
  source-adjacent preview files.
- Presentation :: *Asap is the default proportional face*; code remains
  monospace. Both variable WOFF2 faces and their notices are already included.
- Ownership :: Reused Org fidelity code is *maintained project code*, subject to
  the same design, build, and verification requirements as new code.
- Licensing :: Project code and documentation are *Apache 2.0*; the font files
  retain *SIL OFL 1.1*.

** Unresolved blockers

- Linked browsing :: Whether this change includes bounded traversal and
  conversion of linked local Markdown and Org documents is *unresolved*.
- Lifetime :: How long previews remain usable and whether the command must
  return immediately are *unresolved*.
- Release scope :: Supported platforms and the first installation route are
  *unresolved*. macOS/Homebrew is the architecture's proposal.
- Source safety :: A proposed passive-document policy blocks source-supplied
  scripts and leaves Org includes unexpanded; operator direction is *pending*.

** Proposals awaiting those decisions

- Linked browsing :: Include the extension in this change as an *opt-in mode*,
  using the architecture's breadth-first traversal, explicit directory boundary,
  and finite budgets. Ordinary invocation still previews only explicit inputs.
- Lifetime :: Retain the architecture's *quick preview and foreground reading
  session* distinction. The existing three-second delay is a candidate quick
  grace period, not evidence that a browser has loaded the page. Linked browsing
  requires the reading-session lifetime.
- Installation :: Start with *macOS and a Homebrew formula declaring Pandoc*.
  Specify architecture, OS, browser, and Pandoc support ranges after that
  platform decision. Publishing a release or tap is not part of definition work.
- Source safety :: Permit *passive document content and application-owned
  controls*. Prevent document-supplied script execution and leave includes
  unexpanded. The final policy must also cover active URL schemes, raw HTML/CSS,
  metadata resources, and network-loaded content; private output alone does not
  resolve these boundaries.
- Authority :: These are *proposals for operator direction*, not accepted
  requirements or defaults. No implementation may infer approval from them.

* Edge Cases

** Read-only sources and simultaneous invocations

- Condition :: Sources cannot be written, or multiple invocations preview the
  same source concurrently.
- Required behaviour :: *Separate private outputs* are generated without source
  mutation or interference.
- Covered by :: [[#ac-001-2][AC001.2 - Source preservation]],
  [[#ac-001-3][AC001.3 - Private session output]], and
  [[#rt-001-2][RT001.2 - Source preservation and session isolation]].

** Relative references and literal delimiters

- Condition :: Input paths differ from the current directory or contain
  Unicode, spaces, percent signs, question marks, or hash characters.
- Required behaviour :: The resolver *distinguishes filesystem names from URL
  components* and preserves the intended target.
- Covered by :: [[#ac-001-9][AC001.9 - Source-relative references]] and
  [[#rt-001-6][RT001.6 - Reference resolution and encoding]].

- Condition :: An explicit input is invalid, conversion fails, or desktop
  handoff fails while another input succeeds.
- Required behaviour :: *Incomplete pages are not opened* and the invocation
  reports failure without hiding successful outputs.
- Covered by :: [[#ac-001-12][AC001.12 - Conversion failure reporting]],

* Solution Design
:PROPERTIES:
:CUSTOM_ID: solution-design
:END:

** Architecture context

- Components :: Go owns *input handling, sessions, rendering orchestration,
  references, and desktop handoff*. Pandoc owns document conversion.
- Source preservation :: Replace the AWK pre-pass with *context-aware Go
  processing*. Preserve only the Org information that the selected Pandoc reader
  demonstrably loses; retain literal blocks and identifiers.
- Transformation boundary :: Adapt the project-owned Lua modules for *parsed
  Org structure*. Keep generic reference policy in the Go application.
- Presentation :: Maintain HTML, CSS, fonts, and limited browser JavaScript as
  *reviewable source assets*. Include them through the normal build.

** Fidelity contract to retain during scope resolution

- Markdown :: Define the exact Pandoc reader and extension set in the final
  compatibility contract. Fixtures must separately exercise headings, nested
  lists, emphasis, quotations, fenced code, tables, images, and footnotes.
  Pandoc's name alone is not a dialect specification.
- Org structure :: Preserve declared task keywords, tag order, priority and
  statistics text, planning labels and values, and drawer names and content.
  Statistics remain *source values*, without recalculation.
- Org timestamps :: Preserve active and inactive timestamps, times, repeaters,
  warning offsets, ranges, and trailing punctuation. Unrecognized text must
  remain readable; styling must not *consume or truncate source values*.
- Literal regions :: Track source/example/comment block boundaries and drawer
  context before preserving semantic Org information. Text resembling a
  directive inside a literal block must remain *literal text*. Do not reuse
  =LOGBOOK_= or another valid source name as an unchecked internal marker.
- Identifiers :: Capture IDs before parsing where needed; derive navigation
  from *actual output identifiers*. Retain a distinct =ID= as an alias when
  =CUSTOM_ID= is the primary destination. Finalize duplicate-ID and
  cross-document search handling with the linked-browsing decision.
- Evidence :: A synthetic Pandoc 3.9.0.2 Org-reader probe on 7 September 2026
  retained an ID-only heading as =only-id=, but a heading with both =ID= and
  =CUSTOM_ID= retained only =public-id= in its parsed heading attributes.
  =LOGBOOK_= survived as a custom drawer; the planning lines and =LOGBOOK=
  drawer did not survive. Source/example blocks retained their literal text.
  This supports *context-aware preservation before parsing*; it does not prove
  the proposed application or the prototype's complete fidelity.

** High-level design

*** Flow

1. Parse the invocation and *validate configuration and explicit inputs*.
2. Check Pandoc and allocate an *owner-private temporary session*.
3. Preserve Org metadata as needed, invoke Pandoc with explicit packaged
   settings, and retain *bounded generated documents*.
4. Resolve references against source locations, transform supported output
   structures, and *write finished HTML atomically* within the session.
5. Open explicit outputs through the desktop adapter; apply the *operator-defined
   retention and cleanup contract* once resolved.

*** Interfaces and configuration

- Invocation :: =htmlpreview FILE [FILE ...]=, with =--= for filenames beginning
  with a hyphen; =-h=, =--help=, and =--version= are informational interfaces.
- Settings :: Public setting names, defaults, valid ranges, and precedence
  must be finalized after the pending scope/lifetime decisions. The Go standard
  selects *environment variables for runtime configuration*.
- Conversion :: Use *direct executable invocation with argument arrays*;
  do not interpolate filenames into shell commands.
- File resolution :: Keep source context distinct from output placement. Use
  filesystem operations for local identity and *URL-aware encoding* for emitted
  references.
- HTML handling :: The architecture proposes =golang.org/x/net/html= for
  structural output processing. Pin a reviewed version during delivery;
  ordinary string replacement is not an HTML parser.

*** Data and state

- Source documents and original linked assets are *read-only*.
- The session owns generated HTML and conversion assets. *No durable cache,
  database, or source-adjacent output* is introduced.
- Each document record identifies its source context, resolved identity,
  generated destination, rendering result, and outgoing references. The linked
  traversal contract remains pending the scope decision.
- Embed Asap WOFF2 bytes in the binary and generated CSS, with *full retained
  copyright and OFL notices*. Do not relicense the font files.

*** Failure behaviour

- Check every process and filesystem result. *No partial HTML is opened*.
- Preserve diagnostics with the relevant source or operation. *Do not hide
  errors* through broad recovery or suppressed exit status.
- Input, byte, time, traversal, and cleanup limits must be stated quantitatively
  when the outstanding scope/lifetime decisions are resolved.

** Architecture impact

*** Security impact

- Threat boundary :: Source documents can carry active HTML or indirect file
  references. The passive-document policy is *pending operator direction*.
- Data and secrets :: Output contains source content and paths. Keep sessions
  *owner-private*, avoid content in diagnostics, and introduce no telemetry or
  publication.
- Access :: The application *does not widen permissions or network access*.
  It executes only packaged transformations and the declared converter/opener.
- Conclusion :: Temporary-directory isolation alone *is not document
  sanitization*. Finalize the source trust and include policy before auditing
  or signing off this definition.

*** Other relevant qualities

- Reliability :: Separate *rendering from browser handoff* and own all generated
  data through a single session. Retention is an unresolved product boundary.
- Performance :: Use bounded data and process lifetimes; exact budgets await
  the linked-browsing decision.
- Operability :: Provide build/install/test/lint and vulnerability-check entry
  points. Packaging and the support matrix await operator direction.
- Accessibility :: Preserve *normal focus traversal* and readable content across
  folding, disabled JavaScript, light/dark presentation, and printing.
- Portability :: Keep desktop-opening and filesystem-specific operations behind
  *small platform adapters*. No support matrix is implied by the inspected host.
- Maintainability :: Prefer the Go standard library; treat reused Lua, CSS, and
  JavaScript as *owned source with normal checks*. No separate prototype runtime
  or new browser automation framework is selected.
- Tooling precedence :: The operator's *no JavaScript on the CLI* constraint
  takes precedence over the selected web standards' ESLint/stylelint tooling
  defaults. Do not silently introduce Node or npm. The final definition must
  state the replacement review/check contract and its limitations; browser
  user tests remain necessary for interaction and visual behaviour.
