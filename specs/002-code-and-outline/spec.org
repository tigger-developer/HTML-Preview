* Highlighted code, copying and compact fold controls
:PROPERTIES:
:CUSTOM_ID: summary
:END:

- Outcome :: *Code is coloured and copyable*, and *local fold controls use
  triangles* in the existing Markdown and Org preview.
- Before :: *Source blocks are plain*. The header alone offers clipboard
  copying; local outline buttons display Fold or Expand.
- After :: *Declared code languages receive local syntax highlighting*.
  Clicking inline code, Org verbatim or a code block copies its text;
  keyboard users have native copy buttons. *Triangles replace local button
  words* while preserving the current outline states.
- Changes :: *Examples demonstrate TODO states, tags, drawers and code*.
  Pandoc handles highlighting; the owned theme supplies light/dark colours.
  *Copying excludes delimiters and controls* and preserves literal whitespace.
- Unchanged :: *The header identifies and copies the original source path*.
  Fonts, CLI settings, source protection, link resolution, private sessions,
  platform handoff and W001 qualification requirements continue to apply.
- Edge cases :: *Unknown languages remain plain*; empty code is not copied.
  *Selection and hyperlink activation remain available*. Clipboard refusal
  offers a manual-copy field. No-JavaScript reading and full printing remain
  available. Org literal lookalikes and trailing newlines remain literal.
- Decisions :: *Go, Pandoc and browser-only JavaScript remain the stack*.
  Proposed details below select triangles, copy affordances and built-in
  highlighting; *operator sign-off adopts these choices*.
- Next step :: *Audit the definition, then obtain operator sign-off* before
  implementation. Browser results remain separate human evidence.

** Problem

- The operator requested *an Org work-ledger example*, including TODO markers,
  tags, drawers and source blocks, on 8 September 2026.
- The operator requested *syntax highlighting, glyph fold controls and copying
  inline/block code*, including Org =~code~= and ==verbatim==.
- The current *Org preservation stage emits plain HTML code*, so enabling a
  Pandoc option alone cannot highlight those source blocks.

** Outcome

- *Readable highlighted code retains its text*, while copying and folding are
  accessible without changing source documents or system configuration.

** Scope

*** In scope

- *Highlight language-labelled Markdown fenced blocks and Org source blocks*.
- *Copy semantic inline code and pre/code blocks*, including Org verbatim,
  Org example blocks and Markdown indented blocks.
- *Replace local heading button words with glyphs*; retain the global toolbar.
- *Provide synthetic Org and Markdown examples* and browser validation.

*** Out of scope

- *No code execution, language guessing or user-supplied highlighter plugins*.
- *No editing, live reload, new CLI settings or browser automation framework*.
- *No copy action for ordinary prose, drawers or planning metadata*.

*** Unchanged

- *W001 remains the baseline* except for the explicit clipboard-scope extension.
  Syntax colouring refines presentation; it does not relax literal fidelity.
- *Header copying still uses the original absolute logical source path*,
  including the Linux path in WSL. Temporary names never supply that value.
- *Embedded Asap and Iosevka Custom remain the defaults*; installation does not
  depend on system fonts or paths adjacent to the executable.

- Operator direction :: *Use glyphs for local folding and add code copying*.
  The request includes Org source blocks, Markdown fenced blocks, Org inline
  code and verbatim, and Markdown inline code.
- Proposed display :: *Use right triangle =▸= when folded, outline down triangle
  =▿= for children, and solid down triangle =▾= for all*. Provide an action
  label and tooltip naming the heading and next state.

- Proposed activation :: *Click code directly unless it is inside a link*.
  Every nonempty target also has a small native copy-glyph button. Link code
  uses that adjacent control, leaving the link's own click unchanged.

  CSS*. Missing/unknown languages and examples remain plain.

* Solution Design
:PROPERTIES:
:CUSTOM_ID: solution-design
:END:

** Architecture context

- Relevant components :: *Go preserves lost Org values and owns sessions*;
  Pandoc/Lua transform document structure; the HTML pipeline sanitizes and
  publishes; owned CSS/JS provide presentation.
- Ownership boundary :: *Pandoc owns tokenization, browser policy owns clipboard
  permission*. The project owns text fidelity, controls and graceful failure.
- Existing pattern :: *Retain one Pandoc conversion per document*. Replace only
  opaque source-block HTML preservation with typed code transfer; keep drawers,
  planning and identifier restoration in their current responsibility.
- Rejected alternatives :: *A browser highlighter adds an unnecessary library*.
  Per-block Pandoc processes multiply cost; a whole-document JSON round trip
  introduces another conversion stage. Private inline data preserves the
  existing single-converter boundary and adds no filter filesystem access.

** High-level design

*** Flow

1. *Capture Org source text and its language* in the literal-aware pre-pass.
   Retain the current CRLF-to-LF contract and end-of-input handling.
2. *Serialize each source block as JSON data in an internal raw export block*.
   Use a format name derived from the existing collision-free source prefix,
   lowercase and absent from the entire source under case-insensitive matching.
   Pass that exact format through an application-owned Pandoc command metadata
   argument; source metadata must not override it. JSON encoding escapes all
   embedded newlines, so source export terminators cannot terminate the wrapper.
3. *Decode only that format in the owned Lua filter*, validate string text,
   language and generated identifier fields, then create a Pandoc CodeBlock.
   Use =pandoc.json.decode= with Pandoc-type coercion disabled. Do not read a
   sidecar, call a process, evaluate Lua or reparse the code body. Walk the
   document explicitly before display metadata is cleared.
4. *Highlight with the built-in engine* using =syntax-highlighting: pygments=.
   Capture Markdown CodeBlock values before writing as well, so the final
   literal comparison is independent of the highlighter's emitted text.
   Carry values through escaped, collision-free markers, not user-selected
   clipboard attributes. Keep this transient preservation data bounded.
5. *Restore exact code text after parsing the HTML*. Associate generated blocks
   with their retained values before internal identifiers are removed.
   If the only difference is one missing terminal LF, append that LF inside
   code. If another difference occurs, retain a plain code block with the
   original value and a bounded diagnostic; never silently corrupt it.
   Retain token spans for successfully matched output. Exclude generated line
   numbers from copy values; no numbering is requested by this change.
6. *Apply the existing passive policy and publish with owned theme CSS*.
   Then browser enhancement registers code targets and glyph controls using
   safe DOM methods, with no new dynamic HTML sink.

*** Interfaces and configuration

- CLI :: *No public interface changes*. Language is the first Org source-block
  language token or the Markdown code language class. Retain Pandoc-supported
  language names; explicitly map =sh= and =shell= to =bash=.
- Plain cases :: *Empty/unknown language and example blocks remain plain*.
  Do not interpret language labels as files, URLs, commands or plugins.
- Syntax CSS :: *Own the token palette in assets/web/preview.css*, scoped to
  code under the document container. Set light/dark theme variables for every
  emitted token class with a readable fallback. The existing font rules and
  exact CSS CSP hash cover the added stylesheet. Do not load runtime theme files.
- Copy scope :: *Enhance semantic code descendants of the owned document only*.
  A pre/code pair is one target, not a second inline target. Copy the code
  node's restored text content captured before controls are inserted.
  Empty values have no enabled control; whitespace-only values remain copyable.
- Copy affordance :: *Use a native button with a small copy glyph* and an
  accessible name, visible focus and minimum 24 by 24 CSS-pixel target.
  Place block controls beside the block, not inside its copied code.
  Inline controls are adjacent; if code is inside an anchor, place the copy
  control immediately after that anchor. Associate multiple code spans in one
  link with separately named controls in source order.
- Pointer handling :: *Direct code clicks copy only without a noncollapsed
  selection and outside an interactive descendant/ancestor*. Ignore drag,
  multi-click selection, modified clicks and empty code. The explicit copy
  button remains an intentional copy action even with a selection elsewhere.
- Feedback :: *Share the existing clipboard service with the source header*,
  retaining a distinct payload and target label per activation. Allow one
  pending write for the page; ignore further activation until it settles.
  Call writeText synchronously during activation, announce success for two
  seconds, and expose a readonly selectable field on rejection/unavailability.
  Feedback is outside the copied value, labelled for the target and does not
  move focus. Do not log or persist copied content.
- Fold presentation :: *Keep native buttons and the existing three-state cycle*.
  Render =▸=, =▿= and =▾= for folded, children and all, with glyph content hidden
  from assistive naming. Names/tooltips describe the next action and heading.
  Leaves skip children. Retain 24-pixel targets, transparent resting appearance
  and clear hover/focus treatment. Do not replace drawer disclosure controls
  or the global Overview/Contents/Show all toolbar.

*** Data and state

- Preservation :: *Keep typed code records separate from raw HTML fragments*.
  Every record carries its literal value, language and unique association.
  Allocate/serialize under the existing byte ceilings; no unbounded duplicate
  document or per-block subprocess collection is introduced.
- Browser ownership :: *One enhancement lifecycle owns controls, status,
  listeners and timers*. Preserve pre-enhancement heading text for accessible
  fold names so inserted copy controls cannot contaminate it.
  Pagehide tears down all enhancements; bfcache restoration rebuilds once.
- Static and print :: *Plain semantic code remains in generated HTML*.
  JS only adds controls. Print hides all interactive copy/fold chrome and
  manual fields, expands content, then restores prior outline/drawer state.

*** Failure behaviour

- Conversion :: *Invalid internal transport is a diagnosed conversion failure*.
  A writer text mismatch has the exact plain-text fallback described above.
  Unknown language alone is not an error.
- Limits :: *Existing cancellation, publication and cleanup contracts apply*.
  No partial page is opened. Increased token markup may consume the output
  budget sooner; the command reports the same bounded operational failure.
- Clipboard :: *No fallback bypasses browser policy*. Keep manual copying
  available, never read clipboard contents and never change browser settings.

** Architecture impact

*** Security impact

- Threat boundary :: *Source code remains untrusted text*. Private transport
  creates CodeBlocks only; it cannot introduce executable filters, HTML or
  filenames. Escape JSON and verify the collision-free association.
- Data and secrets :: *Clipboard receives only an explicitly activated value*.
  That value already appears in the preview; no clipboard reads, telemetry,
  logging or shared cache is added.
- Access :: *No filesystem or network authority is added*. Lua retains its
  no-file/no-process contract; the highlighter uses installed Pandoc syntax
  definitions. Browser activation grants only the requested clipboard write.
- Conclusion :: *The deliberate new boundary is semantic-code copying*,
  superseding W001's header-only handler scope while retaining passive HTML,
  reserved chrome, exact CSP hashes and source-controlled attribute stripping.

*** Other relevant qualities

- Reliability :: *Literal comparisons prevent coloured-but-altered code*.
  Existing Org metadata and link regressions protect neighbouring behaviour.
- Performance :: *One converter remains sufficient per document*. Budget
  transient code records and generated spans; enhance large pages in batches.
- Operability :: *Install and rollback remain binary replacement*.
  Documentation explains code language labels, copying, glyphs and fallback.
- Accessibility :: *Native controls, selection and no-JS reading remain*.
  Real-browser validation is required for clipboard policy and legibility.
- Portability :: *The existing macOS/Linux/WSL browser matrix applies*.
  No new runtime or browser-specific permission workaround is introduced.
- Maintainability :: *Separate clipboard, outline and code-preservation
  responsibilities*, using small functions and explicit state. Source CSS/JS
  review and user tests follow W001's no-CLI-JavaScript tooling decision.
