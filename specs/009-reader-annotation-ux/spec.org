* Synopsis
:PROPERTIES:
:CUSTOM_ID: summary
:END:

** Outcome

- *Reading controls stay visible* while the reader inserts attributed footnotes.

** Before

- The *filename row scrolls away*; navigation reserves a fixed-width column.
- *Add comment can reuse an earlier selection*; the comment panel is a floating box.

** After

- A *full-width sticky info bar* puts the home-abbreviated filename left and stateful buttons right.
- *Navigation fits its content*; annotations occupy a visible right column, or the larger lower pane on phones.
- In annotation mode, a *click places a footnote at an insertion point* and focuses the comment box.
- *Native Org/Markdown footnotes store only current annotation text*, without autosave history or embedded JSON.
- *Pandoc renders all footnotes at the document end*. Annotation mode moves the
  same footnote section into the sidebar; switching off returns it to the end.
- A *subtle editable Footnote ID field below the comment box* defaults to a normalized username plus a collision-checked counter, such as =tadg-001=.
- *Compact save feedback and readable dates* replace raw timestamps and large closing controls.
- *Show plaintext reveals literal Org/Markdown source*, including embedded annotations, with the info bar retained.

** Changes

- *Annotation mode is explicit* and starts off; leaving it safely finishes the active comment.
- *Plaintext disables annotation* and is absent for text wrappers, code, HTML and binary documents.
- *New document-wide comments leave the UI*; existing document-wide records remain readable.
- *Autosave replaces the current annotation*. Existing native footnotes, including closed comments, can be edited while retaining their ID and attribution.

** Unchanged

- *Autosave timing, author attribution and visible conflict recovery* retain W007's user-facing intent.
- *Loopback/root authorization, passive content, fonts, copying and folding* retain their existing boundaries.
- *Reading does not modify the source*. Saving annotations in service mode
  updates native footnotes in the source, or its sidecar. Standalone =file://=
  previews cannot save annotations. Input HTML retains its permitted authored presentation.

** Edge cases
:PROPERTIES:
:CUSTOM_ID: synopsis-edge-cases
:END:

- *Failed saves retain the composer* and block a mode change that would hide unsaved text.
- *Long paths wrap without disappearing*; a phone keeps document text available above the composer.
- *Unmappable insertion points and ID collisions pause saving*, retaining the draft without guessing.
- *Plaintext exposes only the selected source*, never sidecars or included files; output limits still apply.
- *Read-only sources use sidecars* and virtual preview markers; they cannot acquire physical footnote references.
- *Existing JSON stores remain readable* and migrate to current footnotes only on a successful authorized save.

** Decisions

- Operator, 14 September 2026, annotation cursor :: Use =✎= (Unicode U+270E)
  over eligible prose in annotation mode, with the click hotspot at the pencil
  tip. Package the small cursor within the page; retain a crosshair fallback
  and the existing link, code and control cursors.
- Operator, 14 September 2026, attribution on edit :: On each saved edit, replace
  a final non-empty line that begins =Author:= and ends in an inactive Org
  timestamp with =Author: CURRENT USER; Created: [YYYY-MM-DD Day HH:MM]=.
  Use the current captured display name and local date/time. This supersedes
  earlier author/date preservation for matched attribution lines. Unattributed
  notes still need no tool-origin marker. Use Org timestamp presentation in the
  sidebar as well, replacing the earlier full-calendar-date display alternative.
- Native text consistency :: Creation and editing use the same native footnote
  markup. Re-parse the proposed definition and refuse text that escapes it,
  retaining the draft and original source. This supersedes automatic literal
  wrappers for new comment text: there is no origin-dependent decoding of
  ordinary authored EXAMPLE blocks or fences. Existing native markup stays native.
- Concurrent notes :: An acknowledged application write updates the source
  identity used by all active composers for that document. Editing one ordinary
  footnote must not invalidate an unrelated live draft; changes to the same
  definition still produce a conflict.

- Operator, 14 September 2026, simpler native notes :: Remove redundant annotation
  COMMENT metadata blocks from newly saved definitions. Keep optional author
  attribution and use native inactive Org timestamps, such as
  =[2026-09-14 Mon 03:12]=, with 24-hour time. Existing ordinary notes need no
  attribution or tool-origin marker to be editable. Earlier owned-metadata and
  ISO-display prescriptions below are superseded by this amendment.
- Persistence amendment :: Native labels, references and definition digests identify
  saved notes. Only the active creation session retains its latest receipt and
  draft context in bounded service memory; service restart ends that creation
  session, while reopening reads the native definition
  from disk. No session history or hidden ownership block is written. Authored-body revisions
  exclude native footnote definitions and references regardless of origin; full-store
  and definition digests retain conflict detection. Existing
  old records remain readable; editing an old definition replaces its redundant
  metadata with the ordinary current note and preserves attribution. Read-only
  sidecars retain their readable context and native notes for reconstruction.
- Presentation amendment :: The sidebar heading is *Annotations & Footnotes*;
  the toggle remains *Annotations*. Each individual footnote has a subtle
  background and its content area opens editing, without an Edit button.
  Links, selection and keyboard operation retain their actions. Optional
  attribution uses an Org timestamp or a full day-first date with 24-hour time,
  never a US month-first or 12-hour clock presentation.
- Verification amendment :: Exercise repeated native saves without hidden records,
  retries, reopening and edits, competing changes, read-only sidecar reconstruction,
  preservation of optional attribution and native timestamps. Human paired review
  checks clickable blocks, keyboard access, links and timestamp presentation.

- Operator, 14 September 2026, editable footnotes :: *Allow editing any supported
  native footnote*, including ordinary authored notes and closed HTMLPreview
  annotations. The file and native ID identify it, not browser memory. Preserve
  the ID, references and existing attribution; do not assign authorship to an
  unattributed note. Autosave replaces only its current definition, checks for
  competing disk edits and retains unsaved text on conflict. This supersedes the
  closed/ordinary-note read-only restrictions below; deletion remains excluded.
- Existing-note lifecycle :: An =edit= action uses =target.type: footnote=,
  =target.exact= as the definition digest and =target.run= as =embedded= or
  =sidecar=. Acknowledgements include =footnote_revision=. The editor finishes
  locally after its latest save; there is no new persistent close record.
  Empty text is refused for existing notes, since deletion is outside scope.
  A =Use current footnote= recovery action explicitly discards the unsaved
  proposal in favour of the current definition; Copy draft remains available.
- Implementation for this paired increment :: Reuse the authenticated v2 endpoint
  and atomic writer. An edit carries the native ID, storage location, current
  definition digest and source/store revisions. Reading reconstructs the editable
  definitions from disk. Ordinary footnotes retain native markup without added
  ownership records. Existing annotation metadata is retained for compatibility.
  The edit composer keeps the ID read-only, uses the same autosave feedback and
  finishes on outside activation. Native labels and their repeated references
  survive editing. Unresolvable or ambiguous definitions remain visible with an
  explanation rather than being guessed. Read-only original definitions cannot
  be changed through a sidecar; existing sidecar annotations remain editable.
- Verification for this paired increment :: Extend current-value writer and HTTP
  regression cases for ordinary Org/Markdown notes, repeated references,
  attribution, reload, stale edits, byte preservation and write refusal. Extend
  the existing paired composer review to opening, changing and reopening a
  footnote, preserving markup and observing a competing-edit error.

** Problem

During the annotation review, Taḋg reported *controls disappearing on scroll*,
an oversized navigation column, *stale selection reuse* and cramped comment
presentation. Reviewing the actual source requires a separate preview today.

** Outcome

The reader can *reach controls, insert a footnote, follow save state and inspect
source* in the same preview on desktop and phone layouts.

** Scope

*** In scope

- *Info bar, navigation sizing and button states* on pages using the application template.
- *Service footnote interaction and responsive panel*, replacing event-log persistence with current records.
- *Literal source mode for genuine Org/Markdown*, in file and service previews.
- *Editable footnote labels, exact source patches, current-record storage and legacy import*.

*** Out of scope

- *General source editing, deleting closed comments, new accounts, remote access or a new service*.
- *Plaintext extraction from binary formats*, new document-wide creation UI, source highlighting or a native-HTML toolbar.
- *Changes to Writeback*, new JavaScript runtimes or another browser test framework.

*** Unchanged

- *W006 read admission and W008 format selection* remain authoritative.
- *W007 debounce/maximum wait, attribution, sidecar naming, root confinement,
  acknowledgement and draft-recovery guarantees* remain authoritative unless explicitly replaced below.
- *Existing document-wide comments remain readable*. Creation uses point targets;
  the old mutation protocol is retired rather than emulating event appends.
- *Folding, code/path copying and Org metadata* retain their meaning. Native
  footnotes replace the separate annotation print appendix.

* Edge Cases
:PROPERTIES:
:CUSTOM_ID: edge-cases
:END:

** Closing while the source changes

- Condition :: A mode change overlaps autosave, source replacement or an ambiguous target.
- Required behaviour :: *Keep the composer visible* until existing W007 close and
  reattachment rules permit the transition. Clicking outside never discards a draft.
- Covered by :: [[#ac-009-6][Safe closing]] and [[#rt-009-3][Composer transitions and refresh]].

** Very long paths and the on-screen keyboard

- Condition :: The info bar wraps or the usable viewport height shrinks.
- Required behaviour :: *Recalculate available pane height*; retain scrollable
  controls and editor. Wrapping is preferable to clipping or tiny filename text.
- Covered by :: [[#ac-009-1][Persistent bar]], [[#ac-009-4][Responsive panes]] and [[#ut-009-1][Responsive reading and composition]].

** Text views and annotation storage

- Condition :: An embedded comment was just acknowledged, or a read-only source
  stores its comments in a separate sidecar.
- Required behaviour :: Service plaintext shows the *current source including
  acknowledged embedded events*; it does not read the sidecar as source content.
- Covered by :: [[#ac-009-8][Literal source]] and [[#rt-009-5][Literal source and format boundaries]].

* Solution Design
:PROPERTIES:
:CUSTOM_ID: solution-design
:END:

** Architecture context

- Ownership :: *Go owns bounded source snapshots and safe template data*;
  the existing browser modules own presentation, selection and composer state.
- Reuse :: *Retain composer scheduling and canonical text normalization*. Extend
  the mapper for collapsed points and replace event persistence within the existing
  annotation boundary. Reuse reader teardown and refresh; no parallel controller.

** High-level design

*** Components and responsibilities

- Template/styles :: Make the *info bar a top-level sticky element*, with frontmatter
  in the document flow below it. A shared grid contains navigation, reading
  content and annotation aside. No iframe or duplicate filename control.
- Reader module :: Own *outline/appearance states and plaintext switching*;
  preserve path/code clipboard behaviour and shared disposal.
- Annotation panel :: Own *annotation-mode activation, insertion-point capture,
  panel layout and the guarded transition into another target or reading mode*.
- Renderer :: Retain *original admitted source bytes before annotation stripping
  or preprocessing*, attach the optional source payload, and abbreviate display paths.
- Annotation package :: Own *native footnote recognition/serialization, labels,
  point validation, current-record replacement and legacy reading*. The service
  remains the adapter for capabilities, request limits and author/composer grants.

*** Info bar and responsive layout
:PROPERTIES:
:CUSTOM_ID: layout-contract
:END:

- Width :: The *info bar fills available viewport width*, including over the
  side columns. The article retains its existing readable maximum measure.
- Filename :: *Left aligned*, with =min-width: 0= and a responsive size bounded
  between =0.875rem= and =1rem=. Use =clamp()= with a rem-based fluid term,
  =overflow-wrap: anywhere= and normal wrapping. Do not truncate the copy value.
- Controls :: *Right aligned*, common font/height, contiguous compact buttons,
  quiet coloured fills and a stronger selected fill plus a non-colour state cue.
  Keep each label unbroken; wrap the group only when necessary. Use a neat bottom
  rule and native buttons with visible focus and at least 24 CSS pixel targets.
- Path shortening :: Go obtains the *current user's home through the existing OS
  boundary*. Replace only an exact home prefix followed by a path separator with
  =~/=; retain the original absolute source in the copy data. An unavailable
  home leaves the display unchanged. No new environment setting is introduced.
- Wide layout :: From *72rem*, navigation uses content sizing capped at *14rem*,
  the article uses the remaining width, and an enabled annotation column uses
  *18-24rem*. Empty/disabled navigation reserves no space; long labels wrap.
- Intermediate layout :: From *48rem to below 72rem*, keep article and annotation
  columns when enabled; preserve narrow Org-hidden/Markdown-above-content navigation.
- Phone layout :: Below *48rem*, annotation mode uses a *40% document / 60%
  annotation split* below the info bar, with independent vertical scrolling.
  When the software keyboard reduces usable height, the annotation pane retains
  priority. The info bar and both panes stay reachable; turning mode off restores
  ordinary document flow. No draggable splitter is required.
- Height :: Observe the *actual info-bar height* for sticky offsets and fragment
  scroll margins. Use dynamic viewport units and the visual viewport resize
  boundary where necessary for the software keyboard; dispose observers/listeners
  with the reader. Keep focus, fragment targets and editor actions unobscured.

*** Mode and closing contract
:PROPERTIES:
:CUSTOM_ID: mode-contract
:END:

| Control | State and action |
|---------+------------------|
| Overview / Contents / Show all | Existing folding presets, with at most one selected. Manual folds that match none show all inactive. Reapplying the selected preset is harmless. |
| Annotations | Independent on/off toggle, initially off on each new document. Visible only where W007 exposes annotations; readable comments remain available when creation is unavailable. |
| Show plaintext | Initially off, only for genuine Org/Markdown. While on, disable annotation composition. Overview, Contents or Show all exits plaintext and applies its folding preset. |
| Check glyph (removed) | Superseded by clicking or moving focus outside the editor; guarded close keeps annotation mode on. Escape also finishes the comment. |
| X glyph (removed) | Superseded by the Annotations toggle; no delete/cancel-shaped control appears in the composer. |

- Semantics :: Buttons use *aria-pressed* for state and *aria-controls* for owned
  regions. Annotation toggle also exposes *aria-expanded*. Disabled actions
  remain correctly named. The composer has no X/check buttons.
- Outline ties :: If several presets produce the same empty/simple outline,
  *retain the last selected matching preset*; before an explicit choice prefer
  Show all, then Contents, then Overview. With no foldable content, disable the
  outline buttons. Manual changes still recompute the matching state.
- Transition :: Clicking/focusing outside, annotation off, plaintext entry and a different insertion point use
  *one guarded close path*. Capture the requested target once, await the latest
  text's flush and close acknowledgement, then change UI. Repeated actions while
  pending are coalesced; a failed close leaves the original mode and composer.
- Empty composer :: A never-saved empty composer *closes without writing*.
  Clearing a saved active draft removes that draft's owned reference/definition
  on the next acknowledged autosave. It does not restore old text or affect
  closed comments. Failed clearing retains the prior saved value and visible
  unsaved state; closing waits for the clearing acknowledgement before leaving.
- Refresh :: *Keep active mode, composer and focus outside replaced regions*.
  Reapply controls once after refresh, without duplicate handlers. Retain existing
  source reattachment and navigation guards; new document navigation starts modes off.
- Print :: *Return the native footnotes to the document end* with no interactive
  panels or second annotation appendix. Print current saved content, excluding
  unsaved drafts. Plaintext prints source only. Restore modes and placement afterwards.

*** Point activation and composer feedback
:PROPERTIES:
:CUSTOM_ID: passage-contract
:END:

- Click :: In writable annotation mode, an *unmodified primary click/tap* in
  visible paragraph/list/table prose captures a collapsed caret using
  =caretPositionFromPoint= or =caretRangeFromPoint=. Convert UTF-16 offsets to
  canonical Unicode scalar position with the existing text-normalization rules.
  Show a temporary point marker and focus the comment box; no write occurs yet.
- Selection :: *Dragging or selecting text remains ordinary selection*. It never
  activates a composer, and a subsequent click cannot reuse the old selection.
  Remove Add comment, sentence segmentation and document-wide creation fallback.
- Keyboard :: In annotation mode, make eligible prose blocks focusable. Enter
  activates a *temporary caret at the block start*; left/right moves by Unicode
  character, Home/End moves within the block, Enter opens the composer and Escape
  cancels placement. Arrow keys outside placement retain normal scrolling. This
  is point placement, not a contenteditable document or hidden text selection.
- Exclusions :: *Links, copy controls, code, headings, folding bars, summaries,
  metadata and other interactive elements keep their own actions*. No insertion
  inside literal code, raw HTML, metadata, link destinations or hidden content.
- Fallback :: If caret APIs are absent, use the keyboard placement path. If a
  point cannot be mapped safely, *retain the draft with a location error* and
  permit choosing another point; never snap to a paragraph end or guess a match.
- Composer :: *Outline the insertion point in the document while editing*,
  without a context snippet in the sidebar. A different point waits for guarded close. Clicking
  an existing annotation marker opens its current comment read-only after close;
  corrections create another annotation.
- Footnote ID :: Below the textarea, show a *small, subdued labelled text input*.
  Derive its prefix from the registered display name (existing
  =HTMLPREVIEW_USER_DISPLAY_NAME= then =USER= resolution). Apply Unicode NFD,
  remove combining marks, lowercase, replace runs outside ASCII letters/digits
  with one hyphen and trim hyphens. Thus =Taḋg= becomes =tadg=, not =tag=.
  Use =annotation= if empty; prefix =annotation-= if the result begins with a
  digit. Bound the prefix to 48 ASCII characters and trim its trailing hyphen.
  Browser-native normalization needs no new CLI dependency or call to =azonly.pl=.
  Append a hyphen and the next number above all existing labels with that prefix,
  padded to at least three digits starting at =001=. Scan ordinary and owned
  references/definitions, including sidecars, case-insensitively. Do not reserve
  numbers by writing on composer open. The server checks final uniqueness under
  the document lock on every save; a concurrent collision retains the draft and
  reports a field error. Different names may normalize identically; the prefix
  is a readable label, not an identity or security boundary. Stored author names
  retain their original Unicode spelling.
- ID edits :: Accept *1-64 ASCII characters*, beginning with a letter and then
  letters, digits, underscores or hyphens. Treat case-only differences as
  collisions conservatively across formats. The field stays editable while the
  composer is open; autosave updates its reference and definition together.
  Invalid/duplicate IDs show an inline error, pause saving/closing, and retain
  both fields. Do not silently rename. The textarea keeps initial focus; closed
  comments expose the ID read-only.
- Feedback :: Below the textarea, use small legible text: *Saving*, *Not saved*,
  =✔ Auto saved= or *Save failed*, matching actual composer state. A subtle
  green/amber/red outline reinforces status; colour never replaces text.
  Preserve retry, explicit copy and recovery actions. Use a polite live region
  on state changes, not a repeated announcement for every keystroke.
- Timestamps :: Use *Intl.DateTimeFormat*, browser locale/timezone, medium date
  and short time. Show the author's name separately and use a =time= element
  whose =datetime= and inspectable title retain the *exact recorded UTC timestamp*.
  Formatting never changes stored records.

*** Native footnote representation
:PROPERTIES:
:CUSTOM_ID: footnote-storage
:END:

- Native syntax :: *Org references* use =[fn:annotation01]= and column-zero
  definitions use =[fn:annotation01] Comment text=. *Markdown references* use
  =[^annotation01]= and definitions use =[^annotation01]: Comment text=.
  IDs are per-document labels, independent of the stable internal annotation UUID.
  [[https://orgmode.org/manual/Creating-Footnotes.html][Org named footnotes]] and
  [[https://pandoc.org/MANUAL.html#footnotes][Pandoc Markdown footnotes]] define the syntax.
- Current record :: Store *one definition per annotation*. It contains the
  current comment text plus one owned metadata block with schema version, UUID,
  author, created/updated UTC timestamps, draft/closed state, latest operation
  UUID and monotonic revision. Those last two values support retry recognition;
  *no previous operations, values or timestamps form a persisted history*.
- Keys :: The metadata fields are =DOCUMENT_ID=, =UUID=, =AUTHOR=, =CREATED=,
  =UPDATED=, =STATE= (=draft= or =closed=), =OPERATION= and =REVISION= (the latest
  accepted sequence). The document UUID is shared across its source and sidecar;
  the annotation UUID stays stable when its visible label changes. A sidecar or
  legacy unplaced note also carries =POINT=, =BEFORE=, =AFTER= and optional
  =HEADING_ID=. A legacy document-wide note uses =POINT: unplaced=, never a
  guessed zero offset. No absolute source path or capability is persisted.
- Metadata :: Use a native uppercase =#+BEGIN_COMMENT= / =#+END_COMMENT= block
  inside the Org definition, and an indented HTML comment inside the Markdown
  definition. The first line is =HTMLPREVIEW_ANNOTATION: 2=, followed by fixed
  uppercase =KEY: value= lines. Values are single-line UTF-8; encode =&=, =<=,
  =>= and the second hyphen of any =--= using numeric character references and
  decode those only in owned metadata. UUID hyphens remain ordinary hyphens.
  No JSON object is persisted. Unknown/duplicate keys or invalid values block
  mutation rather than being adopted as an ordinary note.
- Visible attribution :: The definition includes a final *Author and Created
  attribution paragraph* in readable text, before its hidden metadata. It is
  generated from the authoritative metadata, not taken from browser fields.
  Browser display continues to localize dates; stored UTC dates are stable.
- Text encoding :: Keep safe plain paragraphs readable. For text that could
  introduce definitions, directives, headings or metadata delimiters, use a
  literal block for the *whole comment body*: uppercase Org EXAMPLE with Org's
  comma escaping, or an indented Markdown code fence longer than any matching
  run in the text. The owned codec reverses this exactly. This does not add rich
  text comments; all comment text stays inert in HTML Preview and native export.
- Ownership :: Recognize only syntactically valid *named footnote definitions
  with the complete owned metadata block*. Similar labels, literal examples,
  ordinary comments and ordinary footnotes are not owned. Use the source's
  literal-region handling before recognizing definitions and references.
- Placement :: Insert the owned reference *at the verified source point* and
  add its definition at a safe top-level location at EOF, separated according to
  the native footnote grammar. Reject an unterminated literal/comment context.
  On edits, patch only its reference token, body and metadata. Preserve all other
  source bytes, BOM, line endings, ordinary footnotes and comments.
- Rendering :: *Leave references and definitions for Pandoc to render normally*;
  remove only hidden owned metadata from the conversion input. Keep native
  footnote content at the document end, outside heading folding and navigation.
  Annotation creation does not install a parallel comment renderer. Comments
  remain passive under the existing sanitizer; ordinary notes retain their content.
  Markdown portability requires a reader supporting footnotes.
- Reading without annotation UI :: File previews and service registrations without
  annotation UI retain native endnotes without gaining writes. Existing reference
  clicks follow their normal link to the endnote; they do not automatically enter
  annotation mode. The mode button controls relocation explicitly.
- Read-only sources :: Keep the established full-basename =-annotations.org=
  sidecar. It contains a readable context line with an Org footnote reference and
  one matching current definition. Metadata additionally stores source identity,
  canonical point and 64-scalar before/after context for reattachment. *Never
  insert a physical reference into a read-only source*. Its preview gets virtual
  markers; external readers need the sidecar and cannot display those as inline
  source footnotes automatically.

*** Native endnotes and sidebar placement
:PROPERTIES:
:CUSTOM_ID: native-endnotes
:END:

- Observed HTML :: A bounded probe with *Pandoc 3.9.0.2* on 14 September produced
  the same structure from Org and Markdown: =a.footnote-ref#fnref1[href="#fn1"]=,
  =section#footnotes.footnotes.footnotes-end-of-document= containing =li#fn1=,
  and =a.footnote-back[href="#fnref1"]=. Roles were =doc-noteref=,
  =doc-endnotes= and =doc-backlink=. Source labels are not preserved as those
  HTML IDs: *never infer a footnote label from fn1 or its displayed number*.
- Rendering boundary :: Retain these Pandoc classes, IDs and fragment links through
  finalization. The current sanitizer strips these role attributes; preserve only
  the corresponding fixed role values on the appropriate anchor/section elements.
  Do not globally allow arbitrary roles or use source-supplied classes as write authority.
  After heading wrapping, keep endnotes as the final non-foldable document child.
- One DOM list :: The reader remembers the *original endnotes position*. On
  annotation-mode entry, move that existing section into the annotation aside;
  on exit, move it back. Do not clone, renumber or separately generate its notes.
  All ordinary and owned footnotes participate; only the active owned composer
  can write. Keep the composer distinct from the read-only native footnotes.
- Navigation :: Preserve native IDs and hrefs. Reference links scroll to their
  target in whichever pane currently contains it; backlinks reveal a folded
  source section and return to the reference. Keyboard focus and fragment scroll
  margins account for the persistent info bar. No automatic toggle on a normal
  reference click is required.
- Refresh/print :: Restore the list before reader teardown, replace it with the
  freshly rendered list through the existing page refresh, then reapply the mode.
  Full-store changes, including footnote-only updates, trigger this refresh.
  Keep the composer outside replacement and preserve its focus/dirty text. Print
  temporarily restores native placement; there is no second saved-comment appendix.
- Canonical text :: Go and browser point mapping both *exclude endnotes and
  footnote-reference/backlink labels*. Moving the list or updating its text must
  not change a point's canonical offset or authored-body revision. Ordinary source
  text remains included; no arbitrary source class changes write authorization.
- Empty/unplaced notes :: A document with no footnotes still permits point creation.
  Legacy or sidecar comments without a verifiable location remain explicitly
  unplaced entries at the end, included in the same moved section without a false
  inline source marker. They are not silently discarded or presented as located notes.

*** Source-point verification and replacement
:PROPERTIES:
:CUSTOM_ID: point-and-replacement
:END:

- New point :: Send *canonical point, body revision and the clicked text run plus
  its scalar offset*, bounded by W007's existing 8 KiB target limit. The service
  verifies that run/offset against its fresh rendered DOM; it does not trust a
  browser-supplied raw-file offset. Match that literal run in eligible source prose,
  treating source whitespace runs according to the canonical normalization.
  Require a unique candidate outside excluded/literal regions.
- Proof :: Before first insertion, render the candidate patch with an owned
  probe marker through the *existing Pandoc pipeline*. Accept only if removing
  the marker reproduces the same canonical document and its position equals the
  requested point. Perform one candidate conversion, within the existing deadline
  and byte budgets, not an unbounded search over positions. Escaped/transformed
  text or duplicate matches that cannot be proven report an unmappable point.
- Later saves :: *The existing owned reference identifies the point*. Editing
  neighbouring text does not require fuzzy quote matching. A missing/duplicate
  reference leaves the comment visible as unplaced and pauses mutation; changing
  a label in the composer changes only that owned reference and definition.
- Sidecar/unsaved reattachment :: Reuse canonical before/after context and
  structural IDs to accept only a unique current point; otherwise show unplaced
  state. Persist no selected-text range. External edits do not silently move a
  marker to the nearest paragraph.
- Save transaction :: Under the existing per-document lock, *reread the rooted
  source and selected store*, validate ownership/revision/label, and build the
  patched bytes. Write a private sibling temporary file through the same root,
  flush it, preserve required metadata, then recheck original identity/content
  immediately before atomic rename. Sync the containing directory before success.
  Never rewrite by rendering the whole document back from a Pandoc AST.
- Write admission :: Test the *source's own write permission* before replacement,
  even when its parent directory permits rename. EACCES/EPERM/EROFS selects the
  established sidecar route; a writable parent must not bypass a read-only file.
  A destination that cannot create a sibling temporary file reports save failure.
- Metadata and failure :: Preserve owner/mode and supported ACLs/extended
  attributes. *Refuse replacement when present metadata cannot be preserved*;
  do not silently strip it. Retain root/symlink/hard-link checks and private file
  creation. Before rename, failure leaves the old file; after rename with an
  uncertain durability acknowledgement, report the uncertainty and reconcile
  the current operation rather than replaying an old snapshot. Clean only the
  exact owned temporary file; no journal or backup history is added.
- Concurrency :: Merge another composer's saved current records into a fresh
  snapshot, never overwrite them with a cached page. Recheck the current source
  on every mutation. An uncooperative editor can still write after the final
  check or save an old buffer later; *filesystem rename is not cross-process
  compare-and-swap*. Document that limit, without claiming autosave eliminates it.
- Bounds :: Retain the *10 MiB source/sidecar and combined annotation-byte limits*,
  with at most *10,000 current annotations* and the existing 64 KiB per-record
  bound. Size accounting includes native encoding and the candidate/temp output.
  Previous draft versions no longer consume document quotas.

*** Current-value protocol and existing stores
:PROPERTIES:
:CUSTOM_ID: footnote-transition
:END:

- HTTP :: Use =/_annotations/v2/<read-token>/<root-relative-path>= with the same
  reader selectors, rooted admission, exact-origin/write/composer tokens,
  limits and private author registration as W007. GET returns =protocol: 2=,
  revisions, storage/writable/reason and a =comments= list of current records;
  it does not expose an event-history API. HEAD remains non-mutating.
- Mutation :: POST carries =operation_id=, =annotation_id=, monotonic =sequence=,
  =composer_id=, =action: upsert|close=, =label=, =text=, =target= and W007's fresh revision
  preconditions. Author/timestamps are server-owned. Use one in-flight request
  per composer and the existing 300 ms debounce/two-second maximum wait.
  Upsert replaces only the current active value; close sets closed state without
  duplicating its text. An empty active upsert removes only that active record;
  empty initial composition does not create a store. No DELETE for closed notes.
- Point interface :: A new target has =type: point=, =body_revision=,
  =position= (canonical scalar offset), =run= (clicked text-node text) and
  =run_offset= (scalar offset within it). The server verifies all fields and
  derives before/after context and structural identity. Subsequent mutations
  retain the annotation UUID and resolve its current owned reference. GET's
  current records expose =annotation_id=, =label=, =text=, author/timestamps,
  sequence, state and resolved/unplaced status; they never expose composer secrets.
- Revisions :: Preserve *authored-source versus full-store revision separation*:
  exclude owned footnote tokens/definitions when calculating authored-source
  revision. The full revision includes current source and sidecar records.
  Another comment save does not by itself invalidate an authored point, but
  each mutation rereads and merges the current records and checks its own sequence.
- Retry :: Persist only the *latest operation/sequence* in each current record.
  A matching retry returns that current result; an older request cannot replace
  newer text. Keep bounded latest-operation state for active composers (including
  clearing) in existing grants. After restart, saved drafts are recovered read-only
  and stale composers must reload; the browser retains unsaved text for copying.
- Errors :: Retain W007 status/error conventions; add field-scoped
  =invalid_label= (400), =label_conflict= (409), =point_unmappable= (409) and
  =storage_metadata_unsupported= (409). They pause saving with text/ID intact.
  Old v1 mutation requests receive 409 =annotation_upgrade_required= and reload
  guidance. Version-1 GET may return the same upgrade error; no dual write path.
- Existing records :: *Read version-1 stores with the existing decoder*. On the
  next successful save to that destination, project the latest valid value per
  annotation, preserve UUID/author/timestamps, and replace its owned log with
  native current records in the same transaction. Historical draft text is not
  copied into another file or committed to Git. Invalid/incomplete logs block
  mutation and remain intact. Reading alone never migrates a source.
- Legacy anchors :: For a uniquely resolved old passage, place its new marker at
  the *end of that passage*. A document target or unresolved range becomes an
  explicitly unplaced current definition, visible in the endnotes/sidebar with its
  original context; do not invent a location or discard the comment.
- Two stores :: Migrate *only the destination being written*. A source and sidecar
  are not an atomic pair; continue reading both and reconcile by UUID/sequence,
  rejecting equal-version conflicts. An unwritable legacy store stays readable
  until it can be explicitly saved. Never perform a silent multi-file conversion.
- Compatibility :: This replaces the unreleased candidate's annotation writer;
  older binaries are not compatible writers for native current records. Rebuild
  and restart the service during delivery and reload its review pages. The old
  event writer is retired; the decoder remains solely for legacy reading/import.

*** Literal source payload and view
:PROPERTIES:
:CUSTOM_ID: plaintext-contract
:END:

- Eligibility :: Use the *same genuine Org/Markdown provenance classification
  as W007*, independently of whether annotations are enabled. A generated Org
  wrapper or explicit reader override cannot turn code, TXT or binary input
  into an eligible source. Native HTML remains outside the application template.
- Payload :: Carry the *original bounded source snapshot* as base64 in an owned
  inert template field. Decode UTF-8 and assign =textContent= to a plain =pre=;
  never assign source to =innerHTML=. This preserves CRLF, BOM and initial newlines
  through HTML parsing and prevents source closing tags escaping the payload.
- Presentation :: Show *Iosevka text without syntax highlighting*, preserving
  spaces, tabs and line breaks, with soft wrapping for viewport fit. Hide rendered
  frontmatter/title/body, navigation and annotation panel; retain the info bar.
  No linkification, source editing or source-code copy takeover in this view.
- Service entry :: After any guarded close, *fetch the existing authorized page
  URL* through the current refresh path before showing its source payload. This
  includes newly acknowledged embedded events without a new endpoint or query.
  A failed fetch leaves the current readable view and reports the failure.
- Refresh :: Where W007 polling is enabled, *plaintext follows full source/store
  revision changes*, including annotation-only replacements, through the existing
  bounded page GET/swap. No writes occur in plaintext. Without that polling,
  service view refreshes on entry; file mode retains its original snapshot.
  Returning to rendered view restores reading state with annotation mode off.
- Bounds :: Include payload/base64 growth in *existing source, output and cache
  budgets*. Do not independently reopen sources, expose sidecar content as source,
  add a raw-files route or increase limits. Missing/invalid payload is a visible
  unavailable-view error, not a switch to blank or truncated content.

** Design decisions and verification

*** Pandoc owns footnote rendering

- Decision :: *Relocate the existing native endnotes section* for the sidebar.
- Rationale :: The operator explicitly chose normal endnotes with a convenience
  sidebar. One DOM section preserves native links and avoids a second renderer,
  duplicate numbering, IDs or a separate print appendix.
- Verification :: [[#rt-009-8][Native endnote relocation]] and [[#ut-009-4][Footnote portability]];
  implementation review checks that native content is reused rather than rebuilt.

*** Shared layout and one browsing context

- Decision :: *Sticky CSS and a shared responsive grid* keep controls and panes visible.
- Rationale :: They retain selection, focus, CSP and refresh ownership in one
  document. An iframe adds an unnecessary browsing and communication boundary.
  [[https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/position][MDN positioning]] and [[https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/clamp][MDN bounded fluid sizing]] supply the relevant mechanisms.
- Verification :: [[#rt-009-1][Info bar/layout regression]] and [[#ut-009-1][Responsive review]];
  implementation review checks one lifecycle and no duplicate shell.

*** Retain composer scheduling, replace event persistence

- Decision :: *Point changes, outside activation and mode controls share one guarded transition*;
  reuse scheduling and acknowledgement handling, replace persistence with current records.
- Rationale :: Neither permanent event logging nor fire-and-forget close satisfies
  the operator's current-value storage and reliable autosave requirements.
- Verification :: [[#rt-009-3][Composer transition regression]]; implementation review
  checks shared close/recovery code rather than a second persistence path.

*** Browser-native caret and date handling

- Decision :: Use *native collapsed carets and Intl date formatting*, with keyboard point placement.
- Rationale :: The user chose insertion points; sentence segmentation and selected
  quotation anchors are unnecessary. [[https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/DateTimeFormat][MDN date formatting]] describes locale/timezone output.
- Verification :: [[#rt-009-2][Point activation]], [[#rt-009-4][Dates]] and [[#ut-009-2][Human point/save review]].

*** Native current records and verified byte patches

- Decision :: *Native footnotes carry the current value*, updated with small
  source patches committed as one file replacement. Retain only a legacy decoder.
- Rationale :: This meets the requested human-readable storage and insertion
  fidelity without a second database, document event journal or AST rewrite.
  One bounded marker round-trip proves a new point; unsupported mapping fails
  explicitly. Metadata preservation is required, not a reason to broaden access.
- Verification :: [[#rt-009-6][Native/current-value regressions]], [[#rt-009-7][Writer/import regressions]],
  [[#ut-009-4][Native-reader review]] and [[#ot-009-1][Native replacement check]].
  Implementation review checks one codec/write boundary and retirement of v1 writes.

*** Same admitted snapshot for literal source

- Decision :: *Embed the original text in existing page output* and reuse page refresh.
- Rationale :: Both delivery modes gain the same view without an additional HTTP
  endpoint, file permission or binary extraction pipeline. Extra bytes consume
  the existing budget; oversized pages fail visibly rather than broadening limits.
- Verification :: [[#rt-009-5][Source/format regression]]; implementation review checks
  pre-transform snapshot ownership, output accounting and unchanged authorization.

** Routine details left to implementation

- *Exact colour tokens, border radius, spacing and helper names* may follow the
  existing styles within these layout, accessibility and lifecycle constraints.

** Architecture impact

*** Security impact

- Threat boundary :: *Same authorized document and loopback service*. The v2
  annotation adapter replaces v1 mutation; no new roots, general file routes,
  external resources or wider capabilities. Current-value writes now replace
  owned portions rather than merely append; fresh checks and atomic publication
  protect the larger write consequence.
- Data :: Plaintext *reveals already admitted source text*, including embedded
  current comments hidden from the article. It never merges sidecars or
  follows includes. Document this difference; do not log payloads or tokens.
- Passive rendering :: *Base64 transport and textContent* keep all source inert;
  retain CSP and template provenance. Source attributes cannot forge owned controls.
- Mutation :: *Only the constrained annotation upsert/close path writes*.
  Reading, empty initial activation and source mode are non-mutating. Clearing
  an active saved draft removes only that draft; closed comments remain immutable.

*** Other relevant qualities

- Accessibility :: *Visible focus, named controls, textual state and reflow* are
  required; small visual controls retain usable hit targets. No iframe focus trap.
- Reliability :: *One guarded transition and existing refresh recovery* protect
  drafts; preserve the known limit that unrelated editors may overwrite old buffers.
- Performance :: *No new polling loop or unlimited payload*. Source presentation
  uses the existing output/cache ceilings and verifies new insertion points on demand.
- Portability :: *Existing Go/browser stack only*. Record actual browser/device
  qualification; unavailable Linux/WSL and phone checks remain explicit.
