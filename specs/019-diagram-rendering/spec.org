* Synopsis
** Outcome
- Explicit =mermaid= and =plantuml= blocks *render as bounded PNGs* above retained source.
** Before
- Diagram blocks appeared only as literal code.
** After
- Installed local renderers generate inert PNG assets; failure retains source.
** Changes
- Preserve code language through the owned transport and add two renderer boundaries.
** Unchanged
- Source files, ordinary code blocks and browser script policy remain unchanged.
** Edge cases
- Missing tools, invalid syntax and resource limits fall back to literal source.
** Decisions
- Mermaid uses strict configuration; PlantUML uses =SANDBOX=; no generated SVG enters the browser.
** Next step
- Closed after delivery and retrospective definition review, and operator browser validation.

* Context
- Scope :: Markdown fences and Org source blocks labelled =mermaid= or
  =plantuml=; file/service PNG publication; packaging and service PATH.
- Out of scope :: Remote services, implicit detection, includes, interactive
  links, browser-side Mermaid and deployment.

* Solution Design
- Flow :: Owned transport carries language/source; literal executables run under
  the existing context/byte limiter; verified PNG reuses existing media routes.
- Security :: Mermaid is =strict=; PlantUML uses =SANDBOX= and a 256 MiB heap.
- Failure :: Log a bounded notice, keep source and make failed service pages retryable.
