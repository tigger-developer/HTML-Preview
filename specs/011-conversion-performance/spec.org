* Synopsis
:PROPERTIES:
:CUSTOM_ID: summary
:END:

** Outcome

- *Org previews and annotation refreshes* render substantially faster while
  retaining their *formatting, native footnotes and safe block placement*.

** Before

- The existing annotation workflow can perform *three Pandoc conversions*.
- A measured 532 kB Org document required *8.13 seconds* for an uncached page.

** After

- *go-org replaces Org conversion* within the same intermediary workflow.
- The release benchmark requires *at least fivefold faster* uncached rendering
  of the large corpus, with *unchanged annotation safeguards*.
- The experiment achieved *0.74 seconds*. The production benchmark subsequently
  measured *0.665 seconds* against *7.951 seconds* for the large-document GET;
  [[file:validation.org][validation evidence]] records the full comparison and passing reader and
  annotation user reviews of 22 September 2026.

** Changes

- A *same-executable converter worker* supplies normalized HTML and the existing
  private transport records; it adds *no separately installed runtime*.
- The adapter preserves *footnotes, headings, navigation, task semantics,
  checkboxes, metadata and highlighted code*.
- *Chroma supplies native highlighting*, with pinned dependencies, licence
  notices and vulnerability checks; it adds *no installed runtime*.
- A bounded go-org correction admits *long lines within existing byte limits*.
- Native Go memory accounting replaces the *Pandoc-specific heap control* for
  Org only, with the explicit bounds described in the design.

** Unchanged

- This increment left *Markdown and other readers on Pandoc*; the later
  [[file:../014-native-markdown/spec.org][W014 native Markdown migration]] supersedes that Markdown path.
  Pandoc is now optional for other readers. Native HTML retains its passive
  authored presentation.
- *Block-level annotation*, native source edits, source identity checks, autosave,
  SSE refresh, cache ownership and the *15-second annotation deadline* remain.
- *No file-mode writes*, network exposure, new public settings or data migration.

** Edge cases
:PROPERTIES:
:CUSTOM_ID: synopsis-edge-cases
:END:

- *Repeated text, short definitions and nested blocks* retain verified endpoints;
  an unverified target remains unavailable and cannot be written.
- *Private markers never appear* in published pages or source files.
- *Conversion failure or timeout* returns an error, without a partial page,
  silent fallback or weakened write checks.

** Decisions

- Select *go-org*: the pipeline experiment passed *23 selected checks*; org-rust
  passed 20 and its smaller additional speed gain did not outweigh the gaps.
- Keep *all existing passes*. Source-offset extensions, Markdown replacement,
  pass reduction and a new source mapper are *outside this change*.

** Next step

- Reader and annotation user reviews passed on 22 September 2026. The
  [[file:validation.org][validation record]] retains the tested scope, revisions and earlier observations.
  The [[file:../../docs/work.org::#w-011][work ledger]] owns lifecycle status; native Linux/WSL execution remains
  an explicit validation limitation.

* Context
:PROPERTIES:
:CUSTOM_ID: context
:END:

** Problem and outcome

Long Org documents make annotation refresh wait for repeated conversion. The
existing 15-second request grace keeps slow requests usable; it does not remove
the delay. The change *replaces the Org converter*, preserving the established
reading and editing contract rather than redesigning annotation mapping.

[[file:assessment.org][The conversion assessment]] records isolated parser comparisons and the
more relevant complete-pipeline experiment. The latter retained preservation,
intermediary markers, structural checks, source writing and final presentation.
Its timings are *feasibility evidence*, not release-test results.

** Scope

*** In scope

- *Every conversion selected as Org*, including internal literal Org wrappers,
  explicit reader selection, file previews and service-linked documents.
- An application-owned go-org adapter and *equivalent published HTML semantics*.
- Compatibility corrections exposed by the corpus; *no unsupported block becomes
  editable* merely because a different parser emits an element for it.
- Reproducible dependency packaging, notices, resource handling and performance
  evidence through the existing application entry points.

*** Out of scope

- Fewer passes, a new cache, native source offsets, sentence splitting, cursor
  matching, source reserialization or changes to annotation storage.
- Goldmark, org-rust, Orgize, Haskell translation, complete Emacs Org emulation,
  additional document formats or removal of Pandoc.
- Browser automation, new services, user configuration migration or live deployment
  during definition.

*** Unchanged

- W009's current *native editable footnotes*, including multiple paragraphs,
  attribution, deletion confirmation, sidecars and block-end placement.
- Source snapshots, authorization, link rewriting, approved roots, loopback-only
  HTTP, passive content policy and original-filename information bar.
- Existing UI, fonts, themes, folding precedence, annotation deadlines and draft
  recovery. Only converter-specific HTML normalization changes.

** Decisions and lineage

- The initial skeleton considered *pass reduction and native readers*. The first
  assessment preferred fewer Pandoc passes and considered go-org plus Goldmark.

  source offsets* as the selected scope. That choice supersedes the first
  recommendation; [[file:assessment.org][assessment history]] retains its evidence and estimates.
- The new adapter must resolve demonstrated compatibility gaps, not require
  byte-identical HTML or blindly reproduce a Pandoc parsing defect.
- *No automatic Pandoc fallback for Org* and no engine selector. Errors remain
  visible; rollback uses the previous application build without changing documents.

** Unresolved blockers

- No unresolved product-design decisions. The linked validation and audit records
  retain execution evidence and closure-gate status separately.

:PROPERTIES:

  attribution and concurrency rules in embedded and sidecar modes. Reading
  never modifies source.
- Proven by :: [[#rt-011-5][RT011.5 - Footnote lifecycle]], [[#ut-011-2][UT011.2 - Annotation review]].

** AC011.6 - Conversion cannot widen document access :ac:
:PROPERTIES:
:CUSTOM_ID: ac-011-6
:END:

- Criterion :: Source-controlled includes, setup files, links, export blocks and
  code cannot cause *converter file reads, resource fetching or execution*.
  Published source content still passes the existing passive policy and rooted
  resolver; malformed private records fail closed.
- Proven by :: [[#rt-011-6][RT011.6 - Trust boundaries]].

** AC011.7 - Conversion failure remains bounded and recoverable :ac:
:PROPERTIES:
:CUSTOM_ID: ac-011-7
:END:

- Criterion :: Native conversion enforces [[#worker-contract][the worker bounds]], admits
  long lines within the existing byte allowance, and *fails explicitly* on
  invalid input, exceeded limits, cancellation or converter failure. No partial
  page is published and no unsafe annotation write follows a failed proof.
  Subsequent valid requests remain serviceable.
- Proven by :: [[#rt-011-7][RT011.7 - Limits and failure recovery]].

** AC011.8 - Full-pipeline latency improves materially :ac:
:PROPERTIES:
:CUSTOM_ID: ac-011-8
:END:

- Criterion :: Under [[#performance-method][the same-machine comparison]], the large Org corpus
  has an *uncached median at most 20% of baseline*; the medium and small corpus
  medians do not regress. The ordinary conversion, conditional footnote pass
  and block verification remain enabled. Timing alone cannot waive fidelity.
- Proven by :: [[#ot-011-1][OT011.1 - Full-pipeline benchmark]].

** AC011.9 - Packaging remains a single application :ac:
:PROPERTIES:
:CUSTOM_ID: ac-011-9

* Edge Cases
:PROPERTIES:
:CUSTOM_ID: edge-cases
:END:

- Parser differences :: Additional go-org targets are acceptable only when
  they correspond to already-supported *whole semantic blocks* and satisfy the
  unchanged source proof. Missing short definitions and fragment targets are
  compatibility defects, not reasons to relax that proof. Covered by
  [[#rt-011-4][RT011.4 - Block placement]].
- Export settings :: Native defaults must not suppress deep headings, TODO
  labels, footnotes or tags that the current preview preserves. Preservation
  owns metadata and authored exclusions; go-org must not add its own second
  filtering policy. Covered by [[#rt-011-2][RT011.2 - Semantic HTML]].
- Existing pages across upgrade :: Restart invalidates current capabilities
  under the existing service contract. Reload uses the new converter; no old/new
  engine state is persisted. Original native source remains usable by either
  application build. Covered by [[#rt-011-5][RT011.5 - Footnote lifecycle]].
- Unsupported syntax :: Preserve existing literal/error behaviour; do not invent
  support or silently discard source because the replacement lacks a feature.
  A material unsupported compatibility case blocks delivery pending remediation
  or explicit scope amendment. Covered by [[#rt-011-2][RT011.2 - Semantic HTML]].

* Solution Design
:PROPERTIES:
:CUSTOM_ID: solution-design
:END:

** Architecture context and flow

1. Existing input resolution and snapshot validation select a reader.
2. Existing Org preservation emits its *temporary intermediary*, including
   protected literal content and application-owned metadata markers.
3. When the effective reader is Org, invoke the *same executable's native
   converter worker*. Other readers keep the existing Pandoc command.
4. The worker parses with go-org and produces the HTML/owned-record contract
   expected by =restoreTransport=; it does not read or write source files.
5. Existing restoration, sanitizer, catalogue, reference resolver and final
   template publish the page. Footnote identification and block verification
   call the same converter path for their intermediaries, as they do today.
6. The existing annotation boundary alone validates revisions and writes native
   references/definitions. The converter never reserializes source.

- Ownership :: A narrow internal Org conversion package owns parser configuration,
  writer adaptation and native highlighting. =internal/preview= retains application
  state, volatile Host execution, preservation, security and publication.
- Shared operation :: One render dispatch and the current restoration pipeline;
  no separate implementations for plain rendering, label probing and block probing.
- Structural verification :: Delivery-code review checks that existing proof,
  source writer and pass selection remain intact, with no hidden fallback or
  alternate cache. Behaviour is exercised by the traced regression package.

** Private worker and resource contract
:PROPERTIES:
:CUSTOM_ID: worker-contract
:END:

- Invocation :: A private =--internal-org-convert= mode of the *current binary*,
  resolved through =os.Executable=, before normal CLI/config/service startup.
  Use direct argv and stdin through the existing Host executor. No shell,
  executable lookup in a document directory, persistent pool or second service.
- Test execution :: Extend the existing =internal/preview/preview_test.go=
  =TestMain= dispatcher to recognize that private mode before running tests or
  its ordinary CLI-child path, and call the same native worker entry function.
  Thus =os.Executable= still names a worker-capable binary in package tests.
  Built-CLI tests exercise the production dispatcher separately. No production
  environment variable, configurable executable path or test-only endpoint is
  added; the existing test subprocess pattern is reused.
- Input :: One size-bounded JSON request containing protocol version =1=,
  intermediary text, owned transport token, TOC enable/depth and remaining input/
  output byte budgets, plus an optional list of current block-probe labels.
  Thread that list from the existing candidate map through render dispatch;
  do not change candidate generation or matching. Bound its serialized size
  with the request. Reject unknown/duplicate fields, trailing values, malformed
  tokens and ceilings above existing application maxima. Tokens stay on stdin,
  never argv or diagnostic output. The worker accepts no document/resource path.
- Output :: One HTML document on stdout with a body and existing owned transport
  elements. Success exits zero; failure exits nonzero, with bounded content-free
  diagnostics. Parent retains existing combined stdout/stderr accounting and
  does not publish partial output.
- Lifetime :: One process per conversion. Parent cancellation or deadline kills
  and reaps it through =runProcess=. Keep the existing two service work slots,
  coalescing, 60-second render ceiling and 15-second annotation-request budget.
- Byte bounds :: Preserve 10 MiB per source, 50 MiB per service conversion
  output and 100 MiB aggregate owned service scratch output, alongside existing
  stricter remaining session allowances. Count intermediary/protocol overhead
  and generated output against
  remaining allowances; never truncate to fit.
- Memory :: Set a *512 MiB Go runtime memory target* in the worker and abort on
  observed Go runtime accounted memory above 512 MiB. A worker-owned 10 ms
  monitor uses runtime accounting, stops on exit and emits only a limit error.
  This is *not a hard RSS ceiling*: transient overshoot and non-Go process memory
  are outside that measurement. It deliberately replaces W006's Pandoc-specific
  maximum-heap mechanism only for native Org; parent process isolation, byte
  ceilings and killable deadlines remain. Do not label a soft target as a hard cap.
  Revisit the target/abort margin only if measured valid inputs trigger limit
  failures or excessive GC latency; any ceiling change requires a scope decision.
- Rationale :: go-org has no cancellation API. Process isolation preserves a
  terminable conversion boundary and confines parser/highlighter failures to the
  request. It is the same packaged program, not a new deployment dependency.
- Verification :: [[#rt-011-7][RT011.7 - Limits and failure recovery]], with lower injected
  private bounds for deterministic threshold tests; packaging uses
  [[#ot-011-2][OT011.2 - Packaging and dependencies]].

** Parser dependency and narrow patch

- Baseline :: =github.com/niklasfasching/go-org= at revision
  =2f088a12697ba4dad46c2c2084db3ae1707830fb=, MIT. The
  [[https://github.com/niklasfasching/go-org/tree/2f088a12697ba4dad46c2c2084db3ae1707830fb][inspected upstream revision]]
  is the comparison baseline, not an assertion that upstream never changes.
- Local correction :: Keep the required upstream =org= package as a minimal
  local module under =third_party/go-org= with its licence and provenance.
  Use a module replacement and document the patch against that exact revision.
  Parameterize the scanner's maximum token size from the bounded intermediary
  length, allowing long lines without altering line breaks or source semantics.
  Do not copy the upstream CLI, website or unrelated tooling.
- Patch boundary :: No native source-offset instrumentation or parser rewrite.
  Prefer writer hooks and existing preservation for compatibility; additional
  necessary parser fixes require a focused reproducer and documented diff,
  staying within this specification's existing semantic contract.
- Configuration :: Fresh parser/writer per conversion; deny =ReadFile= for every
  path, disable automatic external resolution, and suppress unsafe expansion.
  Route library diagnostics through bounded content-free classifications.
  No ambient log output containing document text.
- Native defaults :: Disable go-org's duplicate title/TOC output and extra
  export exclusions; the existing preservation and page settings own them.
  Preserve declared TODO partitions and deep hierarchy instead of relying on
  go-org's default export depth or default TODO configuration.
- Maintenance :: Pin linked dependencies in =go.mod=/=go.sum=, retain MIT notices
  and record the local delta. Security review checks the actual linked graph;
  upstream's declared test/CLI dependencies need not enter the release binary.
- Upstream advisories :: Retain the upstream module path, exact revision and
  corresponding Go module version in the patch provenance. In addition to the
  actual application scan, =make vulncheck= runs =govulncheck -scan=module=
  on an OS-temporary minimal module importing the *unreplaced upstream org
  package at that pinned version*, with the same locked transitive versions.
  Prepare and commit its manifest/checksums during dependency adoption; the gate
  copies those inputs and never resolves new versions or edits tracked files.
  Missing/stale provenance, unavailable advisory data or a non-exempt finding
  fails the gate. Keep text-mode scanner exit semantics; no JSON-output success
  masking. This supplements the actual-code scan and local-patch review; it does
  not claim upstream scanning verifies the patch. Repeat on dependency updates
  and releases through the same gate, without a second scanner or service.

** Published HTML compatibility contract
:PROPERTIES:
:CUSTOM_ID: html-contract
:END:

The adapter owns *structural compatibility*, not byte-for-byte Pandoc HTML.
Normalize with =golang.org/x/net/html= or writer hooks, never regular-expression
rewriting of HTML. Keep browser controllers unchanged where the existing
semantic contract suffices.

| Concern | Required adapter output and retained owner |
|---------+--------------------------------------------|
| Metadata/title | Existing preserved fields, source order, title/subtitle/author/date; final application template owns their sole display |
| Headings | Ordered nested sections, direct heading node, actual source level and owned heading records; current catalogue restores IDs/aliases and resolves duplicate IDs |
| Task states/tags | Direct todo/done classes from the declared before/after-bar partition, including custom states and fast-key suffixes; priority, progress-cookie, timestamp and tag semantics retained |
| Navigation | Owned TOC transport bound to the same heading records, respecting enable/depth; final catalogue/restoreContents owns final destination IDs |
| Drawers/planning | Existing preserved fragments restored once in their intended section, without source delimiter duplication |
| Lists | ul/ol/li and dl/dt/dd with correct whole-item grouping, ordering and nesting; distinguish terms from descriptions |
| Checkboxes | Existing owned square indicators and separator, checked X/x, unchecked space, partial slash/dash; no interactive source controls |
| Inline content | Text, emphasis, underline, strikeout, sub/superscript, entities, links, images and literal code retain meaning; smart dashes remain outside literal spans only |
| Containers | Table cells/header rows, outer nested quote/verse/centre/named blocks and whitespace survive; no duplicate inner target for an outer annotation block |
| Footnotes | Direct reference anchors with footnote-ref/doc-noteref semantics; one section.footnotes with ordered definitions and footnote-back/doc-backlink links, including repeated reference destinations |
| Source IDs/links | Existing explicit IDs, CUSTOM_ID/ID, unambiguous heading searches and relative links retain destinations through the current resolver; do not pretty-rewrite source filenames |
| Raw source HTML | Passes the same sanitizer and grant rules; no trusted classes/attributes are granted merely because source resembles worker output |

- Heading IDs :: Preserve explicit identifiers and the established automatic-ID
  semantics used by local fragment links; normalize generated IDs before
  catalogue allocation. Native writer slugs are not permission to break existing
  links. Heading-based Org searches continue through the current title catalogue.
- Owned transport :: Mirror validated code/heading/TOC records currently supplied
  by =fidelity.lua= and =page.html5=. Reuse Go validators/restoration; no broadening
  of trusted source HTML or generic data-attribute allowlists.
- Inline fidelity :: Port the small Lua presentation responsibilities needed for
  Org into the adapter. Keep Lua for remaining Pandoc readers; do not run a new
  standalone Lua interpreter or send individual Org blocks back to Pandoc.

*** Observed rendering differences and adapter handling
:PROPERTIES:
:CUSTOM_ID: observed-html-deltas
:END:

The [[file:assessment.org][conversion assessment]] identified *footnote structure and checkbox
differences*. The following footnote example was reproduced on 20 September
2026 with the pinned go-org revision and Pandoc's =org= reader/=html5= writer,
without application filters. It shows *raw converter output*, not a completed
production adapter. Only HTML indentation and line wrapping are adjusted below.

Identical Org input:

#+BEGIN_SRC org
A sentence.[fn:note]

[fn:note] A comment.
#+END_SRC

go-org output:

#+BEGIN_SRC html
<p>A sentence.<sup class="footnote-reference"><a id="footnote-reference-1" href="#footnote-1">1</a></sup></p>
<div class="footnotes">
  <hr class="footnotes-separatator"/>
  <div class="footnote-definitions">
    <div class="footnote-definition">
      <sup id="footnote-1"><a href="#footnote-reference-1">1</a></sup>
      <div class="footnote-body">
        <p>A comment.</p>
      </div>
    </div>
  </div>
</div>
#+END_SRC

Pandoc output:

#+BEGIN_SRC html
<p>A sentence.<a href="#fn1" class="footnote-ref" id="fnref1" role="doc-noteref"><sup>1</sup></a></p>
<section id="footnotes" class="footnotes footnotes-end-of-document" role="doc-endnotes">
  <hr />
  <ol>
    <li id="fn1"><p>A comment.<a href="#fnref1" class="footnote-back" role="doc-backlink">↩︎</a></p></li>
  </ol>
</section>
#+END_SRC

| Observed difference | Adapter handling and reason |
|---------------------+-----------------------------|
| go-org nests the reference anchor inside sup; Pandoc nests sup inside the anchor | Emit the direct anchor expected by existing footnote identification |
| go-org puts footnote-reference on sup and omits doc-noteref; Pandoc marks the anchor with footnote-ref and doc-noteref | Attach the existing semantic class and role to the anchor for server-side block and footnote verification |
| go-org uses nested div elements for definitions; Pandoc uses section/ol/li | Emit one endnotes section with ordered definitions, preserving every paragraph and note association |
| go-org uses the definition number as the backlink; Pandoc appends a footnote-back/doc-backlink anchor | Emit the established backlink structure for navigation and existing footnote processing |
| Generated reference and definition ID spellings differ | Preserve unique, consistent destinations; spelling alone does not require renaming to Pandoc's fn/fnref convention |

These changes belong in the *Go writer adapter or HTML normalization*, before
server-side verification and browser presentation. They do not require changing
go-org's footnote grammar. Literal class names above, including go-org's
=footnotes-separatator= spelling, are retained as observed output.

Other *observed compatibility cases* from the assessment remain part of the
same adapter work:

- Checkboxes :: The raw go-org probe recognized =[X]= but left =[x]= and =[/]=
  as literal text. Existing preservation and adapter output must retain the
  *checked, unchecked and partial indicators*, their spacing and whole-item
  annotation targets; changing CSS alone cannot supply missing semantics.
- Generated references :: Standalone probe references were parsed as
  definitions. The *owned inline predecessor* described below preserves their
  reference role; it is removed before publication.
- Definition descriptions :: Two short descriptions in the long corpus lost
  annotation targets. Their *whole-block correspondence* needs the focused
  compatibility cases already defined; target-count equality alone is not proof.

Verification remains [[#rt-011-2][RT011.2 - Semantic HTML]],
[[#rt-011-4][RT011.4 - Block placement]] and
[[#rt-011-5][RT011.5 - Footnote lifecycle]]. These examples explain the existing
contract without adding a new converter path or changing source syntax.

** Intermediary annotation compatibility

- Preserve *MarkBlocks and current structural matching*. The adapter consumes
  their intermediary document, not positions inferred from newly rendered prose.
- Standalone generated footnote references need an invisible inline predecessor
  so go-org does not parse them as definitions. At the converter-input boundary,
  prefix *only the current generated marker references* with a nonce-owned empty
  inline HTML comment. Restrict this to the marker set supplied by the existing
  probe construction; do not match arbitrary author text by a public prefix alone.
- Strip that generated predecessor before publication. Ordinary authored
  definitions and references are unchanged. A missing or duplicate probe marker
  still fails the current verification rather than being guessed into place.
- Normalize native footnote containers/references before the existing label and
  block-association routines. After-block references remain outside source
  delimiters and repeat saves extend the one existing reference paragraph.
- Resolve short-definition and additional-target discrepancies by comparing each
  synthetic source endpoint with its whole rendered block. If normalization
  cannot make the current proof hold, withhold the target; do not relax the proof.
  A required supported block remaining unavailable is a delivery defect.
- Verification :: [[#rt-011-4][RT011.4 - Block placement]] and
  [[#rt-011-5][RT011.5 - Footnote lifecycle]]. No persisted block-ID migration.

** Highlighting and literal transport

- Use the native [[https://github.com/alecthomas/chroma][Chroma Go highlighter]] for Org code via the
  writer callback/owned literal-record path. It avoids one Pandoc subprocess per
  code block. Pin a compatible reviewed release and its required dependencies
  during delivery; retain its MIT notice and run the vulnerability gate.
- Convert tokens to the existing semantic highlight classes/palette, or add a
  narrowly mapped set of owned classes. Use class-based CSS, not inline styles
  or remote themes. Preserve current light/dark colours and fixed-width font.
- Preserve the literal-value record as the authority for copying; verify that
  token concatenation equals it. If a lexer cannot handle a language, render
  escaped plaintext with the current bounded diagnostic. No source-selected
  external syntax definitions or code execution.
- Chroma version selection and exact token-to-class table are routine dependency/
  adapter details; replacing the highlighting architecture is not.
- Verification :: [[#rt-011-3][RT011.3 - Literal code]] and [[#ut-011-1][UT011.1 - Reader review]].

** Performance comparison method
:PROPERTIES:
:CUSTOM_ID: performance-method
:END:

- Baseline :: Build =96a8a2c=, the recorded fifteen-second-grace version, in a
  temporary archive; candidate is the release-ready W011 branch. Record complete
  revisions and toolchain versions. Do not modify the live service.
- Corpus :: Freeze three local copies: the authorized approximately 532 kB long
  Org document, =docs/work.org=, and =specs/009-reader-annotation-ux/spec.org=.
  Record sizes/hashes and use the exact same bytes for both builds. If the private
  corpus is unavailable, record the benchmark unavailable; do not claim a
  substitute proves its numeric target.
- Operations :: Uncached page GET, add-and-refresh two-paragraph UTF-8 annotation,
  and CLI file conversion with browser opening captured. Reset disposable source
  copies and use fresh capability/filename contexts between runs. Include every
  pipeline pass, highlighting and final page generation; exclude build/startup
  and browser launch time. Missing local link targets are not traversal timings.
- Sampling :: One warm-up then five measured sequential runs per operation/build/
  document; alternate build order, same machine, no parallel benchmarks. Record
  median/range and conversion-stage counts as diagnostic evidence.
- Correctness :: Confirm published content and source-preserving annotation
  outcome for each run. Semantic regressions invalidate a speed claim.
- Target :: Large-corpus uncached GET median at most one fifth of baseline;
  smaller GET medians no worse. The research's 0.74-second result motivates
  this margin but is not a universal time guarantee or replacement for the
  [[#ot-011-1][release benchmark]]. POST/CLI measurements explain user-visible effects.

** Failure behaviour and security impact

- Trust boundary :: The worker receives only *already-authorized bounded bytes*.
  It has no API for fetching resources, reading includes or writing annotations.
  Process separation is a lifetime/failure boundary, not an OS sandbox claim.
- Access :: Disable go-org file callbacks and native expansion; leave all link
  authorization, source root checks, script removal and media policy in the
  existing owning components. No new HTTP route or remote listener.
- Data :: Intermediaries and outputs stay in existing private session storage or
  pipes. No source content, footnote text or capabilities in logs. No migration,
  persistent parser cache or annotation history is introduced.
- Failure :: Preserve the original cause internally but report a bounded safe
  operation/category. CLI errors identify Org conversion; HTTP keeps existing
  status/envelope mapping. Parent never accepts output from a failed worker.
- Recovery :: Existing source is unchanged by a failed render/proof. Existing
  autosave recovery owns browser drafts. Do not change the timing or modal UX
  to disguise converter failures.
- Tradeoff :: The explicit native-memory accounting in [[#worker-contract][the worker contract]]
  differs from Pandoc's runtime heap mechanism. Verify its failure path and
  measure peak memory; do not introduce privileged OS controls or misrepresent
  it as a portable hard resident-memory limit.

** Routine details left to implementation

- Cohesive function/file names, writer-hook versus DOM-normalization placement,
  synthetic fixture organization and compatible Chroma version selection.
- No change to converter choice, pass count, source writer, proof strength,
  public settings, data format or the stated worker lifetime/resource contract.
