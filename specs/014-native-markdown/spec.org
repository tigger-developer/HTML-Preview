* Synopsis
:PROPERTIES:
:CUSTOM_ID: summary
:END:

** Outcome

- *Markdown previews and annotations* use bundled Go conversion, removing the
  external converter requirement for the native reading workflow.

** Before

- *Markdown conversion* invokes Pandoc, including intermediary annotation passes.
- *Startup and format discovery* require Pandoc even for native Org inputs.
- *Raw HTML in Markdown* can reach the passive-content sanitizer.

** After

- *Markdown* uses pinned Goldmark with the existing reading and annotation interface.
- *Uncached Markdown previews and annotation saves have lower median latency*
  than the pre-migration master baseline on the same machine and corpus.
- *Recognized embedded HTML is omitted*, with a CLI notice and preview banner.
- *Markdown and Org are first-class native formats* and require *no Pandoc installation*.
- *Pandoc becomes an optional dependency* for additional formats such as DOCX,
  ODT and EPUB; it is required only when those readers are selected.
- *Annotation creation, editing and deletion* retain native footnotes and guarded writes.

** Changes

- *Native conversion and HTML adaptation* replace the Markdown converter path.
- *Dependency discovery becomes conditional*; packaging describes native and optional readers.
- *The native dialect is a documented subset*. Pandoc-only syntax is not emulated;
  additional constructs can be considered in later changes.
- *Specialist Markdown dialects retain their optional Pandoc readers*, with the same
  HTML omission policy; ordinary Markdown never falls back to them.

** Unchanged

- *Original files remain unchanged during reading*; authorized service annotations can write.
- *Org conversion, passive standalone HTML, resource policy and localhost grants* remain.
- *Browser annotation behaviour and source-bound block proof* remain the compatibility boundary.
- *Definition stays on master*. No implementation or installation occurs in this phase.

** Edge cases
:PROPERTIES:
:CUSTOM_ID: synopsis-edge-cases
:END:

- *HTML examples inside code remain visible* and do not trigger HTML warnings.
- *Repeated footnote references* resolve to the same editable note without duplicate records.
- *Unsupported explicit Markdown options fail clearly*. Specialist Pandoc dialects
  remain optional readers; they do not silently replace the native converter.
- *Unverified insertion targets remain inactive*; conversion errors publish no partial page.
- *Missing optional converters* affect their requested formats, not native previews.

** Decisions

- *Goldmark v1.8.6* is the selected, pinned library; no new runtime or browser stack.
- *Server-side adaptation* preserves the tested HTML contract before annotation proof.
- *The existing intermediary workflow remains*; reducing conversion passes is separate work.

** Next step

- *Delivery on a separate feature branch*, beginning with the regression-test package.

* Context
:PROPERTIES:
:CUSTOM_ID: context
:END:

** Problem

- *External Markdown conversion adds latency* to opening and refreshing local documents.
  The native Org migration demonstrates the established integration pattern; Markdown
  still incurs external conversion and discovery work.
- *A similar-looking page is insufficient*: the annotation interface depends on
  exact block, reference and endnote relationships in rendered HTML.

** Outcome

- *Native Markdown conversion preserves the supported reading and editing workflow*
  and reduces measured uncached preview latency against the current master baseline.

** Scope

- Included :: Markdown conversion, metadata, navigation, highlighting, annotation
  HTML compatibility, HTML omission notices and *conditional converter dependencies*.
- Excluded :: Org parser replacement, new annotation storage, source-offset mapping,
  conversion-pass reduction, worker pooling, remote services and new browser tooling.
- Preserved :: Original source identity, relative links, root authorization,
  passive resource controls, folding defaults, fonts, copying and service-only writes.

** Constraints and dependencies
:PROPERTIES:
:CUSTOM_ID: constraints-and-dependencies
:END:

- *Goldmark is pinned to v1.8.6* in =go.mod= and =go.sum=. Its MIT licence must
  accompany distribution; the project remains Apache-2.0.
- *No source documents are migrated*. Conversion markers and normalized HTML are private
  intermediaries; the existing annotation writer continues to own file changes.
- *Personal documents may be tested only in disposable local copies*, never committed,
  uploaded to an auditor or copied into fixtures. Retained fixtures are synthetic.
- *No browser automation is added*. Rendered HTML and HTTP contracts use Go tests;
  interaction, layout and perceived latency use human validation.
- *Definition remains on master*. Delivery requires explicit sign-off and its branch
  choice at admission; this specification does not create a branch or change a service.

** Research evidence

- Method :: Local converter-only comparison on 20 September 2026; seven timed runs
  after one warm-up. Native calls were in-process; Pandoc included subprocess startup.
  *These are not end-to-end application timings* and exclude the compatibility adapter.
- Corpus :: Repository README, 18,120 bytes; synthetic 1,200-section Markdown,
  180,090 bytes. No private text is needed to reproduce the synthetic comparison.
- Results :: Goldmark v1 medians were *0.244 ms and 5.471 ms* respectively; Pandoc
  medians were *253.870 ms and 412.569 ms*. Goldmark v2 medians were 0.183 ms and
  5.468 ms; gomarkdown medians were 0.157 ms and 5.322 ms.
- Fidelity :: Goldmark retained multi-paragraph footnotes, repeated-reference backlinks,
  pipe tables, definition lists and checked task inputs. Additional adaptation is
  needed for metadata, heading identifiers, partial checkboxes and the application's
  footnote HTML contract. Several Pandoc-only constructs rendered literally.
- Selection :: *The v1 pin keeps the accepted library baseline*. Comparable parser
  speed alone does not establish annotation fidelity or justify switching candidates.
- Compared modules :: =github.com/yuin/goldmark/v2 v2.1.5= and
  =github.com/gomarkdown/markdown v0.0.0-20260917010721-cc30ffac3c05= were the
  alternative pins; neither is added to the application by this change.
- Sources :: [[https://pkg.go.dev/github.com/yuin/goldmark@v1.8.6][Pinned Goldmark documentation]];
  [[https://github.com/yuin/goldmark/tree/v1.8.6][Goldmark v1.8.6 source and MIT licence]].
  The module declares Go 1.22 and no external requirements. Delivery checks the
  resolved graph, binary size and current advisories rather than assuming safety.

** Decisions

- *Keep the intermediary annotation workflow*. Normalize converter output before
  source-proof comparisons; do not replace established block mapping with cursor offsets.
- *Omit raw HTML in Markdown*. Detection is a parser classification heuristic,
  not a claim that every angle-bracket sequence is HTML or that all HTML is malicious.
- *Keep native HTML separate*. Its passive authored presentation is unchanged.
- *Adopt the native subset*, preserving the authored Markdown used by the project
  and the SDLC authoring standard. *Do not emulate fenced divs or the full Pandoc dialect*.
  Additions require a demonstrated need and a later scoped change.
- *Preserve the shared browser annotation contract*. Converter differences belong
  in the server-side adapter. UI changes are limited to presentation/refresh of the
  new warning if necessary; annotation selectors and editing semantics remain unchanged.

* Solution Design
:PROPERTIES:
:CUSTOM_ID: solution-design
:END:

** Architecture context

- Ownership :: *The library parses Markdown; the application owns presentation,
  resources, annotations and publication*. No parser fork or broad extension framework
  is proposed. A necessary parser change requires a separately justified decision.
- Integration :: Extend the same-executable native worker with a Markdown dispatch.
  Extract only its genuinely shared bounds/protocol supervision; keep Org and Markdown
  conversion code distinct. The public application interface gains no converter toggle.

** Native dialect and selector contract
:PROPERTIES:
:CUSTOM_ID: dialect
:END:

- Core :: *CommonMark plus the named Goldmark extensions*: Table, Strikethrough,
  TaskList, DefinitionList, Footnote and Typographer, with application-owned heading
  identifiers and heading attributes. Strikeout follows Goldmark's one- or two-tilde
  delimiters; Pandoc-style subscript is not supported. This is a documented dialect
  difference, not a reason to fork its inline parser. YAML metadata and existing
  partial-checkbox display remain application responsibilities.
- Supported authoring :: ATX and Setext headings, paragraphs, thematic breaks,
  emphasis/strong text, escaped punctuation, links/images and reference links,
  angle-bracket URI/email autolinks, ordered/unordered nested lists, task lists,
  blockquotes, pipe tables, inline code and fenced/indented code. Bare URLs are
  not newly autolinked. Preserve footnotes, definition lists and smart punctuation.
- Line breaks :: *Keep soft line breaks within paragraphs*. A single source newline
  is ordinary whitespace; two trailing spaces or a backslash before the newline
  create a hard break. This matches the bundled reader's =-hard_line_breaks=
  setting and CommonMark, preserving wrapped prose without a new rendering option.
- Native selection :: =.md=, =.markdown=, =.mdown=, =.mkd= and =.mkdn=, case-insensitively,
  select =markdown=. Explicit =--from=markdown= and =htmlpreview-format=markdown=
  use the *same native dialect*, regardless of filename or transport.
- Native qualifiers :: Only =+smart=, =-smart= and =-raw_html= are accepted.
  Smart punctuation is on by default; repeated smart qualifiers use the last value.
  =-raw_html= confirms the fixed omission policy. Other qualifiers, including
  =+raw_html=, fail with the unsupported name and supported choices: CLI exit 2 or
  HTTP 400 for an explicit link selector. Preserve the existing 256-character ASCII
  grammar limit. Do not pass native qualifiers to Pandoc for validation.
- Specialist dialects :: Existing named Pandoc readers such as =gfm=, =commonmark=,
  =commonmark_x= and =markdown_strict= retain their explicit optional-Pandoc route.
  Their suffix aliases, installed-reader validation and annotation eligibility stay
  unchanged. They are *not promised native equivalents* and never become an automatic
  fallback for ordinary Markdown. Apply the HTML omission policy to Markdown-family
  readers too, by removing raw HTML AST nodes in the existing Pandoc filter and
  returning the same bounded warning flag; generated transport is added afterwards.
- Unsupported native constructs :: Percent title blocks, fenced divs, bracketed spans,
  inline/link/code attributes, inline notes, fancy/example lists, grid/simple/multiline
  tables, captions, implicit image figures, line blocks, citations, math and superscript/subscript extensions
  are *not emulated*. Ordinary parsing renders their characters under the native
  grammar; it may interpret ordinary emphasis or links within them. No promise of
  byte-for-byte literal display or semantic equivalence is made for this syntax.
  An image-only paragraph retains its image and alternative text without synthesizing
  a =figure= or =figcaption=; image authorization and alternative text are unchanged.
- Diagnostics :: Warn for parser-recognized omitted HTML and reject unsupported
  explicit qualifiers. *No second parser is introduced to guess every unsupported
  Pandoc construct*. The format guide lists the retired native extensions and the
  optional specialist-reader route. Requests to extend the native subset are later work.
- Source fidelity :: Unsupported syntax never authorizes source rewriting. The original
  source view remains exact and source-bound annotation proof remains required.

** Conversion flow and shared responsibilities

1. *Authorize and snapshot* through the existing file/service path. Preserve original
   bytes for plaintext display, copying and annotation revision checks.
2. *Extract metadata and prepare existing annotation intermediaries*. Use the existing
   YAML dependency with bounded scalar/sequence/map handling; never execute metadata.
   Preserve the existing Markdown metadata display described below.
3. *Convert in the bounded worker* with Goldmark and application-owned render hooks.
   Code highlighting reuses bundled Chroma and the current literal-copy records.
4. *Normalize HTML before proof*: section structure, heading catalogue, TOC and endnotes
   must satisfy the same contract for base, projected-note and block-probe conversions.
5. *Apply existing sanitizer and resource/reference rewriting*. Private marker ownership
   remains checked; source HTML cannot bypass the sanitizer or introduce owned attributes.
6. *Publish the existing page shell and annotation data*. Warnings are shell content,
   outside =hp-document= and its canonical text. Only authorized annotation operations
   write the source or its established sidecar.

** HTML compatibility contract
:PROPERTIES:
:CUSTOM_ID: html-contract
:END:

- Footnotes :: Normalize Goldmark's reference wrapper and endnote container before
  =finalizeVirtualNotes= and block proof. Keep source-label associations independent of
  displayed numbers. *One stored note can have several references and backlinks*.
- Headings :: Supply Pandoc-compatible original heading IDs to the existing catalogue
  and section wrappers,
  including duplicate handling, explicit IDs and Unicode fragments. Generate TOC from
  the same catalogue; do not independently invent navigation IDs in two components.
  The compatibility generator lowercases visible heading text, changes whitespace
  to hyphens, retains letters, numbers, underscores, hyphens and periods, and removes
  leading characters before the first letter; use =section= if empty. Preserve Unicode
  letters. Thus =123 Héllo world= yields =héllo-world=, not Goldmark's =123-hllo-world=.
  Use existing final duplicate-ID allocation after explicit ID handling.
- Lists :: Preserve semantic =li=, =dt= and =dd= relationships. Annotation attributes
  belong to the *nearest eligible block the browser actually selects*, including
  paragraphs introduced inside loose items. Reuse checkbox normalization.
- Code :: Render escaped text with the existing highlight classes and original-copy
  transport. Unknown languages stay literal. Code is never executed.
- Metadata :: Preserve the *current Markdown path*, not a new Org-style metadata UI.
  =assets/pandoc/fidelity.lua= currently prepends present title, author, date and lang
  as paragraphs in that order when a body exists. Metadata-only documents use a
  structured frontmatter definition list. Keep this display and the existing filename
  page-title fallback; do not silently claim that Markdown already uses Org's title,
  subtitle and frontmatter panel. Plaintext retains every source field. Metadata
  strings are escaped text, never an alternate raw-HTML route.
- YAML framing :: Recognize a leading =---= metadata block, after an optional UTF-8
  BOM, terminated by =---= or =...=. Invalid YAML or a non-mapping metadata document
  returns a conversion error; an unclosed delimiter sequence follows ordinary Markdown
  parsing. Reuse the YAML library, reject duplicate keys, cap nesting at 64 and bound
  all expanded values by the conversion budget. Alias cycles and over-budget expansion
  are errors. Do not evaluate tags or perform external resolution.

Observed footnote rendering delta:

#+BEGIN_SRC html
<!-- Goldmark output -->
<sup id="fnref:1"><a href="#fn:1" class="footnote-ref" role="doc-noteref">1</a></sup>
<div class="footnotes" role="doc-endnotes">...</div>
<!-- Application-compatible output -->
<a href="#fn1" class="footnote-ref" id="fnref1" role="doc-noteref"><sup>1</sup></a>
<section id="footnotes" class="footnotes footnotes-end-of-document" role="doc-endnotes">...</section>
#+END_SRC

- Backlinks :: Goldmark's =footnote-backref= becomes =footnote-back= with
  =role="doc-backlink"=. Every href resolves to a unique reference ID. The example
  shows one occurrence; repeated occurrences receive distinct IDs.
- Rationale :: *Server-side normalization preserves the tested browser contract*
  and the current proof algorithm. Replacing browser selectors and mapping in the same
  change would add an unnecessary second migration.
- Browser change boundary :: *Do not add format branches to annotation selectors,
  canonical-text mapping, folding or footnote editing*. Reuse their existing elements,
  attributes and relationships for both Org and Markdown. If this cannot be achieved,
  report the concrete incompatibility before changing the shared browser contract.
  A narrowly scoped warning-refresh update is allowed only if existing replaceable
  page regions cannot carry the banner; it receives Org preservation coverage too.
- Verification :: [[#rt-014-2][RT014.2 - Semantic render compatibility]],
  [[#rt-014-4][RT014.4 - Clickable block creation]] and
  [[#rt-014-5][RT014.5 - Footnote lifecycle]] assert the delivered HTML explicitly.

** Raw HTML and warning contract
:PROPERTIES:
:CUSTOM_ID: html-warning
:END:

- Detection :: *Use Goldmark raw-HTML nodes*, not an angle-bracket regular expression.
  Classify inline raw nodes and raw block nodes in authored Markdown. The parser's
  classification is intentionally heuristic; malformed or ambiguous text follows
  Markdown parsing. It is not a general HTML validator.
- Rendering :: *Do not enable unsafe HTML rendering*. Drop recognized inline HTML
  nodes but retain adjacent parsed text; omit complete raw block payloads. Thus an
  inline tag pair can leave its plain text, while a block HTML region can lose its
  contents. Literal code remains escaped and readable.
- Comments :: Authored HTML comments count as recognized omitted HTML. Application-owned
  legacy records, when recognized by the existing annotation parser, are extracted
  before detection; do not invent a second legacy-record parser or warn about generated
  conversion transport. An arbitrary comment is not a trusted record.
- CLI :: Emit *one stderr notice per affected document per explicit invocation* after
  successful rendering, including when the service supplied the page. Extend the
  existing registration response with a bounded notice if needed; no extra fetch loop.
- Browser :: Place one compact, non-modal warning *below the info bar and above
  document content*, outside annotation targets. Include text, not colour alone:
  =Embedded HTML omitted: This Markdown source contains HTML that is not rendered in this preview. Some content may be missing.=
- Region ownership :: Prefer the existing replaceable =hp-frontmatter= region as a
  host for the banner, outside =hp-header= copy controls and =hp-document=. Keep it
  visually separate from metadata. This lets the existing region-swap lifecycle
  refresh warnings without altering annotation selection or canonical text.
- Refresh :: Cache warnings with the rendered source revision; union repeated-pass
  detection into a single flag. Browser-followed links show their own warning without
  requiring a CLI. Re-rendering updates the banner; SSE events do not repeatedly log it.
- Safety :: Never include omitted source snippets in logs or warnings. Plaintext view
  remains a literal source view and may show the ignored markup as escaped text.

** Dependency discovery and packaging

- Native catalogue :: *Org, Markdown, code/plaintext and passive HTML are available
  without Pandoc*. Keep document suffix precedence and original source kinds. Chroma
  supplies native language support; stop requiring Pandoc's language catalogue for wrappers.
- Optional catalogue :: Resolve and validate Pandoc only for a selected non-native
  reader or full reader listing. Existing reader extension validation still applies
  on that optional route. Cache successful service discovery for that service lifetime;
  a failed request must not disable native routes.
- Listing :: =--list-input-formats= lists native reader names even when Pandoc is absent.
  When present, merge its validated catalogue without duplicate names. Native code/text
  routing remains suffix-based, not invented Pandoc reader names. Report operational
  discovery errors rather than publishing a misleading successful complete list.
- Missing dependency :: A selected optional reader fails with an actionable dependency
  diagnostic and existing error status. *No automatic Markdown fallback to Pandoc* on
  conversion failure or unrecognized syntax.
- Installation :: Remove unconditional Pandoc prerequisites from installation and service
  generation. Present *Markdown and Org as first-class native formats* in dependency
  guidance, with *Pandoc optional for additional formats such as DOCX, ODT and EPUB*.
  Retain documented optional installation for office/specialist readers.
  Do not remove or alter another installed converter, package or service.
- Verification :: [[#rt-014-6][RT014.6 - Conditional dependency behaviour]] and
  [[#ot-014-2][OT014.2 - Packaging and documentation]].

** Failure and security impact

- Process bounds :: Preserve *one disposable same-executable worker per conversion*,
  stdin-only authorized bytes, existing cancellation/reaping and session accounting.
  Keep the 100 MiB protocol ceiling, 50 MiB output ceiling and smaller remaining session
  limits. Retain the 512 MiB runtime-memory target and 10 ms accounted-memory check;
  this is not a hard operating-system RSS limit. No source paths are passed to the parser.
- Untrusted inputs :: *Markdown, metadata, links and generated HTML remain untrusted*.
  No includes, external fetches, executable plugins, scripts or source-controlled flags.
  The existing sanitizer, CSP, rooted resource checks and capability validation remain.
- Mutation :: *The converter owns no persistent writes*. Existing revision checks,
  atomic replacement, symlink/hardlink rules, idempotence and authorization guard notes.
  Converter errors do not become annotation success responses.
- Supply chain :: Add only the pinned Goldmark module and its licence. Check the actual
  resolved graph with the existing vulnerability target; no unversioned plugins.
- Data :: Keep private documents, document bodies and service tokens out of committed
  test evidence and diagnostics. Research metrics do not require source disclosure.
- Verification :: [[#rt-014-7][RT014.7 - Failure and trust boundaries]] and
  [[#ot-014-2][OT014.2 - Packaging and documentation]].
