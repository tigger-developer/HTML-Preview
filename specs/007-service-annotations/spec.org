* Context
:PROPERTIES:
:CUSTOM_ID: context
:END:

** Problem

*Comments made while reading need durable context and attribution*. Browser-only
state loses them, while file-mode output has no authorized local write service.
Sources can change in an external editor during a review, so *autosave must
refresh and verify the current source*, rather than write against an old page.

** Outcome

The reader can *add, revisit and understand attributed comments* without a Save
button, manual page reload or silent source replacement. Ambiguous anchors and
failed persistence remain visible, with the user's current text recoverable.

** Scope

*** In scope

- *Whole-document and selected-passage comments* in W007 service previews.
- *Embedded versioned records*, read-only sidecars, autosaved composer revisions,
  automatic refresh, append-only closed comments, author and UTC timestamp.
- *Strict write admission, concurrency, interruption recovery and resource limits*.
- *Persistent browser regressions plus extensive human UX qualification*.

*** Out of scope

- *Editing/deleting closed comments*, threaded discussions, moderation, accounts,
  collaboration servers, rich-text comments, attachment uploads and PDF regions.
- *File-mode annotation*, a generic file editor, automatic source reformatting,
  automatic history compaction or external-editor synchronization.
- *Exodan deployment*, remote serving, database introduction and browser extensions.

*** Unchanged

*Reading alone does not write source or sidecar files*. W006's loopback/root
rules, source confinement, asset restrictions, private registration socket and
file fallback remain authoritative except for the narrow extensions named below.

W007 *supersedes the Vision's live-reload exclusion for service previews* with
bounded polling refresh. It supersedes W006's live-reload exclusion only to that
extent; recursive filesystem watchers remain excluded. W007 also supersedes
W006's persistent-browser-harness exclusion and the Architecture's unselected
browser-harness baseline with the narrowly scoped Go/browser regression runner
below. These exceptions support the explicitly requested refresh and JavaScript
UX verification; the earlier documents remain historical baseline evidence.

* Test Definitions
:PROPERTIES:
:CUSTOM_ID: test-definitions
:END:

*No implementation tests have run during definition*. All delivery results start
PENDING. Each regression first demonstrates its intended failure on the
*delivered W006 baseline*; absent W006 infrastructure is not valid RED evidence.

Go regressions join =make test=. Browser regressions join =make test-browser=:
a Go test runner serves isolated fixtures and the real packaged browser modules
on *127.0.0.1*, opens the system default browser, and receives native JavaScript
assertion results using a one-run random capability. It exits non-zero on failed
assertion or a *120-second timeout*. It accepts no public listener setting,
stores fixtures/results only in its OS temporary directory and shuts down its
own listener on exit. No metered provider or hosted service is involved.
Browser RTs use controlled clocks/network adapters at *owned module boundaries*;
they do not replace human UT, source-text greps do not prove interaction, and
normal verification includes both commands.

*Runner availability is required for browser qualification*: absent browser,
display or working WSL-to-Windows handoff causes a diagnostic and non-zero exit,
never a skip counted as PASS. Headless CI runs =make test= and reports browser
coverage as unexecuted; =make test-browser= is not added to headless CI. Delivery
requires its actual results on the supported native browser matrix before the
implementation gate. A CLI-launched browser tab may remain after the test result;
the page shows its result and tells the human to close that tab. No browser process
is killed and no unrelated tabs are closed. The runner stops its own server.

*A browser run proves only its actual browser engine and version*. Record these
with OS and candidate revision; the system default is not assumed to be Safari,
Firefox or Edge. Required matrix runs use hosts whose default browser matches
the named target, without the runner changing defaults. No automatic retry or
flake quarantine is allowed: retain the first failure, diagnose, then rerun only
after a documented test/product/environment correction. Timing assertions use
controlled module clocks; native timing/usability remains human qualification.

For every UT below, record *candidate revision, OS/browser/version, steps,
observations, result and human reviewer*. The required matrix is
*macOS/Safari, Linux/Firefox, WSL1/Windows Edge and WSL2/Windows Edge*.
UT007.6 additionally records VoiceOver/Safari and NVDA/Edge keyboard/screen-reader
results. Missing platform or accessibility evidence remains PENDING, not inferred
from another platform. Use synthetic documents, not personal reviews.

* Edge Cases
:PROPERTIES:
:CUSTOM_ID: edge-cases
:END:

** External editor changes a passage during typing

- Condition :: A *base-source change arrives before or during autosave*.
- Required behaviour :: Refresh automatically while keeping the composer. Rebase
  a uniquely matching target; otherwise pause with a visible unresolved reason.
  Every write still checks current bytes; never restore an old source snapshot.
- Covered by :: [[#ac-007-24][AC007.24 - Automatic source refresh]], [[#rt-007-11][RT007.11 - Refresh and autosave coordination]], [[#ut-007-9][UT007.9 - Live refresh while annotating]].

** Acknowledgement is lost or an older response arrives late

- Condition :: A *durable append may have succeeded while its response failed*.
- Required behaviour :: Retry the same operation ID and exact payload; deduplicate
  before the stale-revision check. Only the matching client revision is acknowledged.
- Covered by :: [[#ac-007-9][AC007.9 - Ordered and idempotent writes]], [[#rt-007-5][RT007.5 - Append-only autosave protocol]], [[#ut-007-4][UT007.4 - Failure and navigation recovery]].

** An append is interrupted or a human moves the owned tail

- Condition :: A *partial/malformed owned frame or non-tail annotation store* exists.
- Required behaviour :: Keep bytes and all valid preceding events; explain the
  malformed location, suppress owned transport from the body and disable new
  writes. No automatic truncation, repair, migration or record deletion occurs.
- Covered by :: [[#ac-007-11][AC007.11 - Conflicts and interrupted writes]], [[#ac-007-17][AC007.17 - Readable stored metadata]], [[#rt-007-6][RT007.6 - Conflicts and durability faults]].

** Permissions or source location change

- Condition :: Source becomes writable/read-only, aliases change, or source moves.
- Required behaviour :: Read both stores and choose the destination afresh at the
  first event of a composer, pinning it for that composer. Permission loss during
  composition pauses saving. Embedded records travel with the source; sidecars
  must be moved alongside it using the documented full-basename convention.
- Covered by :: [[#ac-007-6][AC007.6 - Read-only sidecar]], [[#ac-007-22][AC007.22 - Document and sidecar identity]], [[#rt-007-4][RT007.4 - Sidecars and storage transitions]], [[#ut-007-2][UT007.2 - Read-only and sidecar workflow]].

** Clearing an autosaved draft or closing the browser

- Condition :: A user clears text after a non-empty snapshot was saved, or the
  browser/service ends without a successful final flush.
- Required behaviour :: Never delete the stored snapshot. Empty drafts cannot
  overwrite it; explain that the last autosaved text remains and allow restoring
  it or writing a correction. Forced termination may lose *unacknowledged*
  keystrokes; the last acknowledged draft is recovered read-only.
- Covered by :: [[#ac-007-7][AC007.7 - Append-only comments]], [[#ac-007-18][AC007.18 - Draft recovery and navigation]], [[#ut-007-3][UT007.3 - Autosave and append-only composition]], [[#ut-007-8][UT007.8 - Service boundary and lifecycle]].

* Solution Design
:PROPERTIES:
:CUSTOM_ID: solution-design
:END:

** Architecture context

- Renderer :: Reuse the *owned Go/Pandoc pipeline* after extracting recognized
  annotation transport. Keep read rendering separate from file mutation.
- Annotation domain :: A small Go package owns *event validation, author capture,
  selector resolution, storage and write policy*. HTTP routes adapt this domain;
  the package does not depend on browser DOM, service manager or Exodan.
- Browser :: Separate *composer/autosave state, target mapping and presentation*
  from existing copying/folding code. Share narrowly defined lifecycle hooks.
  No global dirty boolean can acknowledge unrelated composers.
- Reuse assessment :: Writeback inline autosave creates on first input and uses
  a *300 ms update debounce*. Its general feedback uses two seconds. The inspected
  close path starts asynchronous flush then removes the editor; htmlpreview must
  await acknowledgement. Its excerpt restoration finds the first matching text
  node; mutable documents need the stronger selector rules below. Adopt its
  nearby save/error feedback, not SQLite review ownership, edit/delete routes,
  sentence-click takeover, automatic clipboard writes or its implementation
  structure without assessment.
- Ownership :: Prototype or reused project code is *our maintained code*.
  Restructure and test it against these contracts; no upstream/prototype exemption.

** High-level design

*** Responsibilities and reuse

- Event codec :: Own *recognition, framing, validation and projection* of the
  defined record format. Org and Markdown vary only in literal-context handling
  and frame envelopes; they share the JSON event schema and sequence rules.
- Store operation :: Own *one read/validate/append/synchronize path*, supplied
  with the selected embedded or sidecar destination. Destination selection is
  separate from writing; no duplicate autosave implementation exists per format.
- Service adapter :: Reuse *W006 admission, rooted handles and rendering*.
  Adapt validated HTTP requests to annotation operations; it owns ephemeral
  grants, composer admission and the shared polling snapshot. Durable records,
  rather than cache or browser state, remain the saved-history authority.
- Browser modules :: The *composer owns text and acknowledgement state*; target
  mapping owns canonical text/DOM positions; presentation owns controls and
  region replacement. Refresh invokes those boundaries without replacing the
  composer or duplicating copying/folding behaviour.
- Dependency direction :: The domain accepts explicit validated values and
  owned filesystem/clock/randomness operations; it does not call HTTP handlers,
  browser code or a service manager. *No database, event bus, general editor or
  synchronization framework* is needed.

*** Flow

1. CLI validates inputs/settings and *captures the display name*. It registers
   the preview through W007's private control endpoint.
2. The service renders an authorized source snapshot, strips owned storage
   transport and supplies *annotation state plus document-scoped write authority*.
3. The browser reads saved comments and opens an *explicit annotation composer*
   for the document or current text selection.
4. It autosaves serialized draft snapshots. The server *revalidates the source,
   author grant, event sequence and filesystem destination*, appends and
   synchronizes, then acknowledges that exact revision.
5. The browser *checks for source changes and refreshes automatically*. A changed
   document triggers target revalidation; dirty text is preserved.
6. Closing the composer flushes its latest text and appends a close event.
   *Reopening is read-only*; later comments add records.

*** Identity and private registration
:PROPERTIES:
:CUSTOM_ID: annotation-registration
:END:

- Resolution :: The initiating CLI trims Unicode whitespace from
  =HTMLPREVIEW_USER_DISPLAY_NAME=; empty/unset falls back to trimmed =USER=.
  Neither value means *reading without creation*. No daemon USER substitution.
- Validation :: Register =HTMLPREVIEW_USER_DISPLAY_NAME= in the *strict known
  settings set*. A non-empty resolved name must be valid UTF-8, at most *128 Unicode
  scalars and 512 bytes*, with no control characters or embedded line breaks.
  Invalid resolved values report the responsible setting and *exit 2 before
  browser opening or registration*, as other invalid settings do. They do not
  silently fall back. Missing values are valid and permit reading without creation.
- Lifetime :: *Capture the name in the registration context*, including it in the
  W006 context-equivalence key. Existing tabs/links retain their captured name;
  a new CLI invocation captures the current environment. Browser JSON cannot
  set author or timestamp.
- Extension :: Add private control =POST /v1/annotation-previews= with the W006
  preview request schema plus =display_name= (string or null). Its response has
  the same per-file preview results. Keep =POST /v1/previews= unchanged and
  *read-only*. W007 CLI tries the extension once; 404 means use the unchanged
  read-only endpoint with one annotation-unavailable notice. Other failures
  retain W006's classification. No silent protocol downgrade on malformed replies.
- Authority :: Same-UID socket checks and private runtime permissions remain.
  A display name is *a label, not proof of identity or permission*.

*** Browser HTTP interfaces
:PROPERTIES:
:CUSTOM_ID: annotation-http
:END:

- Paths :: =/_annotations/v1/<read-token>/<encoded-root-relative-document-path>=
  is the annotation state/event route. Reuse W006's canonical decoding, admission
  and path bounds. It resolves *one Org/Markdown document*, never an arbitrary
  browser-supplied disk path. Root tokens cannot collide with this reserved prefix.
- GET state :: Returns ={protocol:1, revision, source_revision, body_revision, events, storage,
  writable, reason, write_token}=. Events are the latest projected comments,
  including saved drafts and unresolved targets; tokens are omitted for
  read-only contexts. No GET creates a file or durable event. HEAD has no body.
- Write grant :: A separate *32-byte random capability* binds the canonical
  document, root/logical context, author and service instance. Return it only
  under an annotation-enabled read context and send it in
  =X-HTMLPreview-Annotation-Token=, never URLs. At most 256 active document grants;
  reuse equivalent grants, reject excess with 503 until service restart.
- POST event :: Strict JSON ={operation_id, annotation_id, composer_id, sequence,
  revision, source_revision, body_revision, kind, target, text}=. IDs are UUIDv4; kind is
  =draft= or =close=. The first accepted draft creates the annotation/composer;
  later events require its in-memory composer secret in
  =X-HTMLPreview-Composer-Token=. The browser generates this 32-byte random
  secret before the first request and retains it for identical retries and later
  events; the server stores only its digest. The secret is never written into
  the annotation file or browser persistent storage.
- Result :: 201 for a new durable event; 200 for an identical accepted retry.
  Response ={annotation_id, sequence, revision, source_revision, body_revision, stored_at, storage,
  closed}=. Unknown fields, forged author/date, malformed selectors and IDs: 400;
  authentication/origin: 403; unauthorized target: 404; revision/sequence/store
  conflict: 409; oversize/capacity: 413; per-document busy: 429; temporary service
  or filesystem failure: 503. Errors are bounded ={error:code}= JSON; browser
  maps codes to plain recovery guidance.
- Mutation boundary :: POST alone appends events. PUT/PATCH/DELETE remain 405;
  arbitrary uploads, source editing and author changes have no route. This
  *narrowly extends W006's GET/HEAD-only TCP rule*.
- Requests :: JSON <=64 KiB, comment <=4,000 Unicode scalars and 16 KiB UTF-8,
  selected exact quote <=8 KiB, prefix/suffix <=64 scalars each. Reject invalid
  UTF-8, NUL and unsupported schema values without truncating user text.
- Revision :: SHA-256 over a length-delimited tuple of *current raw source bytes
  and current sidecar bytes or an explicit absent marker*. A fresh read under
  the write lock supplies it. Body revision hashes the canonical rendered text
  defined below, excluding annotation transport and controls.
  Source revision separately hashes authored source bytes with the owned tail
  removed, so metadata or formatting changes trigger refresh even if canonical
  body text is unchanged.
  *source_revision is the optimistic write precondition*. The full revision is
  a read/refresh cursor, not a precondition: valid appended annotation events from
  another composer do not stale a request. Under the writer lock, validate the
  current stores, exact operation identity and this annotation's expected next
  sequence before appending against the current tail. Reject corrupt/replaced
  stores and conflicting event IDs; do not overwrite another composer's records.
- Composer lifecycle :: One active composer per tab, at most *64 active service
  composers*. A composer cannot change target identity, author or storage choice.
  Admission beyond 64 returns *503 composer_capacity*, preserving every active
  composer. Closing a composer releases its slot; no active composer is evicted.
  The browser retains attempted text, explains capacity and offers Retry after
  another composer closes or the service is restarted. No automatic retry loop
  is used for this named capacity error. Read state creates no composer slot.
  Explicit close seals it. After service restart no old composer secret is
  recognized; its latest draft remains a read-only recovered comment. An open
  page may retry an already committed event after restart once reauthorized,
  but cannot append further revisions to that recovered annotation.

*** Autosave and automatic refresh
:PROPERTIES:
:CUSTOM_ID: autosave-refresh
:END:

- State :: Track *local revision, acknowledged revision, in-flight snapshot,
  queued newest snapshot and error* separately per composer. Keep at most one
  request in flight per composer; coalesce intermediate unsent keystrokes.
- Scheduling :: Debounce valid non-empty text by *300 ms*; send within *two
  seconds* of continuous dirty input. Suspend submission during IME composition
  and schedule on compositionend. The initial draft follows the same rule.
- Status :: Show textual *Saving, Autosaved draft, Saved, or Not saved* beside
  the composer. Autosaved requires acknowledgement of the latest local text.
  Older replies cannot clear new dirty state. No automatic clipboard write.
- Close :: Close/Escape, another annotation and app-owned navigation *flush and
  await* the newest text then close. Clicking within the composer, changing focus
  to its controls or selecting/copying text does not implicitly close it. If the
  save fails, keep the editor and text with Retry and Copy draft controls.
  Browser chrome cannot always be intercepted; use beforeunload only while
  dirty/in-flight and flush on visibility loss as best effort, never as durable proof.
- Retry :: Network failures, *429 busy and transient 503* retry the *same operation*
  after one, two and four seconds, plus 0-250 ms per-attempt jitter to separate
  contending tabs, then stop with Not saved and Retry. The fixture runner controls
  clock/jitter for deterministic assertions. A request deadline is five seconds. Retry never
  changes the acknowledged event payload or invents a new ID for a lost response.
  New typing remains queued. The server includes =Retry-After: 1= for 429;
  the schedule honours that minimum. Named grant/composer capacity errors and
  permanent errors require visible recovery, not automatic retries. Transient
  contention alone does not require a manual save action.
- Polling :: While visible, issue state GET *once per second*, with at most one
  poll in flight. While hidden, stop periodic checks; on visibility/focus/pageshow,
  immediately check and flush pending text. Poll failure backs off to two, four,
  eight then 30 seconds; visible reconnect/status action checks immediately.
- Refresh :: A changed revision updates comments; a changed source revision fetches
  a fresh normal W006 rendered page and *replaces only its owned document/header
  and navigation regions*, never the active composer. Parse as inert content,
  use the owned initialization path and discard embedded script execution.
  Compare the rendered response's revision with current state and retry at most
  twice if the source changes during fetch. No blind location.reload.
  The owned rendered-page response carries its raw/source/body revision tuple;
  it must agree with the state response before replacement. Title, metadata and
  formatting changes refresh even when their normalized passage text is unchanged.
- State preservation :: On unchanged source revision, existing node IDs can
  restore folds. Across authored-source changes, restore heading folds only via
  the *verified explicit-ID provenance map* below. Without that evidence, use
  the format's normal fold defaults; never match a shifted ordinal or text slug.
  Drawers have no stable source IDs in W007 and return to their default folded
  state after source refresh. Preserve focus outside replaced regions; restore
  scroll by a surviving verified heading, otherwise retain bounded scroll offset.
  Keep composer text/selection and its captured original excerpt outside replaced
  nodes. If an anchor becomes unique at a new position, *rebase automatically*.
  If absent/ambiguous, pause saves and show the reason while retaining text.
- Save race :: Every POST checks *source_revision and current store validity*
  after re-reading. Annotation-only changes do not cause 409 stale_source.
  On a genuine authored-source change returning 409 stale_source,
  refresh and revalidate automatically, then submit with the new revision and a
  new operation ID *only after establishing the prior event did not commit*.
  Limit automatic rebase to two attempts per snapshot; continuing edits cause a
  visible waiting state and another attempt after a quiet poll, not a tight loop.
- Saved anchors :: An already saved draft keeps the same quote/target identity
  across refresh. Position/context evidence may be recomputed for a uniquely
  verified match. Retargeting to different text is a new annotation.
- Exposure :: Source refresh cannot widen the original root grant. Removed,
  revoked or non-regular sources disable saving and retain the draft. A changed
  document never causes the old source bytes to be written back.
- Limits :: Keep W006's conversion/cache/body limits. Polling uses a shared
  per-document state snapshot refreshed at most once per second across tabs;
  *every append still re-reads* before writing. A source state poll never performs
  Pandoc conversion if raw source and sidecar revisions are unchanged.

*** Persisted format and storage
:PROPERTIES:
:CUSTOM_ID: annotation-storage
:END:

*The semantic format is htmlpreview-annotations version 1*. A store consists
of a header frame followed by zero or more event frames, contiguous at EOF.
The first successful save appends the header and first event in one operation;
no speculative empty store is created. Each frame contains one compact JSON
object on one physical line. All strings use JSON escapes; additionally escape
=<=, =>=, =&= and hyphens in strings so Markdown comment terminators cannot occur.
No user string becomes a raw Org directive. The examples show frame envelopes;
=JSON_HEADER= and =JSON_EVENT= label the schema described immediately below.

#+begin_src org
#+begin_comment
htmlpreview-annotations:v1
JSON_HEADER
#+end_comment

#+begin_comment
htmlpreview-annotation-event:v1
JSON_EVENT
#+end_comment
#+end_src

For Markdown the corresponding envelope is:

#+begin_src html
<!-- htmlpreview-annotations:v1
JSON_HEADER
-->
<!-- htmlpreview-annotation-event:v1
JSON_EVENT
-->
#+end_src

- Header schema :: ={schema:1, document_id:<UUIDv4>, source_format:"org"|"markdown"}=.
  The source and sidecar share document_id once either exists. An absent embedded
  header may adopt the valid sidecar's ID. Simultaneous first writes serialize by
  canonical source identity. No absolute source path or capability is persisted.
- Event schema :: ={schema:1, operation_id, annotation_id, composer_id, sequence,
  kind:"draft"|"close", author, created_at, recorded_at, target, text}=.
  Times are server-generated RFC3339 UTC. created_at and author remain fixed
  across a composer's events. Sequence starts at one and increments exactly;
  a close event repeats the latest acknowledged text/target and seals the record.
- Projection :: Display *one comment per annotation_id*, using its highest valid
  contiguous sequence; retain all prior events in the file. Order comments by
  created_at then annotation_id. Equal IDs with unequal event content constitute
  corruption and disable writes; exact duplicate records are deduplicated.
- Recognition :: Recognize only *top-level, exact owned markers* outside source/
  example blocks, Markdown fences/indented code, quoted/list-literal contexts and
  ordinary comments. Extract before Org preservation/Pandoc. Markers in literal
  examples remain content. An owned header followed by malformed/incomplete
  frames or authored content after the store is diagnosed and cannot be appended.
  A source ending inside an unterminated literal/comment construct cannot safely
  accept an embedded store; report conflict rather than guess an insertion point.
- Bytes :: Preserve the existing file prefix exactly, including BOM and CRLF.
  Append owned records with the source's predominant line ending, LF on a tie.
  Initial store creation appends *exactly two line-ending sequences* before the
  header frame. They belong to the owned tail and are removed with that tail
  when calculating source_revision, so initial annotation creation itself does
  not change the authored-source digest. Subsequent appends stay within the tail.
  Embedded events are not placed in ordinary YAML frontmatter or property drawers.
- Sidecar :: Adjacent to the *canonical source*, use full basename plus
  =-annotations.org=. It contains the Org envelope regardless of source format.
  No source path supplied by the browser determines the filename. New sidecars
  are exclusive-created regular files with mode 0600; existing permissions are
  preserved. Foreign/corrupt files at that name are never overwritten or adopted.
- Selection :: Safely writable source uses embedded storage; EACCES/EPERM/EROFS
  opening the otherwise safe source for append selects the sidecar. Do not use
  chmod or privileges. A safety/parse/identity failure is not read-only fallback.
  Pin the chosen destination per composer; later permission loss pauses it.
  New composers may choose again. Reads *union both valid stores*, with no
  automatic relocation or pruning.
- Bounds :: Preserve W006's *10 MiB total source ceiling*, including embedded
  events; sidecar <=10 MiB, combined annotation frames <=10 MiB and <=10,000
  events per document, each frame <=64 KiB. Autosave history consumes this budget.
  At capacity, stop saving visibly; never evict comments or compact history.
  Check the complete planned append before any bytes are written.
- Portability :: Embedded records travel on rename/copy. Sidecars travel only if
  moved with the source and renamed to its full-basename convention. Do not
  scan the disk looking for detached sidecars. Two copied documents become
  independent storage locations even if their initial document IDs match.

*** Append safety and interruption
:PROPERTIES:
:CUSTOM_ID: append-safety
:END:

- Admission :: Reuse W006 rooted handles, canonical identity, regular-file and
  filesystem checks for both source and sidecar. *No symlink sidecar* and no
  multi-hard-linked write target (link count >1). A logical source symlink may
  resolve to a safe canonical source within the grant; writes target that identity.
  Recheck both canonical paths against their held handles immediately before append.
- Serialization :: One in-process writer lock per canonical source, plus an
  *exclusive nonblocking advisory lock on the selected file*. A locked file returns
  429 within one second. If native safe append/locking is unsupported, refuse
  writing with a specific diagnostic; do not weaken confinement for WSL mounts.
- Compare :: Under the lock read source/sidecar, validate complete framing,
  operation identity and expected per-annotation sequence, then compare the
  request's *source_revision*. A different full read revision is allowed when
  caused only by other valid annotation events. A known successful
  retry is recognized *before* stale-revision rejection and synchronized/read back
  before returning acknowledgement. Other mismatches return 409 without append.
- Write :: Append complete frame bytes with an O_APPEND handle; never truncate,
  patch existing bytes, serialize the authored document or replace the whole file.
  Detect short writes, synchronize the file, verify committed bytes and recheck
  path/handle identity before success. Synchronize the parent after sidecar creation.
- Failure :: An append is *not claimed physically atomic across power loss*.
  Only complete validated frames count as events; retain and diagnose an incomplete
  tail, expose earlier saved events and block further writes. A full event after
  an uncertain sync can be retried and synchronized without a duplicate append.
  Never roll back by overwriting bytes another process may have changed.
- External limits :: Advisory locks do not bind arbitrary editors. Detected
  rename/replacement/truncate is a conflict; refresh reflects the actual file.
  An editor can overwrite an earlier acknowledged append later. The UI/guide
  must explain this limit rather than describe autosave as a filesystem lock.
- Logging :: Operation/status/duration and safe request ID only. Do not log
  comments, author names, excerpts, raw paths or capabilities. Persisted comments
  are *part of the document's data*, not confidential hidden browser state.

*** Targets and reattachment
:PROPERTIES:
:CUSTOM_ID: annotation-targets
:END:

- Types :: ={type:"document"}= or ={type:"text", body_revision, exact, prefix,
  suffix, start, end, heading_id}=. Text indices count *Unicode scalar values*;
  end is exclusive. heading_id is optional and can name only a *verified explicit
  source ID* from the provenance map below; absence uses quote/context alone.
  The server validates selectors against the current authorized rendering.
- ID provenance :: Before catalogue removes =data-hp-custom= and =data-hp-org-id=,
  preserve *valid unique Org CUSTOM_ID/ID from the owned prepass* in a server-side
  map from explicit source ID to final section ID. Exclude duplicated/invalid IDs.
  Emit the verified map as escaped, owned non-executable page data for the browser;
  source-authored HTML cannot supply or override it. Keep transport attributes
  stripped. Pandoc text slugs, ordinal fallback IDs and raw HTML/Markdown IDs
  have no verified provenance in W007 and are never corroborating evidence for
  reattachment or changed-source fold restoration. Markdown quote anchoring
  remains fully supported without heading_id. A future explicit Markdown-ID
  provenance extension requires its own definition.
- Canonical text :: Traverse sanitized authored content in document order before
  injecting controls. Include headings, prose, tables, code and drawer values,
  including folded content. Exclude filename/header frontmatter controls, nav,
  generated copy/fold labels and annotation UI/transport. Insert a separator at
  block boundaries and br, collapse Unicode White_Space runs to one ASCII space
  and trim outer space. No case folding or Unicode normalization. Go and browser
  use the same explicit White_Space code-point table and block-element list
  defined with shared fixtures during delivery; they must agree byte-for-byte.
- Fast path :: On an unchanged body revision, accept stored positions *only if
  the exact quote matches* there.
- Changed body :: Search exact normalized quotes, refine using stored context and
  surviving stable heading context; attach *only one uniquely verified match*.
  A changed optional heading does not alone prove the quote lost, but never
  discard conflicting context merely to manufacture a unique match.
- Unresolved :: Zero/multiple candidates display the original excerpt and
  Missing/Ambiguous status in the annotations list. Never hide the comment or
  silently choose the first occurrence. No fuzzy matching or automatic retargeting.
- Source identity :: Canonical path/handle identifies the live document, separate
  from logical link context. URLs and root tokens are never persistent anchors.
  A source rename requires reopening by its new path; no global file watcher
  follows files outside admitted roots.

*** Browser interaction
:PROPERTIES:
:CUSTOM_ID: annotation-browser
:END:

- Entry :: An *Annotations* toolbar button opens the list and Add comment action.
  A retained selection inside authored content targets that passage; without one,
  target the whole document. Show the target excerpt in the composer before input.
  Do not hijack ordinary sentence clicks, code copying or heading folding.
- Layout :: Keep one composer in a stable panel outside the replaceable source
  DOM. Wide layouts must coexist with the left navigation; narrow layouts use
  document flow with no overflow. Annotations use distinct, subtle styling.
- Accessibility :: Native buttons/textarea with labels, visible focus, pointer
  cursors on actions, keyboard selection and polite live status. Escape closes
  through the save guard; focus returns to the invoking control/nearest surviving
  target. Status cannot depend only on colour, a glyph or animation.
- Selection :: Capture the Range before focus changes; map cross-node/code
  selections without surroundContents assumptions. Markers must preserve literal
  text, links and copy payloads. Heading/drawer controls keep independent listeners.
- Lifecycle :: Dispose replaced-region listeners/timers without disposing the
  composer or losing dirty text. Reinitialize after refresh/bfcache restoration
  without duplicate handlers. JavaScript disabled leaves an inert readable page.
- Print :: Closed and latest acknowledged draft comments form a labelled appendix
  with author/date, quote and unresolved status. Exclude pending text, capabilities
  and buttons; restore screen state after printing.
- Browser limitation :: beforeunload is best effort and cannot guarantee saving
  on process termination; [[https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event][the
  browser event documentation]] records this limitation. Auto-refresh and autosave
  do not change it.

- Observability :: Keep *clock, jitter, request transport and write/sync faults*
  controllable at the named owned boundaries. Browser fixtures execute the real
  composer and DOM modules; Go tests exercise real temporary stores and HTTP.
  Shared text fixtures compare Go/browser results. Native locking/durability
  remains [[#ot-007-2][OT007.2 - Filesystem qualification]]; visual and assistive
  usability remains the defined user tests. No imitation of an arbitrary editor
  or browser replaces those observations.
- Proportionality :: The *append history* follows the operator's storage and
  lifecycle choice; it is not a general event-sourcing platform. Bounded polling
  reuses the service rather than adding watchers or push infrastructure. The
  accepted consequence is growing history and a visible capacity stop; any
  compaction or editable-comment feature requires a later approved change.

- *Private names, package/file grouping and CSS values* may follow the existing

- Fixture organization and narrow function signatures remain routine. *Event

  save/close behaviour are already decided* above. They are not left open for
  a delivery agent to redesign.

** Architecture impact

*** Security impact

- Threat boundary :: *Reading becomes purpose-limited writing* only through
  annotation-enabled registration. Configured roots remain the maximum grant.
  No read-only W006 registration can mint a writer.
- Request protection :: Preserve hardcoded 127.0.0.1, exact Host, restart-scoped
  capability, no CORS and no trusted forwarding. Mutation also requires *exact
  Origin*, application/json and the separate document token; reject missing/null
  Origin and cross-site fetch metadata. GET/HEAD never mutate durable data.
- Browser policy :: Permit =connect-src 'self'= for owned annotation requests;
  retain hash-authorized packaged scripts/styles, no remote assets, no-referrer,
  no-store and frame-ancestors none. Source-authored controls/scripts and
  service-origin automatic requests remain stripped.
- Content :: Render comments/names with textContent or Go escaped templates,
  never HTML interpretation. Structured storage escapes delimiter characters.
  Reading a forged on-disk author does not grant editing rights.
- Privacy :: Embedded comments, authors and retained draft revisions *travel when
  the file is shared or committed*. Sidecars inherit filesystem accessibility;
  0600 creation does not protect against the same OS user. No telemetry, remote
  synchronization, automatic clipboard copy or browser-local secret persistence.
- Conclusion :: W007 deliberately adds a narrow write capability. No public
  listener or directory exposure option is added; filesystem/race qualification
  is required before claiming native write support.

*** Other relevant qualities

- Reliability :: Append history, exact-operation retries, current-revision checks,
  auto-refresh and explicit unresolved state limit data loss without claiming
  control over unrelated editors. Saved drafts survive service restart.
- Performance :: Shared polling avoids one disk read per tab. W006's conversion
  ceilings remain; at most *two concurrent annotation writers globally*, one per
  document, with no waiting queue. Reject busy admission with 429; request/write
  deadline five seconds. No recursive watchers, network fetches or background scans.
- Operability :: W006 service installation remains explicit. No new daemon or
  database. Stop/restart revokes grants; files retain comments. Downgrade preserves
  records but may show only ordinary documents; never delete annotations on uninstall.
- Portability :: macOS, Linux and WSL retain the system default browser; actual
  filesystem support is qualified rather than inferred. No network configuration
  change or non-loopback fallback is permitted.
- Accessibility :: Annotation controls retain *keyboard access, visible focus,
  accessible names and polite textual save status* through autosave and refresh.
  Browser regressions verify mechanical behaviour; human screen-reader and
  visual usability qualification remains required under
  [[#ac-007-19][AC007.19 - Accessible browser interaction]] and
  [[#ut-007-6][UT007.6 - Accessible and safe presentation]].
- Maintainability :: Keep event codec, rooted append policy, anchors, HTTP adapter,
  composer state and DOM mapping as independently testable responsibilities.
  Go/HTML/CSS/browser JS suffice; justify any Go dependency before introduction.
- Future hosting :: A separately approved Exodan deployment would supply service
  users, bounded server-owned documents and mutable STATE_DIRECTORY storage.
  Bundled data_dirs are not mutable annotation storage. The application would own
  authenticated identities, permissions and annotation format/API; Exodan would
  own hosting/TLS/deployment. *No client personal filesystem is exposed*. W007
  does not adopt configurable ADDR, hosted authentication or deploy artefacts.
