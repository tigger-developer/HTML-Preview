#+SUBTITLE: Unified defect correction specification

* Fold initial Org property drawers
:PROPERTIES:
:CUSTOM_ID: summary
:END:

- Outcome :: An enhanced Org preview *starts each heading's immediate PROPERTIES
  drawer folded*.
- Before :: *Every Org drawer starts open*, including a PROPERTIES drawer placed
  immediately after a heading.
- After :: JavaScript *folds only the initial heading PROPERTIES drawer* while
  passive HTML remains fully readable.
- Changes :: The renderer identifies the drawer; browser enhancement applies its
  initial closed state and retains the existing reveal and print rules.
- Unchanged :: Other drawers, drawers not immediately after headings, source
  text, section controls, no-JavaScript output and document navigation remain
  unchanged.
- Edge cases :: A heading without a drawer, an empty drawer, a later PROPERTIES
  drawer, nested headings, global modes, source marker-like HTML, printing and
  page-lifecycle teardown retain defined behaviour.
- Decisions :: The operator classified this as a *defect*. "Immediately after"
  permits only whitespace between the heading and drawer.
- Next step :: Definition gate, then operator sign-off.

-----

* Context
:PROPERTIES:
:CUSTOM_ID: context
:END:

** Problem

Org source conventionally places a PROPERTIES drawer directly beneath its
heading. The current renderer emits every drawer open and the browser module
does not distinguish them. That leaves the metadata expanded in an enhanced
preview, contrary to the expected initial reading view.

** Scope

*** In scope

- Detect an Org =PROPERTIES= drawer that follows its heading with only whitespace
  between them.
- Mark the generated drawer without trusting source-supplied HTML attributes.
- Close that marked drawer during browser enhancement's initial state.
- Preserve a marked drawer's normal native summary control, fragment revelation,
  print expansion/restoration and page-lifecycle teardown.
- Add regression and user validation evidence for the defect.

*** Out of scope

- Changing any source document.
- Folding LOGBOOK or other named drawers.
- Folding a PROPERTIES drawer elsewhere in a section.
- Adding a user setting, a new browser harness or an Org parser dependency.

*** Unchanged

- Generated HTML with JavaScript disabled keeps every drawer open and readable.
- Existing section visibility, global outline controls, copied code and contents
  behaviour keep their current contracts.
- Existing non-drawer fragment revelation remains governed by W001/W002. Drawer
  text has no generated fragment mapping and is outside this defect correction.

** Authority and starting point

- Project profile :: [[file:../../.sdlc/project.yaml][=.sdlc/project.yaml=]].
- Product authority :: [[file:../../docs/VISION.md][Vision]], Org fidelity and
  direct document navigation.
- Architecture authority :: [[file:../../docs/ARCHITECTURE.md][Architecture]],
  browser folding responsibility.
- Historical requirement :: [[file:../001-local-document-preview/spec.org][W001 - Installable Markdown and Org previews]], which requires drawers to be
  open without JavaScript and enhancement to apply initial folding.
- Historical delivery :: [[file:../002-code-and-outline/spec.org][W002 - Code
  highlighting, copying and document navigation]], which owns enhanced folding
  and states its historical drawer-open rule. W004 *supersedes that rule only
  for an immediate Org PROPERTIES drawer*; every other W002 drawer behaviour
  remains current.
- Current implementation :: =internal/preview/org.go= emits every drawer as
  =details open=; =assets/web/preview.js= only opens drawer state.

** Constraints and dependencies

- Use existing Go Org pre-processing, owned browser JavaScript and native HTML
  details elements; introduce no runtime dependency.
- Treat source content as untrusted; only application-generated metadata may
  select initial drawer folding.
- Keep no-JavaScript content readable and preserve print accessibility.

** Decisions

- "Immediately after a heading" means the drawer is the first non-whitespace
  content in that heading's section.
- An initial PROPERTIES drawer begins closed only after JavaScript enhancement.
- The native =summary= interaction and the existing global/section, fragment and
  print paths remain valid ways to reveal drawers; no additional control is added.
- The reserved application marker is =data-hp-initial-property-drawer=. It is
  added only by the post-sanitization renderer from an Org pre-pass provenance
  record. Source HTML cannot create, retain or select this marker.

** Unresolved blockers

- None.

* Edge Cases
:PROPERTIES:
:CUSTOM_ID: edge-cases
:END:

** Heading and drawer placement

- Condition :: A heading has whitespace then a PROPERTIES drawer, body text then
  a drawer, another drawer name, nested immediate drawer, source marker-like
  HTML, or no drawer.
- Required behaviour :: Only whitespace-adjacent PROPERTIES is marked; all other
  cases retain their open initial state.
- Covered by :: [[#rt-004-1][RT004.1 - Marked initial property drawer]].

** Nested, global and print state

- Condition :: A marked drawer appears under a folded ancestor, global/section
  controls reveal it, or the reader prints while it is closed or open.
- Required behaviour :: Existing controls reveal content; print returns to the
  actual pre-print state. Drawer-internal fragment targets are out of scope
  because preserved drawer text has no generated fragment mapping.
- Covered by :: [[#ut-004-1][UT004.1 - Browser drawer state]].

* Solution Design
:PROPERTIES:
:CUSTOM_ID: solution-design
:END:

** Architecture context

- Components :: Org pre-processing owns source-to-HTML drawer recognition;
  browser enhancement owns interactive initial state.
- Existing pattern :: All drawer HTML is application-generated and open in the
  passive document. The browser module already preserves print state and opens
  fragment ancestors.

** High-level design

*** Flow

1. The Org pre-pass recognizes a PROPERTIES drawer immediately after a heading
   and emits an owned marker on its details element.
2. The generated document retains =open= on all drawers for passive reading.
3. At enhancement start, browser JavaScript closes only owned marked drawers;
   existing global/section, print and teardown logic continues to operate on
   native details elements and preserves the pre-print state.

*** Interfaces and configuration

- Interface :: Internal =data-hp-initial-property-drawer= marker only; no CLI
  option or public setting. The renderer adds it after sanitization from a
  provenance record, and browser code selects this exact attribute only.
- Compatibility :: Existing documents and non-marked drawers retain open initial
  state. Markers are removed or ignored safely by non-enhanced reading.

** Architecture impact

*** Security impact

- Threat boundary :: Source-derived drawer names and raw HTML stay untrusted;
  only Go emits the marker.
- Data and secrets :: No new data collection, storage or logging.
- Access :: No access or permission change.
- Conclusion :: Existing sanitization and browser-only execution boundary remain
  sufficient.

*** Other relevant qualities

- Accessibility :: Native summary interaction remains keyboard accessible; the
  no-JavaScript state stays readable.
- Portability :: Uses existing browser-standard details behaviour on supported
  macOS, Linux and WSL browsers.
- Maintainability :: A semantic marker avoids positional browser heuristics and
  keeps recognition alongside existing Org drawer handling.
