* Fold generated Org drawers
:PROPERTIES:
:CUSTOM_ID: summary
:END:

- Outcome :: An enhanced Org preview *starts every generated Org drawer folded*.
- Before :: *Every generated Org drawer starts open*.
- After :: JavaScript *folds all generated Org drawers* while passive HTML remains
  fully readable.
- Changes :: The renderer identifies generated Org drawers; browser enhancement
  applies their initial closed state and retains existing reveal and print rules.
- Unchanged :: Source-authored HTML details retain the existing forced-open
  passive state; section controls, no-JavaScript output and document navigation
  remain unchanged.
- Edge cases :: Unheaded, empty, nested, LOGBOOK and named drawers, global modes,
  source marker-like HTML, printing and page-lifecycle teardown retain defined
  behaviour.
- Decisions :: The operator classified this as a *defect*. This amendment adopts
  Org's all-drawer startup model rather than a PROPERTIES-only exception.
- Next step :: Definition gate, then operator sign-off.

* Context
:PROPERTIES:
:CUSTOM_ID: context
:END:

** Problem

Org uses drawers for metadata and secondary material that readers normally do
not need to see. The current renderer emits every generated Org drawer open and
the browser module does not distinguish them. That leaves drawer content expanded
in an enhanced preview, contrary to Org's normal drawer startup model.

** Scope

*** In scope

- Mark every generated Org drawer without trusting source-supplied HTML
  attributes.
- Close each marked drawer during browser enhancement's initial state.
- Preserve each marked drawer's normal native summary control, print
  expansion/restoration and page-lifecycle teardown.
- Add regression and user validation evidence for the defect.

*** Out of scope

- Changing any source document.
- Folding source-authored HTML =details= elements.
- Adding a user setting, a new browser harness or an Org parser dependency.

*** Unchanged

- Generated HTML with JavaScript disabled keeps every drawer open and readable.
- Existing section visibility, global outline controls, copied code and contents
  behaviour keep their current contracts.
- Existing non-drawer fragment revelation remains governed by W001/W002. Drawer
  text has no generated fragment mapping and is outside this defect correction.

** Authority and starting point

- Project profile :: [[file:../../.sdlc/project.yaml][=.sdlc/project.yaml=]].
- Product authority :: [[file:../../docs/VISION.md][Vision]], Org fidelity and
  direct document navigation.
- Architecture authority :: [[file:../../docs/ARCHITECTURE.md][Architecture]],
  browser folding responsibility.
- Historical requirement :: [[file:../001-local-document-preview/spec.org][W001 - Installable Markdown and Org previews]], which requires drawers to be
  open without JavaScript and enhancement to apply initial folding.
- Historical delivery :: [[file:../002-code-and-outline/spec.org][W002 - Code
  highlighting, copying and document navigation]], which owns enhanced folding
  and states its historical drawer-open rule. W004 *supersedes that rule for all
  generated Org drawers*; source-authored HTML details remain outside the rule.
- Org authority :: The current [[https://orgmode.org/manual/Drawers.html][Org
  drawer manual]] describes drawers as material readers do not normally see. Its
  [[https://orgmode.org/manual/In_002dbuffer-Settings.html][startup settings]]
  provide =hidedrawers= and =nohidedrawers= for all drawers. This 2026-09-10
  amendment supersedes W004's earlier PROPERTIES-only interpretation.
- Current implementation :: =internal/preview/org.go= emits every drawer as
  =details open=; =assets/web/preview.js= only opens drawer state.

** Constraints and dependencies

- Use existing Go Org pre-processing, owned browser JavaScript and native HTML
  details elements; introduce no runtime dependency.
- Treat source content as untrusted; only application-generated metadata may
  select initial drawer folding.
- Keep no-JavaScript content readable and preserve print accessibility.

** Decisions

- Existing Org outline startup is applied first: absent metadata means =showall=;
  exact =overview=, =content= and =showall= use their existing meanings; the last
  =#+STARTUP= directive wins; =VISIBILITY= folded|children|all= overrides its
  own heading subtree. Unknown, multiple-value, =hidedrawers= and =nohidedrawers=
  directives are retained as visible metadata, warn, and select =showall=.
- After outline startup, every generated Org drawer begins closed. This W004
  rule supersedes W001's previous drawer-open result for default, all supported
  startup modes and every =VISIBILITY= value. Runtime Show all, native summary,
  fragment revelation and print may subsequently open drawers. Unfolding a
  section leaves its generated drawers closed.
- Each drawer fragment is keyed by a random transport token that cannot occur in
  source. After scrubbing source HTML, restoration replaces exactly one matching
  placeholder with the owned drawer and adds =data-hp-org-drawer=. The final
  sanitizer permits that attribute only on =details=; source attributes and
  classes are scrubbed before restoration and cannot create it.
- Fragment destinations remain limited to generated headings and ordinary body
  targets. Drawer text has no generated target; source-authored detail targets
  retain their existing browser behaviour and are outside W004.
- The native =summary= interaction and the existing global/section, fragment and
  print paths remain valid ways to reveal drawers; no additional control is added.
- The reserved application marker is =data-hp-org-drawer=. The pre-pass creates
  one random placeholder per drawer; post-scrub restoration replaces that exact
  placeholder and adds the marker; final publication sanitization permits it only
  on details. Source HTML cannot create, retain or select this marker.

- None.

* Edge Cases
:PROPERTIES:
:CUSTOM_ID: edge-cases
:END:

** Drawer origin and placement

- Condition :: The input has unheaded, empty, PROPERTIES, LOGBOOK and named Org
  drawers; drawers beneath nested headings; source marker-like HTML; or no drawer.
- Required behaviour :: Every generated Org drawer is marked and closed after
  outline startup. Source HTML details retain their existing forced-open state.
- Covered by :: [[#rt-004-1][RT004.1 - Marked Org drawers]].

** Nested, global and print state

- Condition :: A marked drawer appears under a folded ancestor, a section is
  unfolded, runtime Show all is selected, or the reader prints while it is closed or open.
- Required behaviour :: Section unfolding leaves drawer state closed; runtime
  Show all and native summary reveal content; print returns to the
  actual pre-print state. Drawer-internal fragment targets are out of scope
  because preserved drawer text has no generated fragment mapping.
- Covered by :: [[#ut-004-1][UT004.1 - Browser drawer state]].

* Solution Design
:PROPERTIES:
:CUSTOM_ID: solution-design
:END:

** Architecture context

- Components :: Org pre-processing owns source-to-HTML drawer recognition;
  browser enhancement owns interactive initial state.
- Existing pattern :: Org drawer HTML is application-generated and open in the
  passive document. The browser module already preserves print state and opens
  fragment ancestors.

** High-level design

*** Flow

1. The Org pre-pass recognizes every Org drawer and emits one unique text
   placeholder. Post-scrub restoration replaces each placeholder with its owned
   =details open data-hp-org-drawer= fragment; final document sanitization retains
   that attribute only on =details=.
2. The generated document retains =open= on all drawers for passive reading.
3. At enhancement start, browser JavaScript applies existing outline visibility,
   then closes every owned marker. Existing global/section, fragment, print and
   teardown logic continues to operate on native details elements; pageshow
   reapplies the owned initial state after pagehide restoration.

*** Interfaces and configuration

- Interface :: Internal =data-hp-org-drawer= marker only; no CLI
  option or public setting. The renderer adds it after sanitization from a
  provenance record; the final sanitizer permits it only on generated
  =details=; browser code selects this exact attribute only.
- Compatibility :: Generated Org drawers change only after enhancement;
  source-authored details retain the existing forced-open state. Unsupported
  =hidedrawers= and =nohidedrawers= follow the existing unknown-startup warning
  and =showall= outline fallback. Markers are removed or ignored safely by
  non-enhanced reading.

** Architecture impact

*** Security impact

- Threat boundary :: Source-derived drawer names and raw HTML stay untrusted;
  only Go emits the marker.
- Data and secrets :: No new data collection, storage or logging.
- Access :: No access or permission change.
- Conclusion :: Existing sanitization and browser-only execution boundary remain
  sufficient.

*** Other relevant qualities

- Accessibility :: Native summary interaction remains keyboard accessible; the
  no-JavaScript state stays readable.
- Portability :: Uses existing browser-standard details behaviour on supported
  macOS, Linux and WSL browsers.
- Maintainability :: A semantic marker avoids positional browser heuristics and
  keeps recognition alongside existing Org drawer handling.
