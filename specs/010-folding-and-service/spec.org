* Requirements

- Folding :: Accept optional =folding.override.headers=, =drawers= and =default=,
  each =open= or =closed=. Headers override authored startup/visibility; drawers
  select Org drawers; default selects other foldables, including frontmatter.
  Omitted fields preserve normal initial behaviour. Reject unknown/duplicate keys
  and invalid values. Apply in file previews and inherit through HTTP links.
- Interaction :: Initial settings *do not lock controls*. Headings and bars
  remain clickable; Show all opens all details; fragments reveal targets;
  print restores state. Annotation refresh preserves explicitly identified
  headings and unambiguous detail identities.
- Service :: =make serve= aliases =make service=. Build, generate the user's
  LaunchAgent with absolute paths, then =launchctl load= it. =make service-stop=
  invokes =launchctl unload= without deleting the plist. Neither opens a browser.
- Configuration :: Preserve first-found explicit/current-directory/user selection.
  Background activation requires a config file. Accept the user's =~/= roots,
  expanding only the current user's home; retain canonical filesystem boundaries.
- Testing instruction :: *Remove browser automation*. Browser gestures and visual
  checks are manual UTs; server/configuration/persistence assertions are Go RTs.
  Never take control of the operator's desktop to execute tests.

* Solution and security

- Reuse :: Extend the existing strict YAML parser, private registration settings,
  render identity and owned page attributes. Initial folding runs in the existing
  browser outline controller; explicit refresh state takes precedence.
- Activation :: Reuse the plist renderer and Go build tool. Pass launchctl
  arguments separately; XML-escape resolved paths. No shell expansion or new
  dependency. LaunchAgent activation belongs to the operator invoking the target.
- Access :: Loopback binding and configured-root containment remain mandatory.
  Home notation expands only configured roots. No default whole-home grant,
  remote listener, config rewriting or annotation-store change is introduced.

* TMPDIR amendment - 15 September 2026

- Authority :: The operator reported that =$TMPDIR= in =serve.roots= rejects
  the configuration and prevents previewing temporary documents.
- Contract :: Accept a leading =$TMPDIR= or =${TMPDIR}=, optionally followed
  by a slash and child path. Read its value from the process environment;
  require a non-empty absolute directory path. Unknown variables are rejected.
  Existing canonical-root and filesystem checks still apply after expansion.
- Superseded service proposal :: Generated LaunchAgents retain the invoking environment's TMPDIR
  as a literal XML-escaped value, when present. No shell evaluation is used.
- Verification :: =TestTMPDIRConfiguration= covers configuration admission and
  rejection. The proposed =TestLaunchAgentTMPDIR= environment-preservation test
  was withdrawn when runtime resolution superseded installation-time capture.

* Paired logging and push-update amendment - 15 September 2026

- Authority :: Taḋg requested persistent service diagnostics first, then explicitly
  authorized server-sent events and confirmed the live service was stopped.
- Logging :: LaunchAgents direct stdout/stderr to a private user log file.
  Annotation failures record timestamp, method, HTTP status, bounded error code
  and an opaque document identifier; never source text, comments or capability URLs.
- Push :: Replace periodic browser GET polling with an authorized SSE stream for
  the current Org/Markdown annotation document. Watch the containing directory
  for source and adjacent sidecar changes, including atomic file replacement.
  Coalesce bursts, notify without source data, and refresh through existing APIs.
- Boundaries :: Keep source revision checks on saves and retain dirty composers.
  Reconnect and returning to a visible tab refresh state. No browser automation.
  Limit concurrent streams; disconnect and shutdown release watchers. Heartbeat
  comments keep idle streams alive without fetching document state.
- Dependency :: Use fsnotify for native macOS/Linux directory events; no recursive
  watchers. Unsupported filesystem notification behaviour remains a platform UT.
- Runtime temp path :: Supersedes the proposed plist TMPDIR capture above:
  resolve the runtime environment value when loading config, not at installation.
- Evidence :: Go HTTP tests for notification, replacement, refusal, disconnection
  and error logs; generated plist assertions; manual UT for editor behaviour.

* Paired breaking header-folding amendment, 18 September 2026

- Authority :: The operator requested nested semantic heading settings while
  retaining configuration version 1. This supersedes the scalar headers field.
- Schema :: =folding.override.headers= is an optional mapping with optional
  =default=, =todo= and =done= values, each =open= or =closed=. Drawers and the
  outer default retain their existing scalar meanings. Reject the old scalar
  headers syntax with a migration message; reject unknown/duplicate nested keys,
  nulls, incorrect types and unsupported values. Do not rewrite user config.
- Semantics :: Use Pandoc's existing semantic task classes, including custom Org
  TODO/SEQ_TODO/TYP_TODO sequences and their before/after separator categories.
  Do not compare heading words with literal TODO or DONE. A category override
  takes precedence over headers.default; when both are absent, preserve authored
  or normal initial folding. Unclassified headings use headers.default.
- Interaction :: Apply per heading after authored startup/visibility and before
  restored reader state. Closed ancestors still hide their descendants. Initial
  overrides do not restrict manual bars/buttons, fragment navigation or print.
  The outer default remains for other foldables rather than a heading fallback.
- Transport :: Carry the nested settings through CLI registration, capability
  identity, linked previews and cached render identity in both file and service
  modes. Reuse the existing outline controller and semantic classes.
- Verification :: Amend YAML rejection/admission and file/HTTP inheritance RTs;
  verify custom active/completed classes alongside emitted category settings.
  Browser initial state and preserved manual controls remain manual UT. Update
  the documented config and packaged example; retain the old schema as history.
