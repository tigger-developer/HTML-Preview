* Synopsis
:PROPERTIES:
:CUSTOM_ID: summary
:END:

** Outcome

- Eligible local SVG image references *render as PNG* in file and service previews.

** Before

- SVG image references were treated as unsupported media and *did not render*.

** After

- A bounded conversion runs during rendering; the source document and SVG remain
  unchanged, and *only verified PNG bytes reach the preview*.

** Changes

- Add an `rsvg-convert` boundary, generated-media publication and packaged librsvg
  dependency.

** Unchanged

- *Raw inline SVG remains blocked* and SVG anchors remain download-only.

** Edge cases

- Missing or incompatible conversion, invalid dimensions and excessive output
  preserve readable alternative text without publishing partial image content.

** Decisions

- Supply SVG through standard input without a base URL, cap dimensions at
  4096 by 4096 pixels, and accept only a signature-verified PNG result.

** Next step

- Complete delivery-code review, retrospective definition review, user validation
  of the reported document and operator closure.

* Context
:PROPERTIES:
:CUSTOM_ID: context
:END:

** Problem

Markdown and Org can refer to local SVG diagrams, but the passive-media policy
admits only raster bytes and therefore omits those images from the preview.

** Outcome

The renderer converts an eligible rooted local SVG reference to a bounded PNG at
request time and publishes the generated raster through the existing transport.

** Scope

*** In scope

- Local SVG references used as images in native or passive document output; file
  and service transports; converter discovery; generated service PATH; Homebrew
  dependency; fallback notices; regression and user evidence.

*** Out of scope

- Rendering raw inline SVG, changing SVG link/download behaviour, remote SVG,
  animated SVG, conversion of arbitrary files, source modification and deployment.

*** Unchanged

- Existing rooted-file authorization, browser passive-content policy, image
  alternatives, output budgets and source ownership remain authoritative.

- Operator authority :: =BYPASS-GATE-7= on 4 October 2026 for the corrected
  HTML Preview code change.
- Project profile :: [[file:../../.sdlc/project.yaml][=.sdlc/project.yaml=]]

  was inspected read-only; no content was copied into the repository.

** Constraints and dependencies

- The converter must be `rsvg-convert` 2.57.0 or later and execute under the
  request context and existing output budget.
- SVG dimensions must be explicit finite positive numbers, pixel lengths or a
  finite viewBox-derived size, no greater than 4096 pixels per side or area.

** Decisions

- Resolve the executable directly and use literal arguments, standard input and
  the existing bounded child-process runner.
- Do not pass the source path or a base URL. Reject document type declarations
  before conversion and rely on the converter's passive SVG processing in
  addition to the application's own source, dimension and output bounds.

** Unresolved blockers

- Browser presentation of the reported document requires operator validation
  after installing or running the candidate executable.

- Condition :: The SVG lacks bounded dimensions, declares a document type,
  exceeds bounds, the executable is absent or too old, conversion fails, or its

* Solution Design
:PROPERTIES:
:CUSTOM_ID: solution-design
:END:

** Architecture context

- Relevant components :: The existing reference resolver owns rooted snapshots;
  the session owns limits and executable discovery; the image resolver owns file
  embedding or service media publication.
- Ownership boundary :: HTML Preview authorizes and bounds bytes. Librsvg parses
  and rasterizes the supplied SVG without receiving its filesystem identity.

** High-level design

- Detect `.svg` after the existing rooted local-asset read. Parse only the root
  dimensions, enforce limits, discover and version-check `rsvg-convert`, then run
  it through the existing context-bound process interface.
- Count source and generated bytes against the session budget. Verify the PNG
  signature before embedding or registration. Generated assets have no source
  filename and therefore cannot be reopened as the original SVG.
- Cache executable compatibility per session. Mark failed service conversions
  uncacheable so a corrected runtime or file can be retried.

** Architecture impact

*** Security impact

- Threat boundary :: Untrusted SVG reaches a native parser, so input dimensions,
  execution time and output bytes are bounded before any browser publication.
- Network and files :: No source path or base URL is supplied. The child receives
  only standard-input bytes; the existing request context owns cancellation.
- Browser boundary :: Only verified PNG bytes cross the generated-media boundary.
  No SVG scripting, events, animation or external reference capability is added
  to the preview page.
- Conclusion :: The change adds a narrow native conversion dependency without
  widening browser execution or filesystem authorization.

*** Other relevant qualities

- Portability :: Source installs require librsvg on PATH; the macOS Homebrew
  formula declares it, and generated services retain its discovered directory.
- Reliability :: Failure degrades one image to its alternative without failing
  or partially publishing the containing document.
