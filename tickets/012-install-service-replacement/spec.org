* Synopsis
:PROPERTIES:
:CUSTOM_ID: summary
:END:
** Outcome
- *Installation can switch checkouts* without manually deleting the old link or
  unloading the old HTMLPreview LaunchAgent.
** Before
- A *different or dangling executable symlink* stopped installation.
- Repeated service activation used *launchctl load* against an existing job.
** After
- The default executable link is *atomically replaced* when its target differs.
- Service activation *replaces the registered job* by its stable user label.
** Changes
- *bootout, enable and bootstrap* replace the older load/unload sequence.
- A failed replacement *restores the prior plist* and attempts to restart the
  old registration. Recovery failures remain explicit.
** Unchanged
- *Regular executable files and directories are protected*; prefix copy policy,
  user configuration, logs, roots and rendering remain unchanged.
- This correction stays on *master*, separate from W011's feature branch.
** Edge cases
- *Missing jobs are normal*; other launchd failures are reported.
- Stale plist symlinks are *replaced without changing their targets*.
- An old registration with *no recoverable plist* cannot be reconstructed after
  a failed replacement; the error identifies that limitation.
** Decisions
- Reuse the *existing Go build tool*, a same-directory staged rename and the
  single =org.htmlpreview.agent= label. No new service or dependency.
** Next step
- Review implementation evidence and perform the native checkout-switch user
  test before operator closure.

* Acceptance Criteria
:PROPERTIES:
:CUSTOM_ID: acceptance-criteria
:END:
** AC012.1 - Default link installation replaces stale links safely :ac:
:PROPERTIES:
:CUSTOM_ID: ac-012-1
:END:
- Criterion :: Default installation retains a matching symlink and *replaces a
  different, relative or dangling symlink* with the current checkout's absolute
  binary path. It never changes the previous target; a regular file or directory
  at the executable destination remains untouched and produces an actionable error.
- Proven by :: [[#rt-012-1][RT012.1 - Staged link replacement]].
** AC012.2 - Service activation replaces the old user registration :ac:
:PROPERTIES:
:CUSTOM_ID: ac-012-2
:END:
- Criterion :: Starting from an absent, stopped, disabled or registered
  HTMLPreview job, service activation *registers the current checkout's plist*
  under the existing user label. Repetition requires no manual stop. A stale
  plist symlink is replaced without modifying its target. Stop succeeds when
  the job is already absent and retains the plist.
- Proven by :: [[#rt-012-2][RT012.2 - Service replacement and recovery]],
  [[#ut-012-1][UT012.1 - Native checkout switch]].
** AC012.3 - Genuine failures preserve recovery evidence :ac:
:PROPERTIES:
:CUSTOM_ID: ac-012-3
:END:
- Criterion :: Preparation failure leaves the old registration untouched.
  Manager failures other than an absent job remain errors. After a failed
  activation, the installer *restores the previous plist* and attempts to restart
  a previously registered job. Failed recovery is reported with any retained
  recovery location; no success is claimed from that failure. Configuration,
  existing logs and unrelated services are not removed or rewritten.
- Proven by :: [[#rt-012-2][RT012.2 - Service replacement and recovery]],
  [[#ut-012-1][UT012.1 - Native checkout switch]].

* Edge Cases
:PROPERTIES:
:CUSTOM_ID: edge-cases
:END:
- No old plist :: An already registered job can be replaced by label even when
  its plist is absent. If new activation fails after stopping it, recovery
  cannot reconstruct that missing definition and reports this explicitly.
- Disabled job :: Explicit service activation enables the same label before
  bootstrapping. It does not enable any other service or alter configured roots.
- No GUI domain :: Domain/permission errors are genuine failures, not treated as
  an absent job. The automatic route remains a macOS user LaunchAgent operation.
- Recovery error :: Retain the old plist or named staging directory instead of
  silently deleting the only remaining recovery copy.

* Solution Design
:PROPERTIES:
:CUSTOM_ID: solution-design
:END:
** Link installation
- Build and resolve the current executable and generate inactive service assets.
  Inspect the destination using *Lstat*, so dangling symlinks remain identifiable.
- A matching link is unchanged. For an absent or mismatched symlink, create a
  candidate in a private directory under the destination's parent, then rename
  it over the link. The same filesystem provides *atomic entry replacement*.
- Never write through a previous target or replace an ordinary executable file.
  Remove only the operation's staging directory and report cleanup errors.
** LaunchAgent lifecycle
- Reuse the existing plist renderer, configuration selection and private log.
  Prepare candidate bytes before stopping the job; preserve old plist entries,
  including symlinks, by renaming them into the private staging directory.
- Invoke *bootout gui/<uid>/org.htmlpreview.agent*, followed by *enable* for the
  same label, then *bootstrap gui/<uid> <absolute-plist>*. Only launchctl's
  ESRCH/exit 3 absent-job result is benign. =service-stop= uses the same bootout
  helper and is idempotent when the job is absent.
- Manager execution has a 30-second deadline. Capture diagnostics so expected
  absence does not print a spurious error; wrap genuine errors with operation
  context and retain their exit identity.
- If enabling or bootstrapping fails, remove any partially registered replacement,
  restore the old plist and restart it when a previous job existed. Preserve
  recovery files when restoration fails. Return the original error together
  with recovery errors; do not retry indefinitely or report success.
- Rollback cannot reconstruct a registered job's old in-memory definition when
  its original plist was already missing. No broad launchd enumeration or
  reconstruction subsystem is introduced for that case.
** Simplicity and verification
- Reuse the existing Go build tool and function-injected launchctl boundary.
  No new dependency, persistent state service, browser harness or shell execution.
- The small replacement transaction is necessary to avoid losing the old plist
  on a failed switch. Verify observable filesystem and manager outcomes through
  the two RTs; the real launchd exit/status behaviour remains a native UT.
** Security impact
- The existing *user-owned executable entry and one named user service* are the
  only replacement targets. No root escalation, remote listener or directory
  grant is added. Arguments remain separate and paths remain XML-escaped.
- Symlink targets, configuration and prior log content are preserved. Existing
  no-follow/private-log checks remain. Prefix copy installation is unchanged.
- A service restart invalidates previews according to the existing service
  lifetime contract; reopening documents obtains current URLs.
