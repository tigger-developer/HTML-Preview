* Synopsis
:PROPERTIES:
:CUSTOM_ID: summary
:END:

** Outcome

- *Preview every installed Pandoc reader*, common source-code files, plain text
  and passive native HTML from the same command.

** Before

- Admission accepts only *.md, .markdown and .org*.
- Even *.txt fails* the current extension check.

** After

- A shared resolver selects *document conversion, a code/text Org wrapper or
  native HTML*.
- Ordinary JSON displays *pretty-printed code* while copying retains its
  original contents.
- Native HTML retains *authored layout and permitted styling*, with supported
  document links routed through W006 when serving.

** Changes

- *Explicit reader selection and reader listing* cover uncommon and ambiguous
  formats, including the specialist Pandoc JSON AST.
- *Binary snapshots and bounded embedded media* support office documents.
- Code wrappers carry *filename and application-version metadata* with one
  Source code heading; plaintext wrappers omit that heading.

** Unchanged

- *Go, Pandoc and the default browser* remain the runtime stack.
- Sources remain *read-only*; code never executes.
- Existing converted-page fonts, copying, navigation and file lifetimes remain.
- *File graph mode stays opt-in*: otherwise links retain original-file destinations.
- Native HTML receives *no application reading chrome*. It permits no source
  scripts, form submissions or automatic external requests.
- Annotation writes remain limited to *genuine Org/Markdown sources*.

** Edge cases
:PROPERTIES:
:CUSTOM_ID: synopsis-edge-cases
:END:

- *Delimiter-like text and existing commas* stay literal and copy unchanged.
- *Malformed ordinary JSON* remains readable as source with a notice.
- *Ambiguous extensions* have deterministic defaults and explicit selection.
- *Damaged containers, denied resources and exhausted budgets* fail without
  partial publication or an insecure conversion retry.

** Decisions

- On 12 September 2026, the operator accepted *ordinary JSON formatting with
  original copying, specialist reader selection and passive authored HTML*.
- *TITLE and SCHEMA suffice* for generated wrapper metadata.
- *W008 delivers independently in file mode*; W006 consumes its format pipeline.
- The operator approved *all supported kinds in the existing opt-in file graph*,
  retaining its depth, file-count and byte limits.

** Next step

- *Deliver W008 first* under [[#delivery-handoff][Delivery Handoff]], following
  the operator's 12 September approval and explicit delivery instruction.

** Problem

- The operator reports a *.txt preview failure*. The current extension check in
  =internal/preview/source.go= rejects everything except Org and Markdown.
- Local document collections also contain *office documents and source files*.
  A Pandoc dependency should make its supported document readers available.

** Outcome

- *One bounded format pipeline* accepts Pandoc's installed built-in readers and
  the explicitly defined text/code routes. W006 reuses it for HTTP delivery.

** Scope

*** In scope

- *Reader discovery, selection, binary-safe snapshots, source wrapping, JSON
  display, passive HTML and bounded resource handling* in single-file delivery.
- A *shared format contract* consumed by the separately amended W006 service.

*** Out of scope

- *Implementing or activating W006*, annotation writes, custom Lua readers,
  user filters, code execution, external resource fetching and PDF input where
  the installed Pandoc has no PDF reader.
- *Exact word-processor page layout*, editing office formats or reproducing
  functionality beyond Pandoc's supported document model.

*** Unchanged

- *Original source files remain untouched*. Existing read-only, root, lifetime,
  default-browser, font, copy, folding and navigation contracts continue for
  application-rendered previews.
- *Native HTML retains its own layout*. Application chrome and typography are
  not imposed on it.

** AC008.1 - Installed Pandoc readers are selectable
:PROPERTIES:
:CUSTOM_ID: ac-008-1
:END:

- Criterion :: For every installed built-in reader *other than native HTML*, a valid explicit
  input produces a preview using that reader's supported content model. Binary
  documents are admitted as bytes; invalid documents produce actionable errors.
  *--from=html selects passive authored HTML*, without Pandoc conversion;
  HTML reader extension qualifiers are refused.
- Proven by :: [[#rt-008-1][RT008.1 - Every installed reader at the CLI boundary]],
  [[#rt-008-2][RT008.2 - Detection and explicit reader selection]].

** AC008.2 - Automatic detection has deterministic precedence
:PROPERTIES:
:CUSTOM_ID: ac-008-2
:END:

- Criterion :: An *unqualified filename selects exactly one route* using the detection contract:
  native HTML, text, code or a document reader. Unknown suffixes receive an explanation and
  reader-selection guidance; they are not silently treated as Markdown.
- Proven by :: [[#rt-008-2][RT008.2 - Detection and explicit reader selection]].

** AC008.3 - Explicit reader selection is bounded
:PROPERTIES:
:CUSTOM_ID: ac-008-3
:END:

- Criterion :: The *--from selection applies to explicit inputs only*. Its base reader must
  occur in Pandoc's reported list; supported reader extensions may qualify it. Custom-reader
  paths, executable filters and arbitrary Pandoc arguments are refused. Informational listing
  exposes available readers without opening a browser.
- Proven by :: [[#rt-008-2][RT008.2 - Detection and explicit reader selection]].

** AC008.4 - Code wrappers supply source context
:PROPERTIES:
:CUSTOM_ID: ac-008-4
:END:

- Criterion :: A mapped *code file renders through the specified temporary Org wrapper*, with a
  filename title, application-version schema and one Source code heading. The source-language
  identifier controls local highlighting; an unavailable highlighter falls back to literal
  unhighlighted text with a concise notice.
- Proven by :: [[#rt-008-3][RT008.3 - Code and text wrapper presentation]].

** AC008.5 - Plain text has no synthetic section heading
:PROPERTIES:
:CUSTOM_ID: ac-008-5
:END:

- Criterion :: A *.txt input renders a plaintext source block* with TITLE and SCHEMA but without
  a Source code heading. Text resembling Org, Markdown or HTML remains literal.
- Proven by :: [[#rt-008-3][RT008.3 - Code and text wrapper presentation]].

** AC008.6 - Wrappers preserve original content
:PROPERTIES:
:CUSTOM_ID: ac-008-6
:END:

- Criterion :: *Code and plaintext display preserve every original character*, with only
  the defined BOM/newline display normalization; wrapper escapes are invisible.
  Existing commas remain present and delimiter-like lines stay inside one block.
  *Copying supplies the original decoded UTF-8 text*, with no wrapper framing.
  Ordinary JSON alone follows AC008.7's explicit display-formatting exception.
- Proven by :: [[#rt-008-4][RT008.4 - Literal payload preservation]],
  [[#ut-008-1][UT008.1 - Native format reading]].

** AC008.7 - Ordinary JSON is readable without changing its source
:PROPERTIES:
:CUSTOM_ID: ac-008-7
:END:

- Criterion :: An unqualified *.json input displays indented, highlighted JSON* when
  syntactically valid, preserving object-member order and number lexemes. Copying retains the
  original text. Invalid JSON remains readable as literal highlighted source with a diagnostic;
  it is not rejected as a Pandoc AST.
- Proven by :: [[#rt-008-5][RT008.5 - JSON display and exact copy payload]],
  [[#ut-008-1][UT008.1 - Native format reading]].

** AC008.8 - HTML retains passive authored presentation
:PROPERTIES:
:CUSTOM_ID: ac-008-8
:END:

- Criterion :: A native *HTML preview retains its authored document structure, title and
  permitted styling*, without a Pandoc round trip or injected application reading template. The
  passive HTML contract blocks source scripts, submissions and automatic external requests while
  retaining ordinary hyperlinks.
- Proven by :: [[#rt-008-6][RT008.6 - Passive HTML without layout replacement]],
  [[#ut-008-1][UT008.1 - Native format reading]].

** AC008.9 - Conversion preserves identity and resources
:PROPERTIES:
:CUSTOM_ID: ac-008-9
:END:

- Criterion :: Converted documents *retain original logical source-path headers* and resolve
  references from their original locations. Supported container-owned raster
  media survives conversion. If sandbox-safe extraction is unavailable, return
  an explicit *dependency error before publication*, never an insecure retry or
  silent omission of otherwise supported media. Source identity and source-file
  links never expose wrapper or extraction paths; generated-page and admitted
  raster URLs may refer to owned session outputs.
- Proven by :: [[#rt-008-7][RT008.7 - Binary resources and original identity]].

** AC008.10 - Hostile inputs stay bounded and passive
:PROPERTIES:
:CUSTOM_ID: ac-008-10

- Criterion :: Every input route *preserves root confinement, non-execution and finite resource

  page and cleans only owned temporary state.
- Proven by :: [[#rt-008-8][RT008.8 - Input and resource confinement]].

** AC008.11 - Existing previews and lifetimes remain compatible
:PROPERTIES:
:CUSTOM_ID: ac-008-11

:CUSTOM_ID: ac-008-14

* Solution Design
:PROPERTIES:
:CUSTOM_ID: solution-design
:END:

** Architecture context

- Components :: Separate *source identity and bounded snapshots*, *format
  resolution*, *conversion* and *transport-specific URL publication* within the
  owned Go application. Preserve the existing Org prepass and copy transport.
- Ownership :: htmlpreview owns wrapper generation and passive HTML treatment;
  Pandoc owns document parsing. *W006 owns HTTP endpoints and capability grants*.
- Existing pattern :: Reuse bundled fonts, defaults and Lua for converted pages.
  *Native HTML uses its authored layout* and a distinct passive sanitizer policy.

** High-level design

*** Responsibilities and reuse

- Classification :: *One resolver* consumes the installed reader catalogue and
  the two mapping tables. Reader, language and original source kind are data;
  adding a suffix does not add another conversion coordinator.
- Rendering :: Reuse *one bounded snapshot and publication pipeline*. Document
  readers differ by validated Pandoc arguments; code/plaintext share the wrapper
  operation, with heading and language parameters. Native HTML has a separate
  preparation path because Pandoc would replace its authored layout.
- Resources :: The *same raster admission* handles container, local-file and
  data-URI bytes. Their acquisition differs; content validation does not.
  File publication and W006 HTTP publication provide their own authorized URL
  resolution without duplicating conversion or source-identity policy.
- Ownership :: Keep these operations in the established private Go code and
  bundled Pandoc assets. *No reader plugin framework*, configurable policy layer
  or service dependency is needed for this change.

*** Flow

1. Discover *installed built-in readers and highlighting languages* once per
   invocation; W006 snapshots them once per service instance.
2. Resolve the input using explicit selection or the filename contract, then
   read a bounded, stable snapshot through the existing rooted file boundary.
3. Convert documents with *sandboxed Pandoc*, create code/text Org wrappers,
   or parse and preserve passive native HTML without conversion.
4. Resolve media and links from *original source context*. Publish only after
   conversion, validation and all output-budget checks succeed.
5. Open the default browser using the existing lifecycle. Delete only the
   invocation's owned output according to its selected retention mode.

*** Interfaces and configuration
:PROPERTIES:
:CUSTOM_ID: format-interfaces
:END:

- CLI :: =htmlpreview [--from FORMAT] FILE [FILE ...]=; accept the equivalent
  =--from=FORMAT= spelling. At most one selection applies to all explicit inputs.
  =--= retains literal filename handling. *-f is refused* as an unknown option,
  with exit status 2; only the documented --from forms are accepted.
- Reader listing :: =htmlpreview --list-input-formats= is a sole informational
  operation and prints the installed Pandoc reader list. Missing/incompatible
  Pandoc exits 1. Help and --version remain independent of Pandoc.
- Selection grammar :: A reported base reader with optional Pandoc
  =+extension= / =-extension= qualifiers. Validate syntax and the installed
  reader's extension support; no paths, whitespace, shell fragments or arbitrary
  options. Native =html= selects the passive HTML route; its extension qualifiers
  are rejected because no Pandoc HTML reader is invoked.
- Precedence :: *Explicit reader; native HTML; exact named code basename;
  longest matching suffix across both tables and .txt; exact installed reader
  name as suffix; otherwise error*. The code table wins any equal-length suffix
  conflict. Suffix matching is case-insensitive. Named code basenames use the
  exact spellings in the table. No shebang execution or content sniffing changes
  the chosen type.
- Default Markdown :: Automatic .md/.markdown retains the bundled dialect;
  explicit reader selection uses its validated named reader/extensions.
- Specialist JSON :: =--from=json= expects Pandoc AST JSON. An ordinary .json
  path without selection always chooses the source-code route.
- Linked selection :: W006 reserves the query key =htmlpreview-format= for the
  same reader grammar. It applies to that target only. Ordinary .json anchors
  need no key. W008 exposes the format resolver; W006 implements query parsing.
- Error behaviour :: Invalid invocation/settings exit 2; per-source admission,
  encoding or conversion failures exit 1 while retaining valid batch results.
  Diagnostics identify the explicit original input and selected format.
- New settings :: *No persistent configuration key or runtime executable* is
  added. Reader selection is a per-invocation operation.

*** Wrapper and literal-content contract
:PROPERTIES:
:CUSTOM_ID: wrapper-contract
:END:

For code, create a private temporary Org file with the following logical
structure. Bracketed terms here denote substituted values, not literal brackets.

#+begin_example
#+TITLE: [original basename]
#+SCHEMA: HTML-Preview version [application version]

* Source code
#+BEGIN_SRC [mapped language]
[original contents, protected for Org transport]
#+END_SRC
#+end_example

For .txt, *omit the Source code heading* and use =plaintext= as the language.
The application version is the same build version used by --version, including
=dev= for a development build. Do not add guessed author/date or file timestamps.

- Metadata :: Render the basename as *literal text*. Escape CR/LF/control and Org
  metasyntax for the generated header; keep the original path separately for the
  source-copy control. Restore the exact visible basename through owned metadata
  transport rather than allowing a filename to introduce a directive.
- Escaping :: *Comma-escape Org delimiter and heading syntax where required*.
  Verify the installed Org reader's treatment of existing commas. If transparent
  escaping cannot represent a line losslessly, use the existing owned code
  transport to carry that payload through Pandoc; do not indent or alter source.
  The temporary Org wrapper remains a real artefact with owned block boundaries.
- Copy authority :: Preserve *original decoded text separately from formatted
  display*. Existing random, collision-checked transport and safe encoding carry
  it into the page's copy control, never into executable source HTML.
- Display authority :: *Restore the original payload after transport*, before
  highlighting. Org reader escaping must never leak its added commas into the
  rendered code. The existing Org prepass copies literal lines into its transport;
  generated wrappers therefore need an explicit original-payload restoration
  boundary, verified against displayed DOM text as well as clipboard data.
- Encoding :: Wrappers require valid UTF-8 without NUL. A leading UTF-8 BOM is
  omitted from display but retained in the original copy payload. CRLF may become
  LF for browser display; clipboard input retains the original decoded text.
- JSON :: Use a *token-preserving formatter*, not a map/float decode-reencode
  cycle. Indent two spaces without sorting members, collapsing duplicate keys or
  rounding numbers. Malformed JSON keeps its original display text and a notice.

*** Binary documents and media

- Snapshots :: Read *raw bounded bytes*, maintaining original logical/canonical
  context and stable-read checks. Apply text validation only to text routes.
  Reader inputs may use owned temporary files where Pandoc needs seekable input.
- Pandoc :: Keep *--sandbox*, owned defaults, HTML5 standalone output, trusted
  bundled Lua and the existing 512 MiB heap and conversion deadlines. Disable
  user configuration/filter loading; no source file controls command options.
- Media :: Extract only *container-owned media* into the conversion's private
  directory. Do not enable generic remote/local resource fetching through
  --extract-media. Use the sandbox and an owned bounded media-bag export, then
  independently validate output paths and raster types before publication.
  Source-relative external files are separately admitted by the URL resolver.
  Missing sandbox-safe export support is a *dependency error before publication*;
  never retry without sandboxing or silently drop an otherwise supported raster.
- Archives :: Before a known ZIP-container reader, validate member names and
  declared/actual inflation using Go's bounded archive reader: no absolute,
  traversal, duplicate normalized names, symlinks or non-regular entries.
  Limits are *4096 entries, 100 MiB total inflated data and 10 MiB per media
  asset*. Stream counting enforces actual sizes; invalid archives fail before
  Pandoc. Other readers remain under the same conversion/output bounds.
- Output :: Existing stricter configured limits win. Temporary snapshots,
  wrappers, expanded content and media count against owned scratch limits;
  application output including embedded assets remains bounded. Container media
  never expands access to adjacent files.
- Metadata-only readers :: Use the parsed document's metadata as *readable
  structured frontmatter*, including bibliographic entries, if it has no body.
  Do not invent content or invoke remote citation services to fill an empty page.

*** Raster admission
:PROPERTIES:
:CUSTOM_ID: raster-admission
:END:

W008 owns this *file-mode and shared conversion policy*. W006 adds transport
authorization and HTTP headers; its implementation is not a W008 prerequisite.

| Suffix | MIME type | Required bounded-header signature |
|--------+-----------+-----------------------------------|
| .png | image/png | Eight bytes 89 50 4E 47 0D 0A 1A 0A |
| .jpg, .jpeg | image/jpeg | Initial FF D8 FF |
| .gif | image/gif | Initial GIF87a or GIF89a |
| .webp | image/webp | Initial RIFF and WEBP at bytes 8-11 |
| .avif | image/avif | Complete initial ISO-BMFF ftyp box, 16-4096 bytes, containing avif or avis as a major/compatible brand |

- *Match suffix and signature*; any declared MIME must agree. Truncated or
  conflicting data is refused. Container/data-URI media needs matching MIME and signature
  where there is no original suffix. SVG is never promoted to a raster.
- *At most 10 MiB per admitted image*, within the stricter configured source,
  output and scratch budgets. Root and same-filesystem checks govern local paths.
- File mode embeds admitted raster bytes or publishes owned copies within the
  session directory; its CSP permits only those local resources and validated
  raster data. Remote automatic loading remains blocked.
- Refused media retains *alternative text and an omission notice*. This policy
  rejection differs from a missing sandbox-safe export capability, which fails
  conversion under AC008.9.

*** Passive native HTML
:PROPERTIES:
:CUSTOM_ID: passive-html
:END:

- Fidelity :: *No Pandoc round trip, application title block or reading chrome*.
  Parse HTML with the maintained HTML5 parser and retain the document title,
  structural elements, anchors and permitted inline/embedded/local CSS.
  HTML fragments receive only the document structure required by a browser.
  This is visual preservation, not byte-identical output.
- Blocking :: Remove scripts, inline event handlers, javascript URLs, forms'
  submission capability, refresh directives, frames, objects/embeds, active SVG
  and automatic resource forms not expressly supported below. Form field text
  may remain inert. No source JavaScript receives a CSP exception.
- CSS :: Use a maintained CSS parser, not regex replacement. Preserve static
  layout/colour/typography declarations. Remove imports and unsupported at-rules;
  inspect decoded CSS tokens, including escapes. Every url() is either an
  admitted local raster or removed. No remote fonts, fetches or stylesheet chain.
  Local stylesheets referenced by the page may be read under its existing root,
  10 MiB asset limit and aggregate budget, sanitized and inlined. Relative CSS
  URLs resolve against that stylesheet's original directory.
- Resources :: Admit local raster images and raster data under
  [[#raster-admission][W008's raster admission contract]]. Rewrite img/srcset and CSS image URLs through
  the transport's authorized resolver. Unsupported/remote automatic resources
  remain inactive with a concise omission notice; ordinary external anchors
  remain explicit user navigation with no referrer/opener propagation.
- Base and anchors :: Resolve source-relative anchors/resources against the
  first valid base href, then remove the base element. A remote base cannot
  authorize local reads or automatic remote loads. In-root document anchors are
  available to W006's normal conversion router, including HTML-to-HTML links.
  File-mode anchors use [[#file-graph][the existing graph setting]]: generated
  targets when enabled and eligible, original-file destinations otherwise.
  This adds no HTTP service or on-click file-mode converter.
- Policy :: Native HTML receives CSP default-src 'none', script-src 'none',
  style-src 'unsafe-inline', form-action 'none', base-uri 'none', object-src
  'none', font-src 'none', and only transport-authorized raster image sources.
  HTTP additionally uses W006's frame-ancestors, no-store, no-referrer and nosniff.
  The inline-style allowance is confined to this *script-free authored page*;
  it does not relax the normal generated-page policy.
- Identity :: The native HTML keeps its own title and layout. Its URL/publication
  record retains original source identity; no synthetic Org title or source-copy
  header is added. Converted documents retain the established visible header.

*** Existing file-mode graph
:PROPERTIES:
:CUSTOM_ID: file-graph
:END:

- Admission :: Before W006's replacement is delivered, *HTMLPREVIEW_LINKS=1
  admits every automatically supported W008 kind*, including native HTML and
  binary documents. No new file-mode selector syntax is introduced; W006 owns
  the target-specific query selector. Explicit --from applies to entry inputs.
- Publication :: Resolve anchors from original logical locations and rewrite
  admitted targets to generated pages. Native HTML participates without the
  application template. Code/plaintext payloads contribute no document links.
- Identity :: Keys include *original source context and resolved format*.
  Equivalent nodes deduplicate; different readers are distinct representations.
  Every kind counts towards MAX_FILES and depth limits; snapshots, wrappers,
  media and HTML count towards existing byte budgets and stricter W008 ceilings.
- Boundaries :: Preserve root, same-filesystem, cycle, alias, traversal and
  explained skip/partial-failure behaviour. *No numeric default or limit changes*.
- Graph off :: No linked conversion; original-file destinations and existing
  unresolved-search diagnostics remain.
- Regression reconciliation :: Extend =internal/preview/graph_test.go= and

  budget and retention assertions; change only narrowed-extension expectations.
- W006 migration :: Delivered W006's graph-option deprecation and on-demand
  service/fallback contract supersede this compatibility requirement.
  *W008 does not add a third W006 transport*.

*** Data and state

- Format result :: Carry *original kind, selected reader and extensions, code
  language, logical source context and transformation version* separately.
  Generated Org is an intermediate, never evidence that the original is Org.
- Persistence :: *Only private temporary output* is added. No source migration,
  file rewrite, formatter writeback, stored reader preference or annotation
  record is introduced.
- Service contract :: W006 keys conversion/cache results by source revision and
  resolved format as well as existing context/settings. Links resolve their own
  format; an explicit parent reader never propagates to children.

*** Failure behaviour

- *Errors identify the original source*, selected route and useful remedy.
  Unknown suffixes suggest --from and reader listing; invalid JSON display is
  a notice, while invalid explicit Pandoc AST input is a conversion error.
- *No insecure fallback*: a failed reader, sandbox or resource check cannot
  silently become raw HTML, a download or an unsandboxed retry.

** Architecture impact

*** Security impact

- Threat boundary :: *More document parsers and passive authored CSS* process
  untrusted local files. Source code remains data; generated wrappers must not
  grant source directives or attributes trusted application status.
- Data and secrets :: Original source paths/content remain local and read-only.
  Private scratch holds snapshots; external references do not gain filesystem
  access. Routine logs never contain service credentials or document bodies.
- Access :: *Existing roots and opened-handle checks remain mandatory* for every
  format and resource. W006 retains token and loopback requirements; HTML
  rewriting does not create new roots.
- Conclusion :: Retain sandboxing, bounded archive/media operations and distinct
  passive HTML policy. Tests cover actual boundary effects, not source greps.

*** Other relevant qualities

- Reliability :: *Deterministic classification and explicit failures* prevent
  accidental Markdown fallback or silent corruption of JSON/code.
- Performance :: Reader discovery runs once per invocation/instance; limits
  cover wrappers, archives, media and resulting HTML. No recursive pre-index.
- Operability :: Help and reader listing expose dependency capability; errors
  distinguish missing reader, invalid source and denied resource.
- Accessibility :: Converted pages retain existing keyboard/copy/navigation
  controls. Native HTML retains authored semantics; omitted content gets readable
  notices. Native browser qualification checks contrast, focus and narrow layouts.
- Portability :: *macOS, Linux and WSL* retain default-browser adapters; no new
  runtime executable, JavaScript CLI or system-font dependency.
- Maintainability :: Shared classification avoids CLI/service drift. Reader and
  language tables are separate; original source type survives every intermediate.
