* Synopsis
:PROPERTIES:
:CUSTOM_ID: summary
:END:
** Outcome
- A *theme button before the filename* switches the preview between light and dark.
** Before
- Previews *follow the system theme* with no manual control.
** After
- New pages still *follow the system*. Clicking the button *overrides the current page*.
** Changes
- The info bar gains a compact, keyboard-operable *sun/moon button* at its far left.
** Unchanged
- *No stored preference*, configuration change, source write or native-HTML controls.
** Edge cases
- *Annotation refreshes preserve* the override; reloading or opening another page
  *returns to system detection*. Without JavaScript the button stays hidden.
** Decisions
- Reuse the *existing palettes and reader lifecycle*; no library or new runtime.
** Next step
- Validate switching and layout through the human test, then obtain closure.

* Edge Cases
- No JavaScript :: *Static reading remains automatic*, with the inert control hidden.
- Lifecycle :: *Abort-scoped listeners* are removed on reader teardown; rebuilding
  controls restores the root's page-local choice without duplicating handlers.
- Print :: Print palette rules override both manual and automatic dark appearance.

* Solution Design
- Markup :: =page.html= places a hidden native button outside the source-copy node.
- State :: =enhanceTheme= in =preview.js= reads =prefers-color-scheme= until
  =document.documentElement.dataset.hpTheme= is set to =light= or =dark= by a
  click. The attribute survives reader-region replacement; it is never stored.
- Interaction :: The button has the fixed accessible name =Dark mode= and an
  =aria-pressed= state; a decorative sun/moon and tooltip describe the next action.
  The existing reader lifecycle owns its listeners and teardown.
- Styling :: Existing CSS palette values support explicit dark selection and
  automatic dark selection when light has not been forced. Explicit =color-scheme=
  also updates browser-native controls. The compact button consumes fixed flex
  space before the existing flexible filename. Print overrides retain precedence.
- Security :: No network, storage, source-content interpolation, permission or
  source-writing change. The existing generated script/style hashes continue to
  govern publication. No new dependency or execution boundary.
- Verification :: Published HTML regression plus human interaction; native JS/CSS
  lint and a production build. No browser or JavaScript CLI test framework added.
