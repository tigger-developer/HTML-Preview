* Code highlighting, copying and document navigation
:PROPERTIES:
:CUSTOM_ID: summary
:END:

- Outcome :: *Code is coloured and copyable*, and *clickable margin bars fold
  sections* in the existing Markdown and Org preview.
- Before :: *Source blocks are plain*. The header alone offers clipboard
  copying; local outline buttons display Fold or Expand.
- After :: *Declared code languages receive local syntax highlighting*.
  Clicking inline code, Org verbatim or a code block copies its text;
  keyboard users have native copy buttons. *A thick, bright bar with a bottom
  plus opens hidden content; a normal bar closes expanded content*.
  *Standalone output is mandatory*. A table of contents is enabled by default,
  including source heading levels 1 to 3.
- Changes :: *Examples demonstrate TODO states, tags, drawers and code*.
  Pandoc handles highlighting; the owned theme supplies light/dark colours.
  *Copying excludes delimiters and controls* and preserves literal whitespace.
- Unchanged :: *The header identifies and copies the original source path*.
  Fonts, existing CLI settings, source protection, link resolution, private sessions,
  platform handoff and W001 qualification requirements continue to apply.
- Edge cases :: *Unknown languages remain plain*; empty code is not copied.
  *Selection and hyperlink activation remain available*. Clipboard refusal
  offers a manual-copy field. No-JavaScript reading and full printing remain
  available. Org literal lookalikes and trailing newlines remain literal.
  The first click of a double-click selection may copy before the word is selected.
  *TOC links use final heading IDs*; empty outlines omit the contents navigation.
- Decisions :: *Go, Pandoc and browser-only JavaScript remain the stack*.
  The operator selected margin bars; proposed details select copy affordances and built-in
  highlighting; *operator sign-off adopts these choices*.
  *TOC and depth are configurable* through =HTMLPREVIEW_TOC= (default =1=)
  and =HTMLPREVIEW_TOC_DEPTH= (default =3=, valid =1= to =6=).
  *Standalone is hardcoded true*, following the operator's correction.
- Next step :: *Review the implemented examples and record browser validation*.
  The implementation gate reports PASS; browser results and operator closure
  remain separate human evidence.
- Subsequent amendment :: [[file:../003-format-contents-defaults/spec.org][W003 - Format-specific contents defaults]]
  *supersedes this record's all-format default-on choice*. Markdown retains TOC
  on at depth 3; Org defaults to off. Explicit overrides remain available.
  Default-on statements below document the originally approved W002 contract;
  the linked emergency amendment is the current authority for format defaults.

:CUSTOM_ID: context

** Problem

- The operator requested *an Org work-ledger example*, including TODO markers,
  tags, drawers and source blocks, on 8 September 2026.
- The operator requested *syntax highlighting, glyph fold controls and copying
  inline/block code*, including Org =~code~= and ==verbatim==.
- The current *Org preservation stage emits plain HTML code*, so enabling a
  Pandoc option alone cannot highlight those source blocks.
- The operator also requested *configurable contents and maximum levels*,
  then clarified that *standalone must always be true*.

** Outcome

- *Readable highlighted code retains its text*, while copying and folding are
  accessible without changing source documents or system configuration.

** Scope

*** In scope

- *Highlight language-labelled Markdown fenced blocks and Org source blocks*.
- *Copy semantic inline code and pre/code blocks*, including Org verbatim,
  Org example blocks and Markdown indented blocks.
- *Replace local heading buttons with clickable left margin bars*; retain the
  global toolbar and initial visibility metadata.
- *Provide synthetic Org and Markdown examples* and browser validation.
- *Always enable Pandoc standalone conversion* and provide a default-on TOC
  with configurable depth, retaining the application-owned final page.

*** Out of scope

- *No code execution, language guessing or user-supplied highlighter plugins*.
- *No editing, live reload, fragment-output mode or browser automation framework*.
- *No copy action for ordinary prose, drawers or planning metadata*.

*** Unchanged

- *W001 remains the baseline* except for the explicit clipboard-scope extension.
  Syntax colouring refines presentation; it does not relax literal fidelity.
- *Header copying still uses the original absolute logical source path*,
  including the Linux path in WSL. Temporary names never supply that value.
- *Embedded Asap and Iosevka Custom remain the defaults*; installation does not
  depend on system fonts or paths adjacent to the executable.

** Constraints and dependencies

- *Pandoc 3.9.0.2 through 3.9.x and its Lua 5.4 host remain supported*.
  Use the current Go build baseline and existing module dependencies.
- *No CLI JavaScript, standalone Lua, new package or network highlighter*.
- *Source HTML remains passive*. Highlighting never enables source scripts,
  styles, filters, includes, language-definition paths or code execution.
- *Existing source, output, process and time budgets still apply*.
  Highlighted markup and all intermediate data consume the relevant budgets.

** Decisions

- Operator direction :: *Use glyphs for local folding and add code copying*.
  The request includes Org source blocks, Markdown fenced blocks, Org inline
  code and verbatim, and Markdown inline code.
- Operator display direction :: *Use a thicker, bright left margin bar with a
  bottom =+= when collapsed; a normal thin bar when expanded*. Clicking the
  bar opens or closes the section. This direction supersedes the initial
  triangle proposal, retained in the first draft's Git history.
- Local action :: *The bar toggles between fully open and closed*. The global
  Contents mode and initial children visibility still exist; a section whose
  body is hidden uses the thick-plus bar and opens fully on activation.
- Proposed copy scope :: *All rendered semantic code is eligible*, including
  raw HTML code admitted by the passive policy. Classes and IDs alone do not
  create a copy target. This extends W001's header-only binding deliberately.
- Proposed activation :: *Click code directly unless it is inside a link*.
  Every nonempty target also has a small native copy-glyph button. Link code
  uses that adjacent control, leaving the link's own click unchanged.
- Proposed highlighting :: *Use Pandoc's internal highlighter and owned theme
  CSS*. Missing/unknown languages and examples remain plain.
- Operator configuration direction :: *Hardcode standalone=true*. Expose
  *TOC=true and maximum levels=3* as defaults. The earlier suggestion of a
  standalone switch was explicitly withdrawn before definition sign-off.
- Authority :: *Taḋg approved this specification on 8 September 2026*,
  adopting the proposed choices above through an explicit "approved" response.

** AC002.2 - Literal content survives highlighting
:PROPERTIES:
:CUSTOM_ID: ac-002-2
:END:

- Criterion :: *Code text retains its literal value*, including tabs, Unicode,
  blank lines, indentation and terminal newlines. Org uses the preserved body
  with CRLF normalized to LF; Markdown uses Pandoc's parsed code value.
  No language declaration or code delimiter appears in that value.
- Proven by :: [[#rt-002-1][RT002.1 - Highlighted output and literal fidelity]],
  [[#ut-002-2][UT002.2 - Clipboard interaction and fallback]].

:PROPERTIES:
:CUSTOM_ID: ac-002-3

  faithful code*, without guessed highlighting or a failed preview.
- Proven by :: [[#rt-002-1][RT002.1 - Highlighted output and literal fidelity]],

** AC002.4 - Explicit activation copies code text
:PROPERTIES:
:CUSTOM_ID: ac-002-4
:END:

- Criterion :: *Clicking eligible code or activating its copy button copies only
  that target's literal value*. This covers Org inline code/verbatim, Markdown
  inline code, and pre/code blocks. Empty code offers no enabled copy action.
  Buttons support pointer, Enter and Space activation.
- Proven by :: [[#ut-002-2][UT002.2 - Clipboard interaction and fallback]].

** AC002.5 - Selection and links retain their actions
:PROPERTIES:
:CUSTOM_ID: ac-002-5
:END:

- Criterion :: *Dragging a selection or clicking a hyperlink does not copy code*.
  An existing noncollapsed selection suppresses direct-code copying. Code within a link
  retains navigation and has a separate copy control outside the link.
- Proven by :: [[#ut-002-2][UT002.2 - Clipboard interaction and fallback]].

** AC002.6 - Clipboard feedback reports the actual result
:PROPERTIES:
:CUSTOM_ID: ac-002-6
:END:

- Criterion :: *Copy success is shown and announced only after a successful
  clipboard write*. Unavailable/denied access exposes the exact value in a
  selectable readonly field with an instruction; it never reports success.
  Loading, focusing, folding and navigation perform no automatic copy.
- Proven by :: [[#ut-002-2][UT002.2 - Clipboard interaction and fallback]].

** AC002.7 - Clickable margin bars open and close sections
:PROPERTIES:
:CUSTOM_ID: ac-002-7

* Edge Cases
:PROPERTIES:
:CUSTOM_ID: edge-cases

** Literal boundaries and unsupported languages

- Condition :: *Code contains metadata, transport lookalikes or terminal blank
  lines*, or has an unknown language.
- Required behaviour :: *Preserve literal text and use plain fallback* where
  highlighting is unsupported; never interpret code as an include or filter.
- Covered by :: [[#ac-002-2][AC002.2 - Literal fidelity]],
  [[#ac-002-3][AC002.3 - Plain fallback]],
  [[#rt-002-1][RT002.1 - Highlighted output and literal fidelity]],
  [[#rt-002-2][RT002.2 - Passive rendering and resource limits]].

** Interactive nesting and clipboard refusal

- Condition :: *Code appears within a heading, table, link or folded section*,
  a selection is active, or clipboard permission is unavailable.
- Required behaviour :: *Preserve navigation and selection*, use separately
  associated native controls and retain a manual-copy path on failure.
- Covered by :: [[#ac-002-4][AC002.4 - Code copying]],
  [[#ac-002-5][AC002.5 - Selection and links]],
  [[#ac-002-6][AC002.6 - Honest clipboard feedback]],
  [[#ut-002-2][UT002.2 - Clipboard interaction and fallback]].

** Repeated initialization, printing and large pages

- Condition :: *Navigation restores a cached page*, printing changes visibility,
  or the source contains many code targets.
- Required behaviour :: *One owner manages each control and pending write*.
  Teardown cancels handlers/timers; restoration creates no duplicates.
  Initialization yields in bounded batches, preserving static reading.

* Solution Design
:PROPERTIES:
:CUSTOM_ID: solution-design
:END:

** Architecture context

- Relevant components :: *Go preserves lost Org values and owns sessions*;
  Pandoc/Lua transform document structure; the HTML pipeline sanitizes and
  publishes; owned CSS/JS provide presentation.
- Ownership boundary :: *Pandoc owns tokenization, browser policy owns clipboard
  permission*. The project owns text fidelity, controls and graceful failure.
- Existing pattern :: *Retain one Pandoc conversion per document*. Replace only
  opaque source-block HTML preservation with typed code transfer; keep drawers,
  planning and identifier restoration in their current responsibility.
- Rejected alternatives :: *A browser highlighter adds an unnecessary library*.
  Per-block Pandoc processes multiply cost; a whole-document JSON round trip
  introduces another conversion stage. Private inline data preserves the
  existing single-converter boundary and adds no filter filesystem access.

** High-level design

*** Flow

1. *Capture Org source text and its language* in the literal-aware pre-pass.
   Retain the current CRLF-to-LF contract and end-of-input handling.
2. *Serialize each source block as JSON data in an internal raw export block*.
   Use a fresh cryptographically random 128-bit document token with a lowercase
   format name absent from the source under case-insensitive matching.
   Pass that exact format through an application-owned Pandoc command metadata
   argument; source metadata must not override it. JSON encoding escapes all
   embedded newlines, so source export terminators cannot terminate the wrapper.
3. *Decode only that format in the owned Lua filter*, validate string text,
   language and generated identifier fields, then create a Pandoc CodeBlock.
   Use =pandoc.json.decode= with Pandoc-type coercion disabled. Do not read a
   sidecar, call a process, evaluate Lua or reparse the code body. Walk the
   document explicitly before display metadata is cleared.
4. *Capture every CodeBlock's text before highlighting*, for both formats.
   Wrap each block with an internal Div association using that document token
   and a sequence number, preserving its original attributes/identifier.
   Emit an adjacent internal raw-HTML pre element containing an HTML-escaped
   JSON record of association and literal text. This is data, never a script.
   These transient records return through the same bounded Pandoc output pipe.
   Go consumes and removes them before source sanitization and publication;
   verify unique associations, exact fields and one record per marked block.
   Source metadata/classes cannot choose the private token.
   *Highlight with the built-in engine* using =syntax-highlighting: pygments=.
5. *Restore exact code text after parsing the HTML*. Associate generated blocks
   with their retained values before internal identifiers are removed.
   If the only difference is one missing terminal LF, append that LF inside
   code. If another difference occurs, retain a plain code block with the
   original value and a bounded diagnostic; never silently corrupt it.
   Retain token spans for successfully matched output. Exclude generated line
   numbers from copy values; no numbering is requested by this change.
6. *Apply the existing passive policy and publish with owned theme CSS*.
   Then browser enhancement registers code targets and margin-bar controls using
   safe DOM methods, with no new dynamic HTML sink.

*** Interfaces and configuration

- Language selection :: Language is the first Org source-block
  language token or the Markdown code language class. Retain Pandoc-supported
  language names; explicitly map =sh= and =shell= to =bash=.
- Private transport :: *Go generates 16 random bytes and lowercase hex-encodes
  them as a 32-character token*. Pass
  =--metadata=htmlpreview-code-token:VALUE= directly as one Pandoc argument.
  Lua reads =doc.meta["htmlpreview-code-token"]= at the start of its Pandoc
  callback, requires a Lua string containing exactly 32 lowercase hexadecimal
  characters and derives raw format =htmlpreview-code-VALUE=.
  Command metadata takes precedence over source metadata; this was probed for
  Markdown YAML and Org on Pandoc 3.9.0.2. Ignore source attempts to set the key,
  clear it before display metadata handling and reject missing/malformed
  effective values as a conversion failure.
- Transport validation :: *Org input JSON contains exactly id, text and language
  string fields*. IDs are =htmlpreview-code-VALUE-N= for positive sequence N.
  Validate each input ID once; it is an internal association, not a user heading
  or output code ID. Construct Org CodeBlocks with an empty source identifier.
  Code return records contain exactly =id= and =text= strings, with association
  IDs tied to that same token. Their wrappers use =htmlpreview-code-VALUE-N=;
  adjacent record elements use =htmlpreview-code-record-VALUE-N=.
  Heading return elements use =htmlpreview-heading-record-VALUE-N= with the
  heading schema below. Encode records through JSON plus HTML text escaping.
  Go requires each expected association exactly
  once and removes only its own matching records. Missing, duplicate, malformed
  or mismatched records fail conversion. Source lookalikes are never decoded
  merely because they carry a similar class or metadata key.
- Contents settings :: *Use the existing environment interface*:
  =HTMLPREVIEW_TOC= accepts =0= or =1=, default =1=;
  =HTMLPREVIEW_TOC_DEPTH= accepts decimal integers =1= through =6=, default =3=.
  Unset/empty values select defaults. Validate both before any session
  allocation, even if TOC is disabled. Add no standalone variable or CLI option.
- Pandoc configuration :: *Hardcode standalone=true in packaged defaults*.
  Pass the validated =--toc=true/false= and =--toc-depth=N= as explicit
  application arguments, overriding source options. Use an embedded minimal
  Pandoc HTML5 template for the intermediate complete document; it contains
  the generated TOC and body but no default Pandoc styles/scripts.
  The final Go template retains sole ownership of the visible source header,
  embedded fonts, CSP and browser script. Do not nest whole HTML documents.
- Contents identity :: *Keep generated contents separate from the source body*
  before source sanitization/discovery. The owned Pandoc template gives its
  TOC container a per-document token identifier supplied through the explicit
  template variable =htmlpreview-toc-token=. It is not source-selectable.
  Only the identified container becomes the owned final Contents navigation,
  located below the source header and before the outline toolbar/document.
- Contents targets :: *Assign temporary unique IDs to Pandoc Header nodes* in
  the owned filter so its TOC uses unambiguous destinations. Use
  =htmlpreview-heading-VALUE-N=, distinct from code associations. Emit a
  separate heading record with exactly =id= and =originalID= strings, through
  the same escaped/bounded data channel. Go restores each original ID before
  existing Org restoration/cataloguing; retain the node association until
  final IDs are allocated, then rewrite only owned TOC hrefs using that mapping.
  Validate heading records as strictly as code records. Preserve source IDs
  and ordinary link semantics; do not guess destinations from heading text.
- Contents levels :: *Follow Pandoc's source heading levels*, before the Go
  page-header offset; the maximum is 1 to 6. Raw-HTML headings outside Pandoc's
  Header nodes do not gain TOC entries. Preserve Pandoc's unnumbered/unlisted
  heading semantics. Omit empty contents containers. Sanitize its text/links
  with the passive policy and add owned navigation semantics afterwards.
  TOC anchors do not enter document discovery or the local folding index.
- Plain cases :: *Empty/unknown language and example blocks remain plain*.
  Do not interpret language labels as files, URLs, commands or plugins.
- Syntax CSS :: *Own the token palette in assets/web/preview.css*, scoped to
  code under the document container. Set light/dark theme variables for every
  emitted token class with a readable fallback. The existing font rules and
  exact CSS CSP hash cover the added stylesheet. Do not load runtime theme files.
- Copy scope :: *Enhance semantic code descendants of the owned document only*.
  A pre/code pair is one target, not a second inline target. Copy the code
  node's restored text content captured before controls are inserted.
  Empty values have no enabled control; whitespace-only values remain copyable.
- Copy affordance :: *Use a native button with a small copy glyph* and an
  accessible name, visible focus and minimum 24 by 24 CSS-pixel target.
  Place block controls beside the block, not inside its copied code.
  Inline controls are adjacent; if code is inside an anchor, place the copy
  control immediately after that anchor. Associate multiple code spans in one
  link with separately named controls in source order.
- Pointer handling :: *Direct code clicks copy only without a noncollapsed
  selection and outside an interactive descendant/ancestor*. Ignore drag,
  later clicks in a multi-click sequence, modified clicks and empty code.
  Do not prevent browser selection. A double click's first ordinary click may
  copy: retaining immediate user-activated clipboard access has this trade-off.
  The explicit copy
  button remains an intentional copy action even with a selection elsewhere.
- Feedback :: *Share the existing clipboard service with the source header*,
  retaining a distinct payload and target label per activation. Allow one
  pending write for the page; ignore further activation until it settles.
  Call writeText synchronously during activation, announce success for two
  seconds, and expose a readonly selectable field on rejection/unavailability.
  Feedback is outside the copied value, labelled for the target and does not
  move focus. Do not log or persist copied content.
- Fold presentation :: *Replace local heading buttons with native bar buttons*
  in a dedicated left gutter for each section, including root sections.
  Their hit area spans the visible section height and is at least 24 CSS pixels
  wide/high; draw the normal bar at 1 pixel and the folded bar at 4 pixels.
  A folded/children section uses the theme's bright accent and a small bottom
  =+=. An all-open section uses a normal thin bar without a plus.
  Keep each hit area separate from its text and adjacent/nested section bars.
  Names/tooltips describe Expand or Collapse and the original heading text.
  =aria-expanded= is false when the section body is hidden, true when its own
  body is visible. Folding a child does not change the parent body's visibility.
  Click, Enter and Space apply the existing subtree operation: non-all to all,
  all to folded. The plus is part of the same button, not another nested control.
  Preserve visible focus, normal Tab/Shift+Tab order and independent parent/
  child targets. Do not add folding to source code, blockquotes or drawers;
  existing drawer disclosure and Overview/Contents/Show all remain.

*** Data and state

- Preservation :: *Keep typed code records separate from raw HTML fragments*.
  Every record carries its literal value, language and unique association.
  Allocate/serialize under the existing byte ceilings; no unbounded duplicate
  document or per-block subprocess collection is introduced.
- Browser ownership :: *One enhancement lifecycle owns controls, status,
  listeners and timers*. Preserve pre-enhancement heading text for accessible
  fold names so inserted copy controls cannot contaminate it.
  Pagehide tears down all enhancements; bfcache restoration rebuilds once.
- Static and print :: *Plain semantic code remains in generated HTML*.
  JS only adds controls. Print hides all interactive copy/fold chrome and
  manual fields, expands content, then restores prior outline/drawer state.

*** Failure behaviour

- Conversion :: *Invalid internal transport is a diagnosed conversion failure*.
  A writer text mismatch has the exact plain-text fallback described above.
  Unknown language alone is not an error.
- Limits :: *Existing cancellation, publication and cleanup contracts apply*.
  No partial page is opened. Increased token markup may consume the output
  budget sooner; the command reports the same bounded operational failure.
- Clipboard :: *No fallback bypasses browser policy*. Keep manual copying
  available, never read clipboard contents and never change browser settings.

** Architecture impact

*** Security impact

- Threat boundary :: *Source code remains untrusted text*. Private transport
  creates CodeBlocks only; it cannot introduce executable filters, HTML or
  filenames. Escape JSON and verify the collision-free association.
- Data and secrets :: *Clipboard receives only an explicitly activated value*.
  That value already appears in the preview; no clipboard reads, telemetry,
  logging or shared cache is added.
- Access :: *No filesystem or network authority is added*. Lua retains its
  no-file/no-process contract; the highlighter uses installed Pandoc syntax
  definitions. Browser activation grants only the requested clipboard write.
- Conclusion :: *The deliberate new boundary is semantic-code copying*,
  superseding W001's header-only handler scope while retaining passive HTML,
  reserved chrome, exact CSP hashes and source-controlled attribute stripping.

*** Other relevant qualities

- Reliability :: *Literal comparisons prevent coloured-but-altered code*.
  Existing Org metadata and link regressions protect neighbouring behaviour.
- Performance :: *One converter remains sufficient per document*. Budget
  transient code records and generated spans; enhance large pages in batches.
- Operability :: *Install and rollback remain binary replacement*.
  Documentation explains code language labels, copying, bars and fallback.
- Accessibility :: *Native controls, selection and no-JS reading remain*.
  Real-browser validation is required for clipboard policy and legibility.
- Portability :: *The existing macOS/Linux/WSL browser matrix applies*.
  No new runtime or browser-specific permission workaround is introduced.
- Maintainability :: *Separate clipboard, outline and code-preservation
  responsibilities*, using small functions and explicit state. Source CSS/JS
  review and user tests follow W001's no-CLI-JavaScript tooling decision.
