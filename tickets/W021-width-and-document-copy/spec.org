* Synopsis
:PROPERTIES:
:CUSTOM_ID: summary
:END:
** Outcome
- *Use available width* and *copy a whole document without preview colours*.
** Before
- The reader was *capped at 54rem*. Chromium selection-copy retained dark colours.
** After
- The reader *fills its column*. *Copy doc* supplies semantic HTML and plain text.
** Changes
- Remove the reader cap, keep table words intact, and add a lifecycle-owned copy control.
** Unchanged
- *Ordinary selection-copy remains browser-owned*. Source files, annotation writes,
  theme selection and navigation behaviour remain unchanged.
** Edge cases
- Folded content and sidebar footnotes are included. Clipboard refusal is visible.
- Local links and images remain preview-dependent; this is *not portable export*.
** Decisions
- Copy *rendered title, body and footnotes*, excluding frontmatter and interface controls.
- *Human validation* establishes actual clipboard and layout behaviour.
** Next step
- Validate Chromium pasting and desktop/mobile layout against the built candidate.

* Context
** Problem and scope
- The document column wastes available space, and narrow table cells split words.
- Chromium copies dark foreground/background styling during ordinary selection-copy.
- Emergency scope covers *both available-width reading and a Copy doc button*.
  It does not change selection-copy, browser choice, installation or service configuration.

* Acceptance Criteria
** AC021.1 - Available reader width :ac:
:PROPERTIES:
:CUSTOM_ID: ac021-1
:END:
- The document *fills the available column* beside responsive navigation and
  annotation panels at 100% browser zoom, retaining page padding.
- Table cells *do not split words merely to squeeze columns*; oversized tables
  remain horizontally scrollable rather than widening the page.
- Verification :: [[#ut021-1][UT021.1 - Responsive reading]].
** AC021.2 - Theme-neutral whole-document clipboard :ac:
:PROPERTIES:
:CUSTOM_ID: ac021-2
:END:
- *Copy doc* copies the current rendered title, body and footnotes, including
  folded sections and footnotes moved into the annotation panel.
- Clipboard HTML *preserves headings, emphasis, underline, lists, links and tables*
  without preview colours or controls. Plain text is supplied alongside it.
- Copying *does not mutate* the live document, selection, folds, theme or source.
- Frontmatter panels, navigation, controls and unsaved annotation drafts are excluded.
- Verification :: [[#ut021-2][UT021.2 - Clipboard behaviour]].
** AC021.3 - Accessible, repeatable copying and visible failure :ac:
:PROPERTIES:
:CUSTOM_ID: ac021-3
:END:
- The button supports *keyboard activation* and reports success only after the
  clipboard write resolves. Refusal or unavailable support produces a visible error.
- Refreshes and repeated activations *do not duplicate controls* or copy old regions.
- Verification :: [[#ut021-2][UT021.2 - Clipboard behaviour]].

* Edge Cases
- Clipboard permission and API support vary. Refusal *retains a visible error*;
  no automatic plain-text downgrade is reported as formatted success.
- Copy uses the current rendered snapshot, not unsaved annotation drafts.
- Oversized unbreakable table content *scrolls inside the table*.
- Without JavaScript, static reading remains available and no copy button is added.

* Solution Design
** Reader and clipboard ownership
- Remove the 54rem maximum from shared reader regions, stretch within the grid,
  and override arbitrary word wrapping in table cells. Existing breakpoints and
  bounded sidebars remain authoritative.
- Extend the existing reader lifecycle. On explicit activation, clone title/body
  plus sidebar endnotes into a detached container; remove UI nodes, hidden state,
  styling and operational attributes. Retain semantic/link/table attributes and
  convert Org underline to semantic underline markup.
- Serialize detached markup directly, *without computed styles*. Build plain text
  from that same cleaned tree with block and cell separators. Write both formats
  in one ClipboardItem, then report completion or refusal.
- Dispose listeners, feedback and timers on teardown. Read current regions per click.
** Security and compatibility
- Only already-sanitized preview content is copied. No raw source HTML, script
  execution, clipboard reads, source writes, new dependencies or external services are added.
- Clipboard writes require explicit activation. Detached DOM processing does not
  change live nodes. Existing local links/images retain their preview destinations.
- Ordinary browser selection-copy and existing path/code copy contracts are unchanged.
- Architectural review checks ownership and sanitization; user tests establish
  layout and paste results. No new service, configuration or test architecture is introduced.
